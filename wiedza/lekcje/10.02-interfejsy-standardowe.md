# Lekcja 10.2 — Interfejsy z biblioteki standardowej

## Cel
Po lekcji uczeń:
- Implementuje `IComparable<T>` i dzięki temu sortuje własne obiekty przez `Sort()`
- Rozumie, co znaczą liczby zwracane przez `CompareTo`
- Wie, że `foreach` działa dzięki `IEnumerable` — i czemu działa na tablicy, liście i tekście
- Widzi, że interfejsy nie są tylko jego wymysłem: cała biblioteka na nich stoi
- Rozpoznaje `InvalidOperationException` przy sortowaniu bez kontraktu

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Masz stos teczek pracowników. Proszę: uporządkuj je."

**Co chcesz usłyszeć:** pytanie zwrotne — **według czego?** Nazwiska, daty zatrudnienia, pensji?

**To jest cała lekcja.** Sortowanie wymaga **reguły porównywania**, a rzeczy same z siebie jej nie mają.

**Drugie pytanie:**
> „A liczby? Czy przy sortowaniu liczb musisz komuś tłumaczyć, która jest »przed«?"

**Co chcesz usłyszeć:** nie — dla liczb to oczywiste. Dla teczek nie.

**Trzecie pytanie:**
> „Skąd program ma wiedzieć, że twój `Uczen` porównuje się po ocenie, a nie po imieniu?"

**Co chcesz usłyszeć:** trzeba mu powiedzieć. **I to jest kontrakt** z lekcji 10.1.

## Krok 2 — Mostek (12 min)

Zacznij od porażki. Uczeń pisze:

```csharp
List<Uczen> lista = new List<Uczen>
{
    new Uczen("Cyd", 3),
    new Uczen("Ala", 5),
    new Uczen("Bo", 4)
};

lista.Sort();

class Uczen
{
    public string Imie { get; }
    public int Ocena { get; }
    public Uczen(string imie, int ocena) { Imie = imie; Ocena = ocena; }
    public override string ToString() => $"{Imie}({Ocena})";
}
```
→ program się buduje i **przewraca w trakcie**:
```
Unhandled exception. System.InvalidOperationException: Failed to compare two elements in the array.
```

> „`Sort()` działało w lekcji 6.2 na `List<int>`. Czemu tu nie działa?"
→ bo liczby wiedzą, jak się porównać. Twój `Uczen` nie.

**Mostek:**
> „W bibliotece C# istnieje gotowy interfejs dokładnie na to: `IComparable<T>`. Ma jedną metodę — `CompareTo`. Implementując go, mówisz: »oto reguła, według której moje obiekty się porządkują«."

```csharp
class Uczen : IComparable<Uczen>
{
    public string Imie { get; }
    public int Ocena { get; }

    public Uczen(string imie, int ocena) { Imie = imie; Ocena = ocena; }

    public int CompareTo(Uczen? inny)
    {
        if (inny == null) return 1;

        return Ocena.CompareTo(inny.Ocena);
    }

    public override string ToString() => $"{Imie}({Ocena})";
}
```

```csharp
lista.Sort();
foreach (Uczen u in lista) Console.Write(u + " ");
```
→ `Cyd(3) Bo(4) Ala(5)`

**Pytania:**
- „Ile metod trzeba było napisać, żeby `Sort` zadziałało?" → jedną
- „Czy zmieniłeś coś w `Sort`?" → nie. **`Sort` był gotowy i czekał na kontrakt.**
- „Co robi `Ocena.CompareTo(...)` w środku?" → deleguje robotę liczbom, które porównywać umieją

> **Pierwsza linia to zabezpieczenie na wypadek `null`.** Powiedz jednym zdaniem: „jeśli nie ma z czym porównywać, uznaj, że jestem większy — wtedy braki wylądują na początku". Ta sama linia wraca w kroku 3.D; trzymaj jedną konwencję w całej lekcji. `Uczen?` ze znakiem zapytania to wymóg podpisu metody z interfejsu — nie rozwijaj, typy nullowalne są poza kursem.

## Krok 3 — Eksperyment (25 min)

### A. Co znaczą liczby z `CompareTo`

```csharp
Console.WriteLine(5.CompareTo(3));
Console.WriteLine(3.CompareTo(5));
Console.WriteLine(4.CompareTo(4));
Console.WriteLine("Ala".CompareTo("Bo"));
```
→ `1`, `-1`, `0`, `-1`

> „Trzy możliwe odpowiedzi. Co znaczy każda?"

| Wynik | Znaczy |
| --- | --- |
| liczba **ujemna** | „jestem **przed** tamtym" |
| **zero** | „jesteśmy równi" |
| liczba **dodatnia** | „jestem **za** tamtym" |

> „Zwróć uwagę: nie chodzi o konkretną liczbę, tylko o **znak**. `-1` i `-500` znaczą to samo."

> „Teksty też to potrafią — `\"Ala\".CompareTo(\"Bo\")` dało `-1`, bo alfabetycznie Ala jest wcześniej."

### B. Odwrócenie kolejności

```csharp
public int CompareTo(Uczen? inny)
{
    return inny?.Ocena.CompareTo(Ocena) ?? 0;
}
```
> „Zamieniłeś strony. Co się stanie z kolejnością?"
→ od najwyższej oceny do najniższej.

Niech uczeń sprawdzi obie wersje i sam nazwie regułę: **kto woła `CompareTo`, ten jest „ja"**.

### C. Sortowanie po tekście

```csharp
public int CompareTo(Uczen? inny)
{
    return Imie.CompareTo(inny?.Imie ?? "");
}
```
→ `Ala(5) Bo(4) Cyd(3)`

> „Ta sama klasa, ta sama lista, to samo `Sort()`. Zmieniła się jedna linia — i porządek jest zupełnie inny."

**To pokazuje, gdzie leży decyzja:** nie w `Sort`, tylko w twoim kontrakcie.

### D. Sortowanie po dwóch kryteriach

```csharp
public int CompareTo(Uczen? inny)
{
    if (inny == null) return 1;

    int poOcenie = Ocena.CompareTo(inny.Ocena);
    if (poOcenie != 0)
    {
        return poOcenie;
    }

    return Imie.CompareTo(inny.Imie);
}
```

> „Kiedy wykona się ostatnia linia?"
→ tylko gdy oceny są **równe**. Wtedy rozstrzyga imię.

To wzorzec, który uczeń zobaczy w każdym prawdziwym kodzie sortującym.

### E. `Array.Sort` działa tak samo

```csharp
Uczen[] tablica = { new Uczen("Cyd", 3), new Uczen("Ala", 5) };
Array.Sort(tablica);
Console.WriteLine(string.Join(" ", tablica));
```

> „Nie zmieniałeś nic w klasie. Czemu `Array.Sort` też zadziałało?"
→ bo też pyta o `IComparable`. **Jeden kontrakt, wiele narzędzi.**

### F. `IEnumerable` — czemu `foreach` w ogóle działa

Zapytaj, zanim pokażesz cokolwiek:
> „`foreach` działał ci na tekście (5.3), tablicy (6.1), liście (6.2) i słowniku (6.3). To cztery zupełnie różne rzeczy. Skąd `foreach` wie, jak po nich chodzić?"

Odpowiedź: **wszystkie implementują interfejs `IEnumerable`.** `foreach` nie zna listy ani tablicy — zna tylko kontrakt „da się po mnie przejść po kolei".

```csharp
List<int> lista = [1, 2, 3];
IEnumerable<int> cos = lista;

foreach (int x in cos)
{
    Console.Write(x + " ");
}
```
→ `1 2 3`

> „Zmienna jest typu `IEnumerable<int>` — czyli »coś, po czym da się przejść«. `foreach` niczego więcej nie potrzebuje."

**Własnego `IEnumerable` w tym kursie nie piszemy.** Wymaga elementów, których nie mamy. Wystarczy, że uczeń **rozumie, dlaczego** `foreach` jest tak uniwersalny.

> „Zapamiętaj tę nazwę — wróci w module 13, gdy poznasz LINQ. Wszystkie jego narzędzia działają właśnie na `IEnumerable`."

## Krok 4 — Pogłębienie (10 min)

**Interfejsy, których uczeń już używał, nie wiedząc o tym**

| Interfejs | Gdzie się objawiał | Od lekcji |
| --- | --- | --- |
| `IEnumerable<T>` | każdy `foreach` | 5.3 |
| `IComparable<T>` | `Sort()` na liczbach i tekstach | 6.2 |
| `IDisposable` | zobaczysz przy `using` | 11.2 |

> „Biblioteka C# jest zbudowana na interfejsach. Twoje klasy mogą do niej **dołączyć**, implementując te same kontrakty — i wtedy działają z gotowymi narzędziami, których nikt nie pisał z myślą o tobie."

To jest najważniejsze zdanie lekcji.

**`ToString` to nie interfejs**

> „`ToString` nadpisywałeś w 8.2 słowem `override`, a nie `implement`. Czemu?"
→ bo pochodzi z klasy `object` (9.1), nie z interfejsu. **`override` dla dziedziczenia, implementacja dla interfejsu.**

To rozróżnienie warto nazwać, bo oba wyglądają podobnie.

**Sortowanie bez zmiany klasy**

> „A gdybyś chciał raz posortować po ocenie, a raz po imieniu, nie przepisując klasy?"
→ da się — `lista.Sort((a, b) => ...)`. To wymaga wyrażeń lambda, czyli **lekcji 13.3**. Nazwa i numer, dalej.

**Czego nie robić w `CompareTo`**

- nie wypisuj niczego na ekran
- nie zmieniaj obiektów
- pilnuj spójności: jeśli `a` jest przed `b`, to `b` musi być za `a`

> „Niespójna reguła daje sortowanie, które czasem działa, a czasem nie — i to jest bardzo trudne do znalezienia."

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „`IComparable`". Propozycje:

- 🔥 **Rozgrzewka** (`30-icomparable-a.cs`): klasa `Ksiazka` z `Tytul` i `Rok`, implementująca `IComparable<Ksiazka>` porównującą po roku. Utwórz listę pięciu książek, posortuj i wypisz.
- ⭐ **Główne** (`30-icomparable-b.cs`): klasa `Produkt` z `Nazwa`, `Cena` i `Ilosc`. Zaimplementuj `CompareTo` sortujące **po cenie rosnąco, a przy równych cenach — alfabetycznie po nazwie**. Utwórz listę sześciu produktów (w tym dwa o tej samej cenie), posortuj, wypisz. Potem zmień regułę na malejącą po cenie i pokaż mi oba wyniki.
- ⚡ **Gwiazdka** (`30-icomparable-c.cs`): klasa `Wersja` reprezentująca numer wersji z trzema liczbami (`Glowna`, `Pomniejsza`, `Poprawka`). Zaimplementuj `CompareTo` porównujące je **po kolei**: najpierw główną, przy równych — pomniejszą, przy równych — poprawkę. Dodaj `ToString()` w formacie `1.4.2`. Posortuj listę siedmiu wersji, w tym `1.10.0` i `1.9.0` — i sprawdź, czy wyszły w dobrej kolejności. Wyjaśnij mi, czemu sortowanie tych wersji **jako tekstów** dałoby zły wynik.

Gwiazdka ma pułapkę, którą uczeń musi zauważyć: tekstowo `"1.10.0"` jest **przed** `"1.9.0"`, bo znak `1` jest wcześniej niż `9`.

## Pułapki

- **`Sort()` bez `IComparable`** → `InvalidOperationException` w czasie działania, nie błąd kompilacji.
- **Zwracanie `true`/`false` z `CompareTo`** → nie skompiluje się; metoda zwraca `int`.
- **Mylenie kierunku** — kto woła `CompareTo`, ten jest „ja". Zamiana stron odwraca sortowanie.
- **Zapominanie o `null`** — `Sort` może podać `null`. Zabezpiecz się na początku metody.
- **Niespójna reguła** — sortowanie działa losowo. Trzymaj się jednego kryterium (plus rozstrzygające).
- **Sortowanie liczb jako tekstów** — `"10"` jest przed `"9"`. Wraca w gwiazdce.
- **Implementacja `IComparable` bez `<T>`** — starsza, nieogólna wersja przyjmuje `object` i wymaga rzutowania. Używaj `IComparable<T>`.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Starsze materiały pokazują `IComparable` **bez nawiasów ostrych**:
```csharp
public int CompareTo(object obj) { ... }
```
Ta wersja jest starsza od typów ogólnych i wymaga rzutowania w środku. Dziś używa się `IComparable<T>` — bezpieczniejszej i czytelniejszej.

`IEnumerable` bez `<T>` ma tę samą historię.

## Notatki tutora

- **Krok 2 musi zacząć się od wyjątku.** Uczeń zna `Sort()` z lekcji 6.2 i uważa je za oczywiste. Dopiero `InvalidOperationException` na własnej klasie pokazuje, że `Sort` czegoś od niego chce.
- **Krok 3.F jest ważniejszy niż implementacja `IComparable`.** Uczeń używał `foreach` przez pięć modułów; zrozumienie, że działa dzięki kontraktowi, zmienia jego obraz całej biblioteki.
- **Nie każ implementować `IEnumerable`.** Wymaga jawnej implementacji nieogólnej wersji i `IEnumerator` — to trzy nowe rzeczy naraz, bez zysku dydaktycznego na tym etapie.
- **`?.` i `??` w kroku 2 obsłuż jednym zdaniem.** Nie rozwijaj; poza kursem.
- **Nie wprowadzaj `IComparer`** ani lambd. Krok 4 podaje nazwę i numer lekcji.
- **Nie wprowadzaj `IEquatable` ani nadpisywania `Equals`.** Uczeń może zapytać po lekcji 8.1, gdzie `==` porównywało tożsamość — odpowiedz „da się to zmienić, ale to poza tym kursem".
- Jeśli uczeń pyta, czemu `CompareTo` zwraca `int`, a nie `enum` z trzema wartościami — dobre pytanie. Odpowiedź historyczna: bo odejmowanie dwóch liczb daje gotowy wynik. Nie rozwijaj.
