# Lekcja 5.1 — Pętla `while`

## Cel
Po lekcji uczeń:
- Pisze pętlę `while` i rozumie, że warunek sprawdzany jest **przed** każdym obiegiem
- Umie **dopytać użytkownika, aż poda poprawne dane** — domyka lekcje 3.2 i 4.1
- Wie, czemu powstaje nieskończona pętla, i umie ją przerwać (Ctrl+C)
- Zna `do...while` i wie, czym różni się od `while`
- Rozumie, że pętla to `if`, który się powtarza

> **To lekcja, na którą uczeń czeka od modułu 3.** Trzy razy słyszał „a jak zapytać jeszcze raz? — w module 5". To jest moduł 5.

## Krok 1 — Zakotwiczenie (5-8 min)

**Pytanie wejściowe — wróć do zadania z lekcji 1.1:**
> „Pamiętasz, jak rozpisywałeś na kartce parzenie herbaty? Zajrzyj tam. Czy któryś krok brzmiał mniej więcej »mieszaj, aż cukier się rozpuści«?"

Jeśli uczeń ma tę kartkę — świetnie. Jeśli nie, zapytaj wprost:
> „Jak zapisałbyś »mieszaj, aż cukier się rozpuści« dla kogoś, kto wykonuje instrukcje dosłownie i nie domyśla się niczego?"

**Co chcesz usłyszeć:** trzeba mieszać, sprawdzać, i wracać do mieszania, dopóki warunek nie przestanie być prawdziwy.

**Drugie pytanie:**
> „Ile razy trzeba zamieszać?"

**Co chcesz usłyszeć:** nie wiadomo z góry. **To jest sedno tej lekcji.** Są czynności, których liczby powtórzeń nie znasz, zanim zaczniesz.

**Trzecie pytanie:**
> „A co, gdyby cukier się nigdy nie rozpuścił — bo wsypałeś go do zimnej wody?"

**Co chcesz usłyszeć:** mieszałbyś w nieskończoność. Zapamiętaj tę odpowiedź; wróci w kroku 3.C.

**Czego NIE rób:** nie mów jeszcze „pętla", „iteracja".

## Krok 2 — Mostek (10 min)

**Mostek:**
> „To, co opisałeś — »rób to, dopóki warunek jest prawdziwy« — w C# nazywamy **pętlą**. Najprostsza zapisuje się słowem `while` i wygląda **dokładnie jak `if`**, tylko zamiast wykonać się raz, wykonuje się w kółko."

Pokaż uczniowi zestawienie:

```csharp
if (licznik < 3)          // sprawdzi raz, wykona raz
{
    Console.WriteLine(licznik);
}

while (licznik < 3)       // sprawdzi, wykona, sprawdzi, wykona...
{
    Console.WriteLine(licznik);
}
```

> „Różni się jedno słowo. Co się zmieni w działaniu?"

Uczeń tworzy `kurs/zadania/11-while.cs`:

```csharp
int licznik = 0;

while (licznik < 3)
{
    Console.WriteLine($"Obieg numer {licznik}");
    licznik = licznik + 1;
}

Console.WriteLine("Koniec");
```
→
```
Obieg numer 0
Obieg numer 1
Obieg numer 2
Koniec
```

**Pytania:**
- „Ile razy wykonało się wnętrze pętli? Czemu nie cztery?"
- „Kiedy sprawdzany jest warunek — przed czy po wykonaniu wnętrza?"
- „Pamiętasz `licznik = licznik + 1` z lekcji 2.4? Teraz widać, po co to było."

> **To jest ta chwila, w której zapis `licznik = licznik + 1` przestaje być ciekawostką.** Bez niego pętla nigdy by się nie skończyła — i uczeń zaraz to zobaczy.

## Krok 3 — Eksperyment (25 min)

### A. Zmiana granicy

Uczeń zmienia `3` na `10`, potem na `0`.

> „Przy zerze wnętrze wykonało się ile razy?"
→ ani razu. Warunek był fałszywy **od początku**, więc pętla nie weszła w ogóle.

To ważne: **`while` może wykonać się zero razy.**

### B. Zapytaj, aż poda poprawnie — nagroda za czekanie

To domknięcie lekcji 3.2 i 4.1. Uczeń pisze:

```csharp
int rok = 0;
bool ok = false;

while (!ok)
{
    Console.Write("Podaj rok urodzenia: ");
    ok = int.TryParse(Console.ReadLine(), out rok);

    if (!ok)
    {
        Console.WriteLine("To nie jest liczba. Spróbuj jeszcze raz.");
    }
}

Console.WriteLine($"Dziękuję. Rocznik {rok}.");
```

Uczeń uruchamia i **celowo wpisuje bzdury kilka razy**, zanim poda liczbę.

> „W lekcji 3.2 program tylko stwierdzał, że dane są złe. W 4.1 umiał na to zareagować jednym komunikatem. Co robi teraz?"
→ nie odpuszcza, dopóki nie dostanie tego, o co prosi.

**Zatrzymaj się tutaj.** To jest pierwszy program w kursie, który zachowuje się jak prawdziwa aplikacja.

> **Zwróć uwagę:** `rok` i `ok` są zadeklarowane **przed** pętlą. Gdyby powstawały w środku, znikałyby po każdym obiegu — a `rok` jest potrzebny po wyjściu z pętli.

### C. Nieskończona pętla — i jak z niej wyjść

Uprzedź ucznia, **zanim** uruchomi: „za chwilę program się nie skończy i to jest zamierzone. Przerwiesz go **Ctrl+C** — pamiętasz z lekcji 1.2."

```csharp
int i = 0;
while (i < 3)
{
    Console.WriteLine(i);
}
```
→ wypisuje `0` w nieskończoność.

> „Czego brakuje w porównaniu z kodem z kroku 2?"
→ `i` nigdy się nie zmienia, więc warunek jest zawsze prawdziwy.

To jest cukier w zimnej wodzie z kroku 1.

> **Zasada:** w każdej pętli `while` musi się dziać coś, co **przybliża** warunek do fałszu. Jeśli nie widzisz, co to jest — pętla się nie skończy.

Niech uczeń **naprawi** ją, dopisując `i++`.

### D. `do...while` — sprawdź po, nie przed

```csharp
int j = 10;

do
{
    Console.WriteLine($"Wykonało się dla j = {j}");
    j++;
}
while (j < 3);
```
→ `Wykonało się dla j = 10` — **raz**, mimo że warunek był fałszywy od początku.

> „Porównaj z krokiem 3.A, gdzie `while` nie wykonał się ani razu. Co się zmieniło?"
→ w `do...while` warunek sprawdzany jest **po** wykonaniu wnętrza, więc wnętrze wykonuje się **co najmniej raz**.

> „Kiedy to jest to, czego chcesz?"
→ gdy pytasz użytkownika o coś: pytanie trzeba zadać przynajmniej raz, zanim ocenisz odpowiedź.

**Zwróć uwagę na średnik** po `while (j < 3);` — tutaj jest wymagany. To jedyne miejsce w C#, gdzie po `while` stoi średnik.

### E. `do...while` zamiast flagi

Ten sam program co w kroku B, krócej:

```csharp
int rok;
bool ok;

do
{
    Console.Write("Podaj rok urodzenia: ");
    ok = int.TryParse(Console.ReadLine(), out rok);
}
while (!ok);

Console.WriteLine($"Dziękuję. Rocznik {rok}.");
```

> „Zniknęła jedna rzecz z wersji z kroku B. Co takiego?"
→ `bool ok = false;` — nie trzeba już ustawiać wartości początkowej, bo pętla i tak wykona się raz i sama ją nada.

## Krok 4 — Pogłębienie (10 min)

**Pętla, która liczy w dół:**
```csharp
int odliczanie = 5;
while (odliczanie > 0)
{
    Console.WriteLine(odliczanie);
    odliczanie--;
}
Console.WriteLine("Start!");
```
> „`odliczanie--` — pamiętasz z lekcji 2.4? To samo co `odliczanie = odliczanie - 1`."

**Suma w pętli — wzorzec, który wraca do końca kursu:**
```csharp
int suma = 0;
int n = 1;

while (n <= 100)
{
    suma = suma + n;
    n++;
}

Console.WriteLine($"Suma liczb od 1 do 100: {suma}");
```
→ `5050`

> „Zwróć uwagę na `suma = 0` **przed** pętlą. Co by się stało, gdyby stało w środku?"
→ zerowałaby się w każdym obiegu. To najczęstszy błąd przy sumowaniu.

**Pomyłka o jeden — najczęstszy błąd w pętlach:**
```csharp
int k = 1;
while (k < 5) { Console.Write(k + " "); k++; }   // 1 2 3 4
```
> „Ile liczb się wypisze? A gdyby było `k <= 5`?"

**Nie ucz tego regułą.** Niech uczeń sprawdzi obie wersje i sam zobaczy różnicę. Pomyłka o jeden to rzecz, którą się rozpoznaje przez doświadczenie, nie przez zapamiętanie.

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „pętla `while`". Propozycje:

- 🔥 **Rozgrzewka** (`11-while-a.cs`): wypisz liczby od 1 do 10, każdą w osobnej linii. Potem zmień program tak, żeby wypisywał je od 10 do 1.
- ⭐ **Główne** (`11-while-b.cs`): zgadywanka na odwrót. Ustaw w kodzie `int sekret = 7;`. Pytaj użytkownika o liczbę, dopóki nie trafi. Po każdej złej odpowiedzi napisz `Za mało` albo `Za dużo`. Gdy trafi — pogratuluj i podaj, ile prób zajęło. (Licznik prób zwiększaj w pętli.)
- ⚡ **Gwiazdka** (`11-while-c.cs`): suma cyfr liczby. Zapytaj o liczbę całkowitą dodatnią. Policz sumę jej cyfr **bez zamieniania na tekst** — używając `% 10` (ostatnia cyfra) i `/ 10` (obcięcie ostatniej cyfry) z lekcji 2.4. Dla `1234` wynik to `10`. Sprawdź też na `9`, `100` i `0`.

Gwiazdka to najładniejsze zastosowanie `%` i dzielenia całkowitego w całym module 2 — i pierwszy raz, gdy uczeń nie wie z góry, ile obiegów wykona pętla.

## Pułapki

- **Zapomniana zmiana zmiennej w pętli** → pętla nieskończona. Objaw: program wypisuje w kółko to samo. Ratunek: **Ctrl+C**.
- **Zmienna zadeklarowana w środku pętli** — znika po każdym obiegu i nie da się jej użyć po wyjściu. Przy sumowaniu daje wynik zerowy.
- **`suma = 0` w środku zamiast przed pętlą** — zeruje się co obieg. Program działa, wynik jest zły. Kompilator milczy.
- **Pomyłka o jeden** — `<` kontra `<=`. Nie da się tego zapamiętać raz na zawsze; sprawdza się na małych liczbach.
- **Brak średnika po `do...while`** — `while (warunek)` bez średnika na końcu daje mylący komunikat.
- **Pętla, która nie wykonuje się ani razu** — to nie zawsze błąd; przy `while` to normalne zachowanie. Warto sprawdzić, czy właśnie tego się chciało.
- **`Ctrl+C` w terminalu wbudowanym w edytor** — działa, ale trzeba najpierw kliknąć w okno terminala.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Ta lekcja nie ma zmian. `while` i `do...while` wyglądają w C# tak samo od pierwszej wersji języka — każdy stary poradnik jest tu aktualny.

## Notatki tutora

- **Krok 3.B jest emocjonalnie najważniejszy w całym module.** Uczeń trzy razy słyszał „w module 5" i to jest ta chwila. Nie przelatuj; zapytaj wprost, czy widzi różnicę wobec lekcji 4.1.
- **Uprzedź o nieskończonej pętli przed krokiem 3.C.** Uczeń, któremu program „się zawiesi" bez ostrzeżenia, może się przestraszyć i zamknąć terminal. Ctrl+C ma być zapowiedziane.
- **Nie wprowadzaj `for`.** Uczeń zapyta („to się da krócej?") — lekcja 5.2, następna. Nazwa i numer.
- **Nie wprowadzaj `break`** ani `while (true)`. To lekcja 5.3. Wersja z flagą `ok` jest w kroku 3.B celowo — uczeń ma zobaczyć, że da się bez `break`, zanim pozna `break`.
- **Nie wprowadzaj tablic ani list.** „A jak zapamiętać wszystkie odpowiedzi?" → moduł 6.
- **Pomyłkę o jeden pokaż, nie tłumacz.** Reguła („`<` daje o jeden mniej") nie zostaje w głowie; dwa uruchomienia zostają.
- Jeśli uczeń pisze pętlę bez zmiany zmiennej **po raz drugi** — to normalne. Ta pomyłka wraca kilka razy, zanim wejdzie w nawyk sprawdzania „co tu się zmienia?".
