# Lekcja 13.2 — Agregacje i grupowanie

## Cel
Po lekcji uczeń:
- Liczy `Count`, `Sum`, `Average`, `Min`, `Max` — także z warunkiem
- Sprawdza `Any` i `All` zamiast pisać pętlę z flagą
- Dzieli kolekcję na grupy przez `GroupBy` i liczy coś w każdej grupie
- Wie, które metody wywracają się na pustej kolekcji
- Buduje zestawienie: „ile czego w każdej kategorii"

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Masz listę wyników i chcesz znać średnią. Napisz to pętlą."

Spodziewane: suma w zmiennej, licznik, dzielenie na końcu.

> „A najwyższy wynik?"
→ kolejna pętla, zmienna `max`, porównanie w środku.

> „Ile takich pętli napisałeś w module 5 i 6?"

**Co chcesz usłyszeć:** dużo, i za każdym razem prawie identycznych.

> „Wszystkie sprowadzają wiele wartości do **jednej**. To się nazywa agregacja i LINQ ma ją gotową."

## Krok 2 — Mostek (10 min)

```csharp
List<int> liczby = new List<int> { 5, 12, 3, 20, 8 };

Console.WriteLine(liczby.Count());
Console.WriteLine(liczby.Sum());
Console.WriteLine(liczby.Min());
Console.WriteLine(liczby.Max());
Console.WriteLine(liczby.Average());
```
→ `5`, `48`, `3`, `20`, `9,6`

**Pytania:**
- „Co zwracają — kolekcję czy jedną wartość?" → **jedną wartość.** Tym różnią się od `Where` i `Select`.
- „Czy któraś potrzebuje `ToList`?" → nie. Wynik jest gotową liczbą, nie przepisem.
- „Skąd przecinek w `9,6`?" → z ustawień regionalnych systemu; w Polsce przecinek jest separatorem dziesiętnym. To ta sama zasada, co przy wypisywaniu liczb w lekcji 3.1.

> **`Count()` a `Count`** — na liście istnieje właściwość `Count` (z lekcji 6.2) i metoda `Count()` z LINQ. Na liście dają to samo. Na wyniku zapytania jest tylko metoda, z nawiasami.

## Krok 3 — Eksperyment (22 min)

### A. Agregacja z warunkiem

```csharp
Console.WriteLine(liczby.Count(x => x > 5));
```
→ `3`

> „Jak zrobiłbyś to bez tego skrótu?"
→ `liczby.Where(x => x > 5).Count()` — to samo, dłużej.

Działa też przy `Sum`, `Min`, `Max`, `Average` — z tą różnicą, że tam lambda mówi **co sumować**, nie **które elementy**:
```csharp
Console.WriteLine(uczniowie.Sum(u => u.Punkty));
Console.WriteLine(uczniowie.Max(u => u.Punkty));
```

> „Zwróć uwagę na dwa różne znaczenia tej samej lambdy: przy `Count` to warunek, przy `Sum` — wybór wartości. Przy `Count` pytasz »czy liczyć«, przy `Sum` — »co dodać«."

To rzeczywiste źródło pomyłek. Powiedz wprost.

### B. `Any` i `All`

```csharp
Console.WriteLine(liczby.Any(x => x > 100));
Console.WriteLine(liczby.All(x => x > 0));
```
→ `False` i `True`

> „Napisz `Any` pętlą."
→ zmienna `bool znaleziono = false`, pętla, `if`, ustawienie flagi, `break`. Pięć linii zamiast jednej.

> „`Any()` bez warunku odpowiada na pytanie »czy w ogóle coś tu jest«."

### C. Puste kolekcje — tu się psuje

```csharp
List<int> pusta = new List<int>();

Console.WriteLine(pusta.Sum());
Console.WriteLine(pusta.Count());
Console.WriteLine(pusta.Max());
```
→ `0`, `0`, a potem:
```
System.InvalidOperationException: Sequence contains no elements
```

> „Czemu `Sum` daje zero, a `Max` się wywraca?"
→ suma zera składników to zero — to ma sens. **Największy element z niczego nie istnieje.**

`Average` na pustej kolekcji wywraca się tak samo.

> „Jak się zabezpieczyć?"
→ sprawdzić wcześniej:
```csharp
if (pusta.Any())
{
    Console.WriteLine(pusta.Max());
}
```

**To najczęstszy wyjątek przy LINQ w prawdziwym kodzie**, bo pusta lista trafia się rzadko w testach i zawsze u użytkownika.

### D. `GroupBy` — dzielenie na kubełki

```csharp
List<Uczen> uczniowie = new List<Uczen>
{
    new Uczen { Imie = "Ala", Klasa = "1A", Punkty = 90 },
    new Uczen { Imie = "Bartek", Klasa = "1B", Punkty = 55 },
    new Uczen { Imie = "Celina", Klasa = "1A", Punkty = 70 }
};

foreach (var grupa in uczniowie.GroupBy(u => u.Klasa))
{
    Console.WriteLine($"{grupa.Key}: {grupa.Count()} osób");
}
```
→
```
1A: 2 osób
1B: 1 osób
```

**Pytania, po kolei:**
- „Co podałeś w lambdzie?" → **po czym grupować** — tu klasa
- „Czym jest `grupa.Key`?" → wartość, która połączyła te elementy — `"1A"`
- „Czym jest sama `grupa`?" → **kolekcją uczniów z tej klasy**. Da się po niej przejść `foreach`-em i policzyć wszystko z tej lekcji

Pokaż zawartość grupy:
```csharp
foreach (var grupa in uczniowie.GroupBy(u => u.Klasa))
{
    Console.WriteLine($"{grupa.Key}: suma {grupa.Sum(u => u.Punkty)}");

    foreach (Uczen u in grupa)
    {
        Console.WriteLine($"   - {u.Imie}");
    }
}
```
→
```
1A: suma 160
   - Ala
   - Celina
1B: suma 55
   - Bartek
```

> „Ile pętli zajęłoby to bez `GroupBy`?"
→ trzeba by najpierw zebrać wszystkie klasy do słownika, potem po nim przejść. Kilkanaście linii.

> **`GroupBy` a `Dictionary` z lekcji 6.3** — obie rzeczy wiążą klucz z wartościami. Słownik trzymasz i uzupełniasz sam; `GroupBy` buduje podział **w locie**, na jedno użycie.

### E. Zestawienie w jednym łańcuchu

```csharp
var zestawienie = uczniowie
    .GroupBy(u => u.Klasa)
    .OrderByDescending(g => g.Count());

foreach (var g in zestawienie)
{
    Console.WriteLine($"{g.Key}: {g.Count()}");
}
```

> „Na czym operuje `OrderByDescending` w tym łańcuchu?"
→ już nie na uczniach, tylko **na grupach**. Grupa też jest zwykłym elementem kolekcji.

To moment, w którym LINQ przestaje być listą sztuczek i zaczyna być składaniem klocków.

## Krok 4 — Pogłębienie (10 min)

**Ściągawka**

| Metoda | Zwraca | Na pustej kolekcji |
| --- | --- | --- |
| `Count()` | liczbę elementów | `0` |
| `Sum()` | sumę | `0` |
| `Average()` | średnią | **wyjątek** |
| `Min()` / `Max()` | skrajną wartość | **wyjątek** |
| `Any()` | `true`/`false` | `false` |
| `All()` | `true`/`false` | **`true`** |

> „Ostatni wiersz zaskakuje: »wszystkie elementy pustej listy spełniają warunek« jest prawdą, bo nie ma takiego, który by go łamał. Warto o tym pamiętać przy walidacji."

**`Count()` czy `Any()`?**

> „Gdy pytasz »czy cokolwiek pasuje«, użyj `Any`. `Count() > 0` też zadziała, ale przelicza całą kolekcję, a `Any` przerywa na pierwszym trafieniu."

**`ToDictionary` — z zapytania do słownika**

```csharp
var punktyWg = uczniowie.ToDictionary(u => u.Imie, u => u.Punkty);
Console.WriteLine(punktyWg["Ala"]);
```
→ `90`

> „Dwie lambdy: pierwsza wskazuje klucz, druga wartość. Uwaga — **powtórzony klucz to `ArgumentException`**, tak samo jak przy dopisywaniu do słownika w 6.3."

**Zapytanie na słowniku**

```csharp
foreach (var p in punktyWg.Where(p => p.Value > 60))
{
    Console.WriteLine($"{p.Key}: {p.Value}");
}
```

> „Słownik też jest kolekcją — każdy element ma `Key` i `Value`, tak jak w lekcji 6.3."

## Pułapki

- **`Max`, `Min`, `Average` na pustej kolekcji** → `InvalidOperationException: Sequence contains no elements`. Sprawdź `Any()` wcześniej.
- **`All` na pustej kolekcji zwraca `true`.** Przy walidacji „czy wszystko poprawne" pusty zbiór przechodzi.
- **Lambda w `Count` to warunek, w `Sum` — wybór wartości.** `Sum(u => u.Punkty > 60)` nawet się nie skompiluje.
- **`ToDictionary` z powtórzonym kluczem** → `ArgumentException: An item with the same key has already been added`.
- **Grupa to kolekcja, nie liczba.** `grupa.Count()`, nie `grupa`.
- **Sortowanie po `GroupBy`** działa na grupach, nie na elementach — łatwo o pomyłkę w lambdzie.

## Notatki tutora

- **Krok 3.C jest ważniejszy niż wygląda.** Wyjątek na pustej kolekcji to najczęstsza awaria programów opartych na LINQ. Niech uczeń zobaczy go na własne oczy.
- **`GroupBy` wprowadzaj w dwóch krokach**: najpierw sam `Key` i `Count`, dopiero potem zaglądanie do środka grupy. Naraz to za dużo.
- **Nie wprowadzaj `Aggregate`.** Wygląda elegancko i jest nieczytelne dla początkującego; `Sum` i `Count` wystarczają.
- **Nie wprowadzaj typów anonimowych** w `Select` po `GroupBy`. Wypisz w `foreach`.
- **Nie wprowadzaj `SelectMany` ani `Join`.** Poza kursem.
- Jeśli uczeń zapyta o wykresy albo eksport zestawienia — odeślij do lekcji 12.1 (zapis do pliku) i 14.7.
