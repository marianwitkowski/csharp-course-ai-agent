# Lekcja 2.2 — Stałe i typy wyliczeniowe

## Cel
Po lekcji uczeń:
- Tworzy stałą przez `const` i wie, kiedy warto
- Rozumie, że ograniczenie („tego nie da się zmienić") bywa zaletą, nie przeszkodą
- Tworzy własny `enum` i używa jego wartości
- Wie, że pod `enum` siedzą liczby, i umie to sprawdzić
- Potrafi powiedzieć, czemu `enum` jest lepszy niż tekst do zamkniętego zbioru możliwości

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Ile dni ma tydzień? A czy w twoim kalendarzu można dopisać ósmy?"

**Co chcesz usłyszeć:** siedem, i nie — zbiór jest zamknięty.

**Drugie pytanie:**
> „Wyobraź sobie formularz, w którym dzień tygodnia wpisuje się ręcznie, z klawiatury. Co pójdzie nie tak?"

**Co chcesz usłyszeć:** literówki, „śrida", „ŚRODA", „sroda", ktoś wpisze „jutro".

**Trzecie pytanie, o stałych:**
> „A stawka VAT — 23 procent. Czy to jest coś, co zmienia się w trakcie działania programu?"

**Czego NIE rób:** nie mów jeszcze „stała", „enum", „typ wyliczeniowy".

## Krok 2 — Mostek (10 min)

**Dwa mostki w jednej lekcji, po kolei.**

### Mostek 1 — stała

> „Wartość, która ma być ustalona raz i nigdy się nie zmienić, w C# nazywamy **stałą**. Piszemy przed nią `const`."

Uczeń tworzy `kurs/zadania/03-const-enum.cs`:

```csharp
const double StawkaVat = 0.23;
const string NazwaSklepu = "Warzywniak";

Console.WriteLine(NazwaSklepu);
Console.WriteLine(StawkaVat);
```

> „Zwróć uwagę na nazwy: `StawkaVat`, nie `stawkaVat`. Stałe piszemy z wielkiej litery — to konwencja C#."

**Pytanie:**
> „Co się stanie, jeśli spróbujesz zmienić `StawkaVat` na 0.08? Napisz to i uruchom."
→ `CS0131`. **Niech spróbuje**, nie mów wyniku.

> „Po co komuś zmienna, której nie da się zmienić? Czy to nie jest po prostu gorsza zmienna?"

Odpowiedź, do której go doprowadzasz: **kompilator pilnuje twojej decyzji**. Jeśli za pół roku ktoś (albo ty) przypadkiem przypisze tam coś innego, program się nie zbuduje — zamiast po cichu policzyć złe faktury.

### Mostek 2 — enum

> „A zamknięty zbiór możliwości — siedem dni tygodnia, trzy stany zamówienia, cztery pory roku — w C# nazywamy **typem wyliczeniowym**, po angielsku `enum`."

```csharp
DzienTygodnia dzis = DzienTygodnia.Sroda;
Console.WriteLine(dzis);

enum DzienTygodnia
{
    Poniedzialek,
    Wtorek,
    Sroda,
    Czwartek,
    Piatek,
    Sobota,
    Niedziela,
}
```

> **Uwaga o kolejności w pliku:** `enum` musi być na **końcu** pliku, po wszystkich instrukcjach. To jedyna reguła układu, jaką uczeń pozna przed modułem 8. Powiedz to wprost i bez tłumaczenia dlaczego — wyjaśnienie wymaga wiedzy o klasach.

**Pytania:**
- „Ile wartości może przyjąć `dzis`?"
- „Co się stanie, jeśli napiszesz `DzienTygodnia.Srida`?" → **niech spróbuje**

## Krok 3 — Eksperyment (20 min)

1. **Literówka w enumie.** `DzienTygodnia.Srida`
   → `CS0117: 'DzienTygodnia' does not contain a definition for 'Srida'`
   > „A teraz porównaj: gdybyś trzymał dzień jako `string dzien = \"Srida\";` — co powiedziałby kompilator?"
   → nic. Program by się zbudował i działał źle. **To jest cała odpowiedź na pytanie, po co enum.**

2. **Co siedzi pod spodem.**
   ```csharp
   Console.WriteLine(dzis);
   Console.WriteLine((int)dzis);
   ```
   → `Sroda` i `2`
   > „Skąd wzięła się dwójka? Policz od góry listy, zaczynając od zera."

3. **Własna numeracja.** Uczeń zmienia enum:
   ```csharp
   enum DzienTygodnia
   {
       Poniedzialek = 1,
       Wtorek,
       Sroda,
   }
   ```
   > „Co teraz wypisze `(int)DzienTygodnia.Sroda`? Zgadnij, zanim uruchomisz."
   → `3`. Numeracja idzie dalej od podanej wartości.

4. **Stała a zmienna — porównanie.** Uczeń pisze obok siebie:
   ```csharp
   const double Vat = 0.23;
   double vatZmienny = 0.23;

   vatZmienny = 0.08;      // działa
   // Vat = 0.08;          // nie skompiluje się
   Console.WriteLine(vatZmienny);
   ```
   > „Który z tych dwóch zapisów lepiej opisuje stawkę VAT? Czemu?"

5. **Obliczenie ze stałą.**
   ```csharp
   const double StawkaVat = 0.23;
   double cenaNetto = 100;
   double cenaBrutto = cenaNetto + cenaNetto * StawkaVat;
   Console.WriteLine(cenaBrutto);
   ```
   > „Co się stanie, gdy stawka VAT się zmieni? Ile miejsc w kodzie musisz poprawić?"
   → jedno. To jest drugi powód istnienia stałych: **nazwa zamiast rozsypanej po kodzie liczby**.

6. **Liczba bez nazwy — kontrprzykład.** Pokaż (uczeń nie musi pisać):
   ```csharp
   double brutto = netto + netto * 0.23;
   double prowizja = kwota * 0.23;
   ```
   > „Obie dwudziestki trzy znaczą to samo? Skąd wiesz?"
   → nie wiadomo. Może druga to prowizja, która przypadkiem wynosi tyle samo. Nazwa rozstrzyga.

## Krok 4 — Pogłębienie (10 min)

**Gdzie enum ma sens, a gdzie nie:**

| Pasuje | Nie pasuje |
| --- | --- |
| dni tygodnia, miesiące | imię użytkownika |
| stan zamówienia (`Nowe`, `Wyslane`, `Anulowane`) | liczba sztuk w koszyku |
| poziom trudności (`Latwy`, `Sredni`, `Trudny`) | treść komentarza |
| kierunek (`Gora`, `Dol`, `Lewo`, `Prawo`) | cena |

> „Reguła: enum wtedy, gdy potrafisz **wypisać wszystkie** możliwe wartości i lista się nie zmieni w trakcie działania programu."

**`const` a `readonly`** — uczeń może zobaczyć oba w internecie.
> „`readonly` to bliski krewny stałej, ale dotyczy klas. Zobaczysz go raz, w lekcji 14.2, przy klasie projektu — i tam wystarczy jedno zdanie."

Jedno zdanie, nie rozwijaj.

**Czego `const` nie potrafi:**
```csharp
const int Sekund = 60 * 60;          // działa — kompilator to policzy: 3600
const DateTime Start = DateTime.Now; // CS0283: The type 'DateTime' cannot be declared const
```
> „Stała musi być znana już w momencie budowania programu. »Teraz« nie jest — zależy od tego, kiedy program uruchomisz."

Komunikat `CS0283` mówi o tym wprost: nie każdy typ w ogóle nadaje się na stałą. Uczeń nie musi wiedzieć, które się nadają — wystarczy, że rozpozna ten komunikat, gdy na niego trafi.

To subtelne i nie trzeba tego głęboko drążyć, ale warto pokazać, żeby uczeń nie próbował potem `const` wszędzie.

**Nazewnictwo, podsumowanie z lekcji 2.1 i tej:**

| Co | Konwencja | Przykład |
| --- | --- | --- |
| zmienna lokalna | `camelCase` | `cenaNetto` |
| stała | `PascalCase` | `StawkaVat` |
| typ wyliczeniowy i jego wartości | `PascalCase` | `DzienTygodnia.Sroda` |

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „stałe i typy wyliczeniowe". Propozycje:

- 🔥 **Rozgrzewka** (`03-const-a.cs`): utwórz stałe `NazwaFirmy`, `RokZalozenia` i `StawkaVat`. Wypisz je w trzech liniach z opisami.
- ⭐ **Główne** (`03-const-b.cs`): utwórz `enum PoraRoku` z czterema wartościami. Zadeklaruj zmienną `aktualna` i przypisz jej jedną z nich. Wypisz: nazwę pory roku, jej numer porządkowy oraz — dodatkowo — numer pory **następnej**. Po ostatniej porze roku wyjdzie liczba spoza zakresu i **tak ma być**: zauważ problem i opisz go słowami. Zawinięcie z powrotem do zera wymaga narzędzi z lekcji 2.4 i modułu 4 — to nie jest twoja porażka, tylko brakujący klocek.
- ⚡ **Gwiazdka** (`03-const-c.cs`): kalkulator zamówienia. Stałe: `StawkaVat = 0.23`, `KosztDostawy = 15.0`, `ProgDarmowejDostawy = 200.0`. Zmienne: `cenaNetto = 180`, `sztuki = 2`. Policz i wypisz: wartość netto zamówienia, kwotę VAT, wartość brutto oraz koszt dostawy (bez używania `if` — pomyśl, jak to zrobić samą arytmetyką albo po prostu wypisz obie możliwości i zaznacz, że wybór przyjdzie w module 4).

Gwiazdka celowo natrafia na granicę: bez `if` nie da się wybrać dostawy. To jest **dobre** — uczeń sam odkrywa, czego mu brakuje, dwa moduły przed lekcją, która to daje.

## Pułapki

- **`enum` w środku pliku** → `CS8803: Top-level statements must precede namespace and type declarations.` Musi być na końcu, po wszystkich instrukcjach. Ten komunikat brzmi dla początkującego zupełnie obco — przetłumacz go wprost: „deklaracje typów (czyli twój `enum`) muszą być za instrukcjami, nie przed nimi".
- **Polskie znaki w wartościach enuma** (`Środa`) — technicznie działa, ale nie używaj. `Sroda`.
- **Próba zmiany stałej** → `CS0131`. Komunikat mówi „the left-hand side must be a variable" — trzeba go przetłumaczyć uczniowi.
- **`const` z wartością liczoną w trakcie działania** (np. `DateTime.Now`) → nie zadziała.
- **Mylenie wartości enuma z tekstem** — `dzis == "Sroda"` się nie skompiluje. To dobrze; niech uczeń spróbuje.
- **Enum z jedną wartością** — technicznie legalny, ale wtedy stała jest lepsza.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Ta lekcja nie ma znaczących zmian. `const` i `enum` wyglądają w C# tak samo od dwudziestu lat i stare materiały są tu w pełni aktualne — warto to uczniowi powiedzieć, bo buduje zaufanie do tego, co znajdzie w internecie.

Jedyna nowość, której **nie** wprowadzamy: enum można łączyć bitowo (`[Flags]`). To technika do zaawansowanych zastosowań; wspomnij jednym zdaniem tylko, jeśli uczeń sam na to trafi.

## Notatki tutora

- **To lekcja o dwóch konceptach naraz** — łamie zasadę „jeden koncept na lekcję". Uzasadnienie: oba są małe, oba dotyczą tego samego pytania („co zrobić, żeby wartość nie mogła być dowolna"), a rozbicie na dwie lekcje dałoby dwa kwadranse. Jeśli uczeń się gubi — zrób `const` dziś, `enum` na początku 2.3.
- **Krok 3.1 to sedno lekcji.** Porównanie „enum z literówką nie kompiluje się, string z literówką kompiluje się i psuje program po cichu" jest tym, co uczeń ma zapamiętać. Reszta to szczegóły.
- **Nie wprowadzaj `switch`** przy enumie, choć to naturalne połączenie. `switch` to lekcja 4.3 i tam enum wróci jako przykład.
- **Nie tłumacz, czym enum jest „pod spodem" głębiej niż `(int)`.** Wystarczy, że uczeń widzi liczbę.
- Jeśli uczeń pyta **„a jak zamienić tekst na enum"** (`Enum.Parse`) — powiedz, że da się, i odłóż. To wymaga obsługi błędów (moduł 11).
- Uczeń, który już programował w arkuszach kalkulacyjnych, dobrze rozumie stałą jako **komórkę z nazwą**, do której odwołują się formuły. Warto tę analogię wyciągnąć, jeśli pasuje.
