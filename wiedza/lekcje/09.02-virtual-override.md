# Lekcja 9.2 — `virtual`, `override` i polimorfizm

## Cel
Po lekcji uczeń:
- Oznacza metodę bazową jako `virtual` i podmienia ją w pochodnej przez `override`
- **Rozumie wreszcie `override` z lekcji 8.2** — i wie, co dokładnie nadpisywał
- Trzyma różne obiekty w jednej kolekcji typu bazowego i wywołuje na nich tę samą metodę
- Wywołuje wersję bazową przez `base.Metoda()`
- Rozpoznaje `CS0506` i ostrzeżenie `CS0108`

> **To jest lekcja, którą uczeń otworzył sam na końcu 9.1**, pytając: czemu pies i kot przedstawiają się identycznie?

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Mówisz do sali pełnej zwierząt: »odezwij się«. Ile różnych dźwięków usłyszysz?"

**Co chcesz usłyszeć:** tyle, ile gatunków. **Jedno polecenie, wiele różnych odpowiedzi.**

**Drugie pytanie:**
> „Czy musisz wiedzieć, jakie dokładnie zwierzęta siedzą w sali, żeby wydać to polecenie?"

**Co chcesz usłyszeć:** nie. Mówisz raz, każdy odpowiada po swojemu.

**To jest polimorfizm w jednym zdaniu** — nie nazywaj jeszcze.

## Krok 2 — Mostek (12 min)

Wróć do problemu z końca 9.1:

```csharp
class Zwierze
{
    public string Imie { get; }
    public Zwierze(string imie) => Imie = imie;
    public string DajGlos() => "...";
    public void Przedstaw() => Console.WriteLine($"{Imie} mówi: {DajGlos()}");
}

class Kot : Zwierze
{
    public Kot(string imie) : base(imie) { }
    public string DajGlos() => "miau";
}
```

```csharp
Kot k = new Kot("Mruczek");
k.Przedstaw();
```
→ `Mruczek mówi: ...`

> „Napisałeś kotu własne `DajGlos`, a przedstawia się kropkami. Czemu?"

Kompilator zresztą ostrzegał:
```
warning CS0108: 'Kot.DajGlos()' hides inherited member 'Zwierze.DajGlos()'. Use the new keyword if hiding was intended.
```

> „»Ukrywa odziedziczoną składową«. Nie **zastępuje** — **ukrywa**. `Przedstaw` jest napisane w klasie `Zwierze` i widzi wersję zwierzęcia."

**Mostek:**
> „Żeby metoda pochodnej naprawdę **zastąpiła** bazową, obie strony muszą się na to zgodzić: baza mówi `virtual` (»tę można podmienić«), pochodna mówi `override` (»podmieniam«)."

```csharp
class Zwierze
{
    public string Imie { get; }
    public Zwierze(string imie) => Imie = imie;

    public virtual string DajGlos() => "...";

    public void Przedstaw() => Console.WriteLine($"{Imie} mówi: {DajGlos()}");
}

class Kot : Zwierze
{
    public Kot(string imie) : base(imie) { }
    public override string DajGlos() => "miau";
}
```
→ `Mruczek mówi: miau`

**Pytania:**
- „Co zmieniłeś? Dwa słowa. Które?"
- „`Przedstaw` nie zmieniło się ani o znak. Skąd wie, że ma zawołać kocią wersję?"
  → **decyzja zapada w czasie działania**, na podstawie tego, czym obiekt naprawdę jest.

Nazwij: **`virtual`**, **`override`**, **metoda wirtualna**.

> **To jest odpowiedź na pytanie z 8.2.** Pisałeś tam `public override string ToString()`. Teraz wiesz: `ToString` jest w klasie `object` oznaczone jako `virtual`, a ty je nadpisywałeś.

## Krok 3 — Eksperyment (25 min)

### A. Trzecia klasa bez wysiłku

```csharp
class Pies : Zwierze
{
    public Pies(string imie) : base(imie) { }
    public override string DajGlos() => "hau";
}
```

```csharp
new Kot("Mruczek").Przedstaw();
new Pies("Burek").Przedstaw();
new Zwierze("Coś").Przedstaw();
```
→ `miau`, `hau`, `...`

> „Ile linii dopisałeś w klasie `Zwierze`, żeby obsłużyć psa?"
→ **zero.**

### B. Polimorfizm — jedna kolekcja, różne obiekty

```csharp
List<Zwierze> zoo = new List<Zwierze>
{
    new Kot("Mruczek"),
    new Pies("Burek"),
    new Kot("Filemon")
};

foreach (Zwierze z in zoo)
{
    Console.WriteLine($"{z.Imie}: {z.DajGlos()}");
}
```
→ `miau`, `hau`, `miau`

> „Jakiego typu jest lista? Jakiego typu są elementy w środku?"
→ lista `Zwierze`, w środku koty i psy.

> „Skąd `foreach` wie, którą wersję `DajGlos` zawołać przy każdym elemencie?"
→ **z tego, czym obiekt naprawdę jest**, nie z tego, jak nazwany jest typ zmiennej.

**To jest sala pełna zwierząt z kroku 1.** Jedno polecenie, różne odpowiedzi.

> „Co byś musiał napisać bez tego mechanizmu?"
→ `if (z jest kotem) ... else if (z jest psem) ...` — i dopisywać gałąź przy każdym nowym gatunku.

**Zatrzymaj się tutaj.** To jest cały zysk z polimorfizmu i jedyne miejsce w kursie, gdzie widać go w całości.

### C. `override` bez `virtual`

```csharp
class Zwierze
{
    public string DajGlos() => "...";
}
class Kot : Zwierze
{
    public override string DajGlos() => "miau";
}
```
→ `CS0506: 'Kot.DajGlos()': cannot override inherited member 'Zwierze.DajGlos()' because it is not marked virtual, abstract, or override`

> „Baza musi **pozwolić** na podmianę. Czemu to nie jest domyślne?"
→ bo autor klasy bazowej decyduje, co wolno zmieniać, a co ma zostać jak jest. `Przedstaw` w naszym przykładzie **nie** jest wirtualne — i to celowe.

### D. `base.Metoda()` — rozszerz, zamiast zastępować

Najpierw `Zwierze` dostaje własne `ToString`:

```csharp
class Zwierze
{
    // ...reszta bez zmian...
    public override string ToString() => Imie;
}

class Pies : Zwierze
{
    public Pies(string imie) : base(imie) { }

    public override string DajGlos() => "hau";

    public override string ToString() => $"Pies {base.ToString()}";
}
```
```csharp
Console.WriteLine(new Pies("Reks"));
```
→ `Pies Reks`

> „`base.ToString()` woła wersję **bazową**. Kiedy to się przydaje?"
→ gdy chcesz dołożyć coś do zachowania bazy, a nie wyrzucić je.

Bez `base.` byłaby nieskończona rekurencja — metoda wołałaby samą siebie.

> **Gdyby `Zwierze` nie miało własnego `ToString`**, `base.ToString()` sięgnęłoby aż do `object`, a ta wersja wypisuje **nazwę typu**. Wyszłoby `Pies Pies` — wynik śmieszny, ale pouczający: `base` idzie o jeden poziom w górę, nie do „czegoś sensownego".

### E. Właściwość też może być wirtualna

```csharp
class Zwierze
{
    public virtual string Opis => "zwykłe zwierzę";
}
class Kot : Zwierze
{
    public override string Opis => "kot, chodzi własnymi drogami";
}
```

> „`virtual` i `override` działają nie tylko na metodach. Na czym jeszcze?"
→ na właściwościach, a od modułu 10 zobaczysz je też przy innych elementach.

### F. Typ zmiennej a typ obiektu

```csharp
Zwierze z = new Kot("Mruczek");
Console.WriteLine(z.DajGlos());
Console.WriteLine(z.GetType());
```
→ `miau` i `Kot`

> „Zmienna jest typu `Zwierze`, a odpowiedź kocia. Co to znaczy?"
→ **typ zmiennej mówi, czego wolno używać; typ obiektu decyduje, co się wykona.**

Niech uczeń spróbuje:
```csharp
z.Drapie();
```
(zakładając, że `Drapie` jest tylko w `Kot`)
→ `CS1061` — bo zmienna jest typu `Zwierze`, a zwierzę nie umie drapać.

> „Obiekt umie, ale zmienna o tym nie wie. To ograniczenie, nie błąd — dzięki niemu `List<Zwierze>` jest bezpieczna."

## Krok 4 — Pogłębienie (10 min)

**Trzy słowa, które łatwo pomylić**

| Słowo | Znaczy |
| --- | --- |
| `virtual` | „tę metodę **wolno** podmienić" (w bazie) |
| `override` | „podmieniam" (w pochodnej) |
| `new` przy metodzie | „ukrywam, nie podmieniam" — prawie zawsze pomyłka |

> „`CS0108` z kroku 2 proponował dopisanie `new`. **Nie rób tego.** To ostrzeżenie prawie zawsze znaczy, że chciałeś `override` i zapomniałeś `virtual` w bazie."

**Kiedy `virtual`, a kiedy nie**

- `virtual` — gdy pochodne **mają** zachowywać się inaczej (`DajGlos`)
- bez `virtual` — gdy zachowanie ma być **takie samo dla wszystkich** (`Przedstaw`)

> „Metoda wirtualna to obietnica: »ktoś to zmieni«. Nie dawaj jej wszystkiemu na zapas — im więcej wirtualnych, tym trudniej przewidzieć, co się naprawdę wykona."

**Polimorfizm bez dziedziczenia?**

> „Ten sam efekt da się osiągnąć **interfejsami** i często jest to lepsze. To moduł 10."

**Podsumowanie trzech filarów, które uczeń już zna**

| Filar | Gdzie poznany | Po co |
| --- | --- | --- |
| enkapsulacja | 8.4 | obiekt sam pilnuje swojej poprawności |
| dziedziczenie | 9.1 | wspólna część w jednym miejscu |
| polimorfizm | 9.2 | jedno polecenie, różne zachowania |

> „To są trzy rzeczy, o które pytają na każdej rozmowie o pracę z C#. Właśnie użyłeś wszystkich trzech w działającym programie."

Trzymaj wszystkich w `List<Pracownik>`, wypisz wypłaty i sumę całkowitą. Zwróć uwagę, że pętla sumująca **nie wie**, jakie to typy.

Wrzuć pięć powiadomień różnych typów do jednej listy i wyślij wszystkie jedną pętlą. Potem dopisz **czwarty** typ i policz, ile linii istniejącego kodu musiałeś zmienić.

Ostatnie pytanie gwiazdki jest sednem: odpowiedź brzmi **zero** i uczeń ma to zobaczyć na własnym kodzie.

## Pułapki

- **`override` bez `virtual` w bazie** → `CS0506`.
- **Własna metoda bez `override`** → `CS0108`, metoda ukryta, baza dalej woła swoją. Objaw: „przecież nadpisałem".
- **Dopisanie `new` zamiast naprawy** — ucisza ostrzeżenie, zostawia błąd.
- **`ToString()` bez `override`** — ten sam problem, tylko trudniejszy do zauważenia.
- **Wywołanie własnej metody zamiast `base.`** wewnątrz `override` → nieskończona rekurencja i przepełnienie stosu.
- **Sięganie po składową pochodnej przez zmienną typu bazowego** → `CS1061`. Typ zmiennej ogranicza, co wolno.
- **`virtual` na wszystkim** — trudniej przewidzieć, co się wykona. Wirtualne tylko to, co ma być podmieniane.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Ta lekcja nie ma zmian. `virtual` i `override` działają w C# tak samo od pierwszej wersji.

Jedna uwaga o kierunku: w nowszym kodzie ten sam efekt częściej osiąga się **interfejsami** (moduł 10) niż dziedziczeniem. Mechanizm z tej lekcji nadal jest podstawą i trzeba go znać — ale nie jest już domyślnym wyborem.

## Notatki tutora

- **Krok 2 musi zacząć się od `CS0108`.** Uczeń pisze kocie `DajGlos`, słyszy kropki i widzi ostrzeżenie. Dopiero ta porażka tłumaczy, po co dwa słowa zamiast jednego.
- **Krok 3.B to najważniejsze pięć minut modułu 9.** Zapytaj wprost: „co musiałbyś napisać bez tego?" — łańcuch `if`ów rozrastający się przy każdym nowym typie jest najlepszym argumentem za polimorfizmem.
- **Domknij `override` z lekcji 8.2 wprost.** Uczeń pisał to słowo, nie wiedząc, co znaczy; teraz wie i warto to nazwać.
- **Nie wprowadzaj `abstract`.** Uczeń zapyta, czy `Zwierze` powinno w ogóle istnieć samo („co to za zwierzę, które mówi kropki?") — **to jest pytanie otwierające lekcję 9.3.** Zanotuj i odłóż.
- **Nie wprowadzaj interfejsów.** Dwie wzmianki po jednym zdaniu wystarczą.
- **Nie tłumacz tablicy metod wirtualnych** ani mechanizmu pod spodem. „Decyzja zapada w czasie działania" wystarcza.
- **`new` przy metodzie pokaż tylko jako ostrzeżenie**, nie jako narzędzie. Uczeń nie ma powodu go używać.
