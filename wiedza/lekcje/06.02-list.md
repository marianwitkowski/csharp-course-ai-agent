# Lekcja 6.2 — `List<T>`

## Cel
Po lekcji uczeń:
- Tworzy `List<T>` i dokłada do niej elementy przez `Add`
- Wie, że `Count` to odpowiednik `Length` z tablicy — i czemu nazywa się inaczej
- Usuwa elementy (`Remove`, `RemoveAt`) i szuka ich (`Contains`, `IndexOf`)
- Wie, kiedy wybrać tablicę, a kiedy listę
- Rozumie, czemu nie wolno zmieniać listy w trakcie `foreach`

> **Ta lekcja odpowiada na pytanie z końca 6.1:** co zrobić, gdy nie wiesz z góry, ile elementów będziesz mieć.

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe — wróć do segregatora z 6.1:**
> „Segregator miał stałą liczbę przegródek. A lista zakupów na kartce — ile ma miejsc?"

**Co chcesz usłyszeć:** tyle, ile dopiszesz. Nie deklarujesz z góry.

**Drugie pytanie:**
> „Co możesz zrobić z listą zakupów, czego nie da się zrobić z segregatorem?"

**Co chcesz usłyszeć:** dopisać na końcu, skreślić pozycję, policzyć, ile zostało.

**Trzecie pytanie:**
> „A czego lista zakupów **nie** ma, a segregator ma?"

**Co chcesz usłyszeć:** numerów przegródek — choć w praktyce można je policzyć. To dobra intuicja: lista też ma indeksy, tylko nie są jej istotą.

## Krok 2 — Mostek (10 min)

**Mostek:**
> „Kartka, na którą dopisujesz i z której skreślasz, to w C# **lista**. Zapisuje się `List<string>` — nawiasy ostre mówią, **czego** to jest lista."

Uczeń tworzy `kurs/zadania/15-list.cs`:

```csharp
List<string> zakupy = new List<string>();

zakupy.Add("chleb");
zakupy.Add("mleko");
zakupy.Add("ser");

Console.WriteLine($"Pozycji: {zakupy.Count}");
Console.WriteLine(zakupy[0]);
Console.WriteLine(string.Join(", ", zakupy));
```
→ `Pozycji: 3`, `chleb`, `chleb, mleko, ser`

**Pytania:**
- „Ile miejsc miała lista w momencie tworzenia?" → zero. Rosła przy każdym `Add`.
- „Czym `Count` różni się od `Length` z tablicy?" → **niczym w znaczeniu**; to po prostu inna nazwa dla liczby elementów.
- „Czy indeksowanie działa tak samo?" → tak, `[0]` to pierwszy.

> **Czemu dwie różne nazwy?** Tablica ma **długość** ustaloną raz na zawsze, lista ma **liczbę** elementów, która się zmienia. Nazwy to odzwierciedlają. Praktycznie: przy tablicy `Length`, przy liście `Count`, obie bez nawiasów.

Teraz to, o co chodziło w 6.1:

```csharp
zakupy.Add("masło");
Console.WriteLine($"Pozycji: {zakupy.Count}");
```
→ `Pozycji: 4`

> „W lekcji 6.1 `Add` na tablicy dało `CS1061`. Tutaj po prostu działa."

## Krok 3 — Eksperyment (25 min)

### A. Usuwanie — dwa sposoby

```csharp
List<string> zakupy = new List<string>();
zakupy.Add("chleb");
zakupy.Add("mleko");
zakupy.Add("ser");

zakupy.Remove("mleko");
Console.WriteLine(string.Join(", ", zakupy));

zakupy.RemoveAt(0);
Console.WriteLine(string.Join(", ", zakupy));
```
→ `chleb, ser`, potem `ser`

> „Czym różnią się `Remove` i `RemoveAt`?"
→ `Remove` usuwa **po wartości**, `RemoveAt` **po numerze**.

> „Co się stanie z indeksami pozostałych elementów po usunięciu pierwszego?"
→ przesuwają się. Element, który był pod `[1]`, jest teraz pod `[0]`. **To źródło błędów przy usuwaniu w pętli** — wraca w kroku D.

Niech uczeń sprawdzi, co zwraca `Remove` na nieistniejącej pozycji:
```csharp
Console.WriteLine(zakupy.Remove("kawior"));
```
→ `False` — nie przewraca programu, tylko mówi, że nie było czego usuwać.

### B. Szukanie

```csharp
Console.WriteLine(zakupy.Contains("ser"));
Console.WriteLine(zakupy.IndexOf("ser"));
Console.WriteLine(zakupy.IndexOf("kawior"));
```
→ `True`, `0`, `-1`

> „`IndexOf` na nieistniejącym elemencie dał `-1`. Czemu nie zero?"
→ bo zero jest **prawidłowym** indeksem. Trzeba było wybrać wartość, która nie może być indeksem — i minus jeden nią jest.

> **To wzorzec, który zobaczysz w wielu miejscach:** „nie znalazłem" trzeba jakoś zakodować, a każda wartość z prawidłowego zakresu byłaby myląca.

### C. Wczytywanie, dopóki użytkownik nie skończy

To jest zastosowanie, dla którego lista naprawdę powstała:

```csharp
List<string> zakupy = new List<string>();

while (true)
{
    Console.Write("Dopisz pozycję (albo Enter, żeby skończyć): ");
    string pozycja = Console.ReadLine();

    if (pozycja == "")
    {
        break;
    }

    zakupy.Add(pozycja);
}

Console.WriteLine($"Lista ma {zakupy.Count} pozycji:");
foreach (string pozycja in zakupy)
{
    Console.WriteLine($"- {pozycja}");
}
```

> „Ile pozycji będzie miała ta lista? Skąd program to wie?"
→ nie wie z góry. **Dlatego tablica by się tu nie nadała.**

To jest cała różnica między 6.1 a 6.2 w jednym programie. `while (true)` z `break` uczeń zna z lekcji 5.3.

### D. Zmiana listy w trakcie `foreach` — wyjątek

```csharp
List<int> liczby = new List<int>();
liczby.Add(1);
liczby.Add(2);

foreach (int liczba in liczby)
{
    liczby.Add(liczba);
}
```
→ program przewraca się:
```
Unhandled exception. System.InvalidOperationException: Collection was modified; enumeration operation may not execute.
```

> „Przeczytaj: »kolekcja została zmieniona; przechodzenie nie może być kontynuowane«. Co się stało?"
→ `foreach` przechodzi po liście i zakłada, że lista się nie zmienia. Dokładanie w trakcie łamie tę umowę.

> „Zauważ, że gdyby C# na to pozwolił, pętla nigdy by się nie skończyła — każdy obieg dokładałby element."

**Jak zrobić to poprawnie?** Zbieraj do **drugiej** listy:
```csharp
List<int> podwojone = new List<int>();
foreach (int liczba in liczby)
{
    podwojone.Add(liczba * 2);
}
```

> „Albo użyj `for` idącego od końca — ale to sztuczka, nie zasada. Druga lista jest czytelniejsza."

### E. Krótszy zapis tworzenia

```csharp
List<string> dni = new List<string> { "pon", "wt", "śr" };
List<int> liczby = [1, 2, 3];
```
→ obie linie tworzą gotową listę.

> „Drugi zapis, w nawiasach kwadratowych, jest nowy (C# 12) i wygląda jak tablica z 6.1 — ale to lista. Zobaczysz oba."

**Nie ćwicz drugiego zapisu.** Uczeń ma go rozpoznać.

## Krok 4 — Pogłębienie (10 min)

**Tablica czy lista? Reguła praktyczna:**

| Sytuacja | Wybór |
| --- | --- |
| liczba elementów znana z góry i stała | tablica |
| dokładasz lub usuwasz w trakcie | lista |
| nie wiesz, ile ich będzie | lista |
| chcesz najprostszą rzecz do przejścia pętlą | obie równie dobre |

> „W praktyce w nowym kodzie częściej zobaczysz listę — bo rzadko wiadomo z góry, ile czegoś będzie. Tablice zostają tam, gdzie rozmiar jest naprawdę ustalony."

**Lista list — pokaż, nie ćwicz:**
```csharp
List<List<string>> grupy = new List<List<string>>();
```
> „Da się. Wygląda strasznie i na razie nie jest ci potrzebne — wspominam, żebyś się nie przestraszył, gdy to zobaczysz."

**`Clear` i `Insert`:**
```csharp
zakupy.Insert(0, "na początek");
zakupy.Clear();
Console.WriteLine(zakupy.Count);
```
→ `0`

> „`Insert` wstawia pod wskazany numer i przesuwa resztę. `Clear` czyści całą listę."

**Czego lista **nie** robi sama:**
> „Lista nie sortuje się sama i nie usuwa duplikatów. `zakupy.Sort()` posortuje ją, gdy poprosisz — ale to zmieni kolejność na stałe."

Pokaż `Sort()` jednym przykładem, bez rozwijania:
```csharp
List<int> liczby = [3, 1, 2];
liczby.Sort();
Console.WriteLine(string.Join(" ", liczby));
```
→ `1 2 3`

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „`List<T>`". Propozycje:

- 🔥 **Rozgrzewka** (`15-list-a.cs`): utwórz pustą listę tekstów. Dopisz do niej trzy ulubione potrawy. Wypisz je z numerami (`1. …`, `2. …`) oraz podaj, ile ich jest.
- ⭐ **Główne** (`15-list-b.cs`): lista zakupów. W pętli pytaj o pozycje, aż użytkownik naciśnie sam Enter. Potem zapytaj o pozycję do usunięcia i usuń ją — jeśli jej nie ma, napisz `Nie ma takiej pozycji` (skorzystaj z tego, co zwraca `Remove`). Na końcu wypisz listę z numerami i liczbę pozycji.
- ⚡ **Gwiazdka** (`15-list-c.cs`): usuń duplikaty **bez** korzystania z gotowych narzędzi. Wczytaj słowa w pętli (Enter kończy). Zbuduj **drugą** listę, do której trafi każde słowo tylko raz — sprawdzając przez `Contains`, czy już tam jest. Wypisz obie listy i podaj, ile duplikatów odrzuciłeś.

Gwiazdka celowo każe zbierać do drugiej listy — czyli robi wprost to, czego krok 3.D zabronił robić w miejscu.

## Pułapki

- **`Count` kontra `Length`** — lista ma `Count`, tablica `Length`. Obie bez nawiasów. Pomylenie daje `CS1061`.
- **Zmiana listy w trakcie `foreach`** → `InvalidOperationException`. Zbieraj do drugiej listy.
- **Usuwanie w pętli po indeksach** — po `RemoveAt(i)` elementy się przesuwają i pętla przeskakuje jeden. Objaw: część elementów zostaje mimo usuwania.
- **`IndexOf` zwraca `-1`, nie zero** — sprawdzaj `!= -1`, nie `> 0` (bo zero jest prawidłowym indeksem).
- **`Remove` zwraca `bool`** — ignorowanie tego wyniku ukrywa fakt, że nie było czego usuwać.
- **Tworzenie listy bez `new`** — `List<string> l;` samo nie tworzy listy. Próba `l.Add(...)` da `CS0165` (zmienna bez wartości, jak w 2.1).
- **`List` bez typu w nawiasach** — `List zakupy` nie istnieje; trzeba powiedzieć, czego to lista.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Sekcja `[moduł 6]`. Trzy rzeczy:

- **`ArrayList`** ze starych poradników to poprzednik `List<T>` bez kontroli typu — wrzucało się do niego cokolwiek, a przy wyjmowaniu trzeba było zgadywać. Zastąpiony dwadzieścia lat temu.
- **`new List<string>()`** można dziś skrócić do `new()`, gdy typ widać po lewej: `List<string> l = new();`
- **Wyrażenia kolekcji `[1, 2, 3]`** to C# 12. Wprowadzaj **po** klasycznym zapisie — uczeń musi wiedzieć, że tworzy listę, zanim skróci zapis.

## Notatki tutora

- **Krok 2 musi odwołać się do `CS1061` z lekcji 6.1.** Uczeń pamięta, że `Add` nie zadziałało; tutaj działa. Bez tego zestawienia lista to „kolejny typ do zapamiętania".
- **Krok 3.C to najważniejszy program lekcji.** Pokazuje sytuację, w której tablica jest bezużyteczna. Nie skracaj.
- **Nie wprowadzaj `Dictionary`.** Uczeń zapyta („a jak szukać po nazwie, a nie po numerze?") — lekcja 6.3, następna.
- **Nie tłumacz, czym jest `<T>`.** „Nawiasy ostre mówią, czego to lista" wystarcza do końca kursu. Typy generyczne własne są poza kursem (patrz `INDEX.md`).
- **Nie rozwijaj `Sort`.** Jedno pokazanie. Sortowanie po własnym kryterium to moduł 10 (`IComparable`) i 13 (LINQ).
- **Lista list — pokaż i idź dalej.** Uczeń zobaczy to w internecie i lepiej, żeby nie wyglądało na czarną magię.
- Jeśli uczeń zaczyna używać listy wszędzie, także tam, gdzie tablica wystarczy — nie poprawiaj. To normalna faza i praktycznie nieszkodliwa.
