# Lekcja 15.2 — `Task.WhenAll`

> **Druga i ostatnia lekcja dodatku.** W 15.1 uczeń zobaczył, że `await` nie przyspiesza. Dziś zobaczy, kiedy **przyspiesza** — gdy kilka operacji czeka naraz — i jaka jest tego cena.

## Cel
Po lekcji uczeń:
- Uruchamia kilka operacji asynchronicznych **jednocześnie** i czeka na wszystkie przez `Task.WhenAll`
- Widzi na zegarze różnicę między „po kolei" a „naraz" i umie powiedzieć, skąd się bierze
- Odbiera wyniki z `Task.WhenAll` w tej samej kolejności, w jakiej podał zadania
- Wie, co się dzieje z wyjątkiem, gdy jedno z zadań się nie uda
- Umie zbudować tablicę zadań z listy plików przez `Select`

## Krok 1 — Zakotwiczenie (4 min)

**Pytanie wejściowe:**
> „Pralnia samoobsługowa, trzy pralki, trzy kosze prania. Wrzucasz pierwszy kosz, czekasz czterdzieści minut, potem drugi kosz, czekasz, potem trzeci — czy wrzucasz trzy naraz?"

**Co chcesz usłyszeć:** trzy naraz; czekam czterdzieści minut zamiast dwóch godzin.

**Drugie pytanie:**
> „A gdyby pralka była jedna?"

**Co chcesz usłyszeć:** wtedy i tak dwie godziny. Równoległość pomaga, gdy **jest na czym** czekać równolegle.

## Krok 2 — Mostek (10 min)

Uczeń wraca do ćwiczenia ⭐ z 15.1 — trzy pliki po kolei, każdy z `Task.Delay(500)`:

```csharp
var zegar = System.Diagnostics.Stopwatch.StartNew();
int a = await PoliczLinie("a.txt");
int b = await PoliczLinie("b.txt");
int c = await PoliczLinie("c.txt");
Console.WriteLine($"{a + b + c} linii, {zegar.ElapsedMilliseconds} ms");

async Task<int> PoliczLinie(string plik)
{
    await Task.Delay(500);
    string[] linie = await File.ReadAllLinesAsync(plik);
    return linie.Length;
}
```
→ `6 linii, 1524 ms` (dla plików z 3, 2 i 1 linią; u ciebie liczba linii wg twoich plików, czas około 1500 ms).

> „Trzy razy po pięćset. Gdzie w tym kodzie jest »wrzuć pierwszy kosz, czekaj, wrzuć drugi«?"
→ w każdym `await` osobno: drugie `PoliczLinie` **zaczyna się** dopiero, gdy pierwsze skończy.

**Mostek:**
> „Żeby wrzucić trzy kosze naraz, trzeba najpierw **uruchomić** trzy operacje, a dopiero potem czekać — na wszystkie. Uruchomienie to wywołanie metody **bez** `await`. Czekanie na wszystkie to `Task.WhenAll`."

```csharp
var zegar = System.Diagnostics.Stopwatch.StartNew();
Task<int> a = PoliczLinie("a.txt");
Task<int> b = PoliczLinie("b.txt");
Task<int> c = PoliczLinie("c.txt");
int[] wyniki = await Task.WhenAll(a, b, c);
Console.WriteLine($"{wyniki.Sum()} linii, {zegar.ElapsedMilliseconds} ms");
```
→ `6 linii, 525 ms`

> „Ta sama metoda, te same pliki. Skąd trzy razy krócej?"
→ trzy `Task.Delay(500)` **biegły w tym samym czasie**. Kelner z 15.1 zaniósł trzy zamówienia do kuchni od razu, zamiast czekać na pierwsze danie przed zaniesieniem drugiego.

> „W 15.1 `PoliczLinie(...)` bez `await` było błędem (`CS4014`). Tu jest celowe. Jaka różnica?"
→ tam **wynik był wyrzucany**; tu obietnica jest **zapisana do zmiennej** i `await` przychodzi później, przez `WhenAll`. Kompilator to rozróżnia — przypisanie do `Task<int>` nie daje ostrzeżenia.

Nazwij: **`Task.WhenAll`** — jedna obietnica „wszystkie skończone", która oddaje tablicę wyników.

## Krok 3 — Eksperyment (18 min)

### A. Sama różnica czasu, bez plików

```csharp
var zegar = System.Diagnostics.Stopwatch.StartNew();
Task a = Task.Delay(1000);
Task b = Task.Delay(1000);
Task c = Task.Delay(1000);
await Task.WhenAll(a, b, c);
Console.WriteLine($"{zegar.ElapsedMilliseconds} ms");
```
→ około `1005 ms` — a w 15.1 trzy `await Task.Delay(1000)` po kolei dały około `3012 ms`.

> „Ile czekał program: sekundę czy trzy?"
→ sekundę. Trzy czekania **nałożyły się** na siebie.

### B. Kolejność wyników

W przykładzie z kroku 2 pliki miały 3, 2 i 1 linię. Niech uczeń wypisze tablicę:
```csharp
Console.WriteLine(string.Join(", ", wyniki));
```
→ `3, 2, 1`

> „Zadania biegły naraz i mogły skończyć się w dowolnej kolejności. Skąd wyniki w kolejności `a, b, c`?"
→ `WhenAll` układa wyniki **w kolejności podanych zadań**, nie w kolejności kończenia. `wyniki[0]` zawsze należy do `a`.

### C. Jedno zadanie się nie udaje

```csharp
Task<int> a = PoliczLinie("a.txt");
Task<int> z = PoliczLinie("nie-ma.txt");

try
{
    int[] wyniki = await Task.WhenAll(a, z);
}
catch (FileNotFoundException e)
{
    Console.WriteLine("Brak pliku: " + Path.GetFileName(e.FileName));
}

Console.WriteLine("a skończone? " + a.IsCompletedSuccessfully + ", wynik " + a.Result);
```
→
```
Brak pliku: nie-ma.txt
a skończone? True, wynik 3
```

> „Jedno z dwóch zadań rzuciło wyjątek. Co z drugim?"
→ **dokończyło się normalnie** — `a` ma wynik `3`. `WhenAll` czeka na wszystkie, a potem rzuca wyjątek tego, które padło. Wyniki udanych zadań są w ich zmiennych (`a.Result` — tu bezpieczne, bo `WhenAll` już zaczekał).

> „Gdzie ląduje wyjątek?"
→ w `await Task.WhenAll(...)`, jak każdy wyjątek przez `await` (15.1, krok E). Zwykły `catch`.

### D. Tablica zadań z listy plików

Trzy zmienne `a`, `b`, `c` nie skalują się do trzydziestu plików. Z lekcji 12.2 i 13.1:

```csharp
string[] pliki = Directory.GetFiles(".", "*.txt");
Task<int>[] zadania = pliki.Select(p => PoliczLinie(p)).ToArray();
int[] wyniki = await Task.WhenAll(zadania);

for (int i = 0; i < pliki.Length; i++)
{
    Console.WriteLine($"{Path.GetFileName(pliki[i])}: {wyniki[i]}");
}
```
→ po jednej linii na plik, np. `c.txt: 1`, `b.txt: 2`, `a.txt: 3` — kolejność plików taka, jak zwrócił `GetFiles`, a wyniki **dopasowane indeksem** (krok B).

> „Ile operacji biegnie naraz, gdy w katalogu jest trzydzieści plików?"
→ trzydzieści. Dla plików na dysku to w porządku; dla zapytań do serwera — patrz krok 4.

## Krok 4 — Pogłębienie (6 min)

**Kiedy `WhenAll` nic nie daje**

| Sytuacja | Naraz czy po kolei? |
| --- | --- |
| trzy niezależne pliki / trzy zapytania | naraz — `WhenAll` |
| drugi krok potrzebuje wyniku pierwszego | po kolei — nie ma jak inaczej |
| jedna operacja | `await`, bez `WhenAll` — nie ma co nakładać |
| obliczenia, które **liczą**, a nie czekają (pętla po milionie liczb) | `WhenAll` nie pomoże — nie ma czekania do nałożenia. To temat wielowątkowości, poza kursem |

> „`WhenAll` skraca **czekanie**, nie pracę. Kelner z trzema zamówieniami naraz nie ugotuje szybciej."

**Cena: wszystko naraz to też wszystko naraz**

> „Trzydzieści plików naraz — dobrze. Trzy tysiące zapytań do cudzego serwera naraz — serwer cię odetnie. W prawdziwych programach ogranicza się liczbę równoczesnych operacji. Jak — to poza kursem; wystarczy, że wiesz, iż `WhenAll` na tysiącu zadań to decyzja, nie odruch."

**Trzy reguły z 15.1 plus jedna**

| Reguła | Skąd |
| --- | --- |
| `async` w nagłówku, `await` przy wywołaniu, `Async` w nazwie | 15.1 |
| operacje niezależne: **uruchom wszystkie, potem `await Task.WhenAll`** | 15.2 |

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „kilka operacji naraz". Propozycje:

- 🔥 **Rozgrzewka** (`42-whenall-a.cs`): trzy `Task.Delay` po `700 ms` — najpierw po kolei z `await`, potem przez `WhenAll`. Wypisz oba czasy. Powiedz mi, o ile się różnią i czy to zgadza się z przewidywaniem.
- ⭐ **Główne** (`42-whenall-b.cs`): katalog z co najmniej pięcioma plikami `.txt`. Metoda `PoliczLinieAsync` z `Task.Delay(300)` na początku. Wersja **po kolei** i wersja **`WhenAll`** w jednym programie, obie mierzone `Stopwatch`; wypisz tabelę `plik: linie` i dwa czasy. Jeden z plików **usuń w trakcie** (między uruchomieniami) i pokaż, że brak pliku daje komunikat, a pozostałe wyniki nadal się wypisują.
- ⚡ **Gwiazdka** (w `kurs/projekt/`): `Magazyn` z 15.1 ⚡ ma `WczytajAsync()`. Dopisz `WczytajWieleAsync(string[] sciezki)` zwracającą `Task<List<Zadanie>>` — wczytuje kilka plików JSON **naraz** i skleja listy. Test asynchroniczny: dwa pliki tymczasowe, po jednym zadaniu w każdym, wynik ma mieć dwa zadania. Bonus: co się stanie, gdy jeden z plików nie istnieje — zdecyduj, czy metoda ma rzucić, czy pominąć plik, i napisz test na tę decyzję.

Gwiazdka jest pierwszym miejscem, gdzie uczeń **projektuje** zachowanie asynchroniczne przy błędzie zamiast je przyjmować — i zapisuje decyzję testem.

## Pułapki

- **`await` przy każdym wywołaniu „na wszelki wypadek"** — wtedy operacje idą po kolei i `WhenAll` nie ma czego nakładać. Uruchom bez `await`, zapisz `Task`, czekaj raz.
- **Wynik z `WhenAll` czytany po kolejności kończenia** — kolejność jest **podanych zadań** (krok B).
- **Wyjątek z jednego zadania „gubi" pozostałe** — nie gubi; udane zadania mają wyniki w swoich zmiennych (krok C). Ale `wyniki` z `WhenAll` nie powstaną — trzeba sięgnąć do `a.Result`.
- **`.Result` przed `await`** — blokuje (15.1). Po `await Task.WhenAll` jest bezpieczne, bo zadanie już skończone.
- **`WhenAll` na tysiącach zadań do sieci** — bez ograniczenia równoległości. Poza kursem, ale świadomie.
- **`WhenAll` na obliczeniach** — nie skraca pracy, tylko czekanie.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Sekcja `[moduł 15]`. W starszych materiałach to samo robiło się przez `Task.WaitAll(a, b, c)` — **blokuje** wątek jak `.Result`. Dziś `await Task.WhenAll`. Nazwy różnią się jedną literą; zachowanie — całkowicie. Jeśli w poradniku jest `WaitAll`, to poradnik sprzed `async`/`await`.

## Notatki tutora

- **Krok 2 musi zacząć się od ćwiczenia ⭐ z 15.1** — uczeń ma **własny** czas „po kolei" do porównania. Bez tego `525 ms` nic nie znaczy.
- **Nie wprowadzaj `Task.WhenAny`, `Parallel.ForEachAsync`, `SemaphoreSlim`, `CancellationToken`.** Ograniczenie równoległości jest wspomniane w kroku 4 jako istniejący problem, bez rozwiązania.
- **Nie wprowadzaj `HttpClient`.** Kurs nie ma sieci; `Task.Delay` udaje ją wystarczająco dobrze do zobaczenia różnicy w czasie.
- **Krok C bywa zaskoczeniem w drugą stronę** — uczeń spodziewa się, że wyjątek „przerwie wszystko". Pokaż `a.Result == 3` i nazwij: `WhenAll` czeka na wszystkie, dopiero potem rzuca.
- Jeśli uczeń pyta, czy `Select` w kroku D uruchamia zadania — tak, w momencie `ToArray()`; bez `ToArray()` LINQ jest leniwy i zadania wystartowałyby dopiero przy przeglądaniu. Jedno zdanie, nie rozwijaj.
- **To koniec dodatku.** Uczeń ma podstawy potrzebne w ASP.NET Core: `async Task<T>`, `await`, `WhenAll`, wyjątki przez `await`. Powiedz to wprost i odeślij do planu z 14.7.
