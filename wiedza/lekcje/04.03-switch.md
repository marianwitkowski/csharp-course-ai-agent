# Lekcja 4.3 — `switch`

## Cel
Po lekcji uczeń:
- Zamienia długi łańcuch `else if` na `switch`, gdy wszystkie warunki pytają o **tę samą** zmienną
- Pisze `switch` jako instrukcję: `case`, `break`, `default`
- Pisze `switch` jako wyrażenie (`=>`), gdy chodzi o wybór wartości
- Wie, czemu `enum` i `switch` chodzą w parze — domyka lekcję 2.2
- Rozpoznaje `CS0163` (brak `break`) i `CS8509` (niepełne wyrażenie `switch`)

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Automat z napojami. Wciskasz przycisk 1 — dostajesz colę, 2 — wodę, 3 — sok. Jak byś opisał tę regułę komuś, kto ma automat obsłużyć ręcznie?"

**Co chcesz usłyszeć:** lista „przycisk → napój". Zwróć uwagę, czy uczeń mówi „jeśli 1, to cola; jeśli 2, to woda" — czy raczej wylicza pary.

**Drugie pytanie:**
> „Zauważ: wszystkie te reguły pytają o **to samo** — o numer przycisku. Czym to się różni od twojej reguły z parasolem, gdzie sprawdzałeś raz deszcz, raz temperaturę?"

**Co chcesz usłyszeć:** tam były różne pytania, tu jedno pytanie i wiele odpowiedzi.

**To jest cała lekcja w jednym zdaniu.** `switch` jest wtedy i tylko wtedy, gdy wszystkie gałęzie pytają o tę samą wartość.

## Krok 2 — Mostek (10 min)

Uczeń pisze **najpierw wersję, którą już umie** — łańcuch z lekcji 4.1:

```csharp
int przycisk = 2;

if (przycisk == 1) { Console.WriteLine("Cola"); }
else if (przycisk == 2) { Console.WriteLine("Woda"); }
else if (przycisk == 3) { Console.WriteLine("Sok"); }
else { Console.WriteLine("Nie ma takiego przycisku"); }
```

> „Policz, ile razy występuje słowo `przycisk`. Cztery razy to samo pytanie."

**Mostek:**
> „Gdy wszystkie gałęzie pytają o tę samą zmienną, C# pozwala zapytać **raz**. Ta konstrukcja nazywa się `switch`."

Uczeń tworzy `kurs/zadania/10-switch.cs`:

```csharp
int przycisk = 2;

switch (przycisk)
{
    case 1:
        Console.WriteLine("Cola");
        break;
    case 2:
        Console.WriteLine("Woda");
        break;
    case 3:
        Console.WriteLine("Sok");
        break;
    default:
        Console.WriteLine("Nie ma takiego przycisku");
        break;
}
```
→ `Woda`

**Pytania:**
- „Gdzie podziało się powtarzane `przycisk ==`?"
- „Co odpowiada gałęzi `else`?" → `default`
- „Co robi `break`?" → kończy `switch`; bez niego kompilator protestuje (krok 3.B)

> **`switch` nie jest »lepszy« od `else if`.** Jest lepszy **tylko** w tej jednej sytuacji: jedno pytanie, wiele odpowiedzi. Do warunków typu `wiek >= 18 && maBilet` nadal używasz `if`.

## Krok 3 — Eksperyment (20 min)

### A. `default` i jego brak

Uczeń zmienia `przycisk` na `9`.
→ `Nie ma takiego przycisku`

Potem **usuwa całą gałąź `default`** i uruchamia ponownie.
→ nie wypisuje się nic; program idzie dalej bez słowa.

> „To samo zachowanie co przy `if` bez `else` z lekcji 4.1. Czy brak reakcji jest tu tym, czego chcesz?"

### B. Zapomniany `break`

```csharp
switch (przycisk)
{
    case 1:
        Console.WriteLine("Cola");
    case 2:
        Console.WriteLine("Woda");
        break;
}
```
→ `CS0163: Control cannot fall through from one case label ('case 1:') to another`

> „Przeczytaj komunikat: »sterowanie nie może przelecieć z jednej etykiety do drugiej«. C# wymaga, żeby każda gałąź jawnie się kończyła."

To dobra wiadomość: **kompilator nie pozwoli ci zapomnieć `break`.** Zapomniany `break` jest w innych miejscach klasycznym źródłem błędów; tutaj jest po prostu błędem kompilacji.

### C. Kilka etykiet, jedna reakcja

```csharp
switch (przycisk)
{
    case 1:
    case 2:
        Console.WriteLine("Napój zimny");
        break;
    case 3:
        Console.WriteLine("Napój ciepły");
        break;
}
```
> „Dwie etykiety pod rząd, bez kodu między nimi. Co to znaczy?"
→ „dla 1 **albo** 2 zrób to samo". To jedyny przypadek, w którym „przelecenie" jest dozwolone — bo nie ma czego przelecieć.

### D. `switch` na tekście

```csharp
Console.Write("Podaj dzień skrótem (pon/wt/sr): ");
string dzien = Console.ReadLine();

switch (dzien)
{
    case "pon":
        Console.WriteLine("Poniedziałek");
        break;
    case "wt":
        Console.WriteLine("Wtorek");
        break;
    default:
        Console.WriteLine("Nie rozpoznaję");
        break;
}
```
> „Wpisz `pon`, potem `PON`. Co się stanie za drugim razem?"
→ `Nie rozpoznaję`. Wielkość liter ma znaczenie, tak jak przy `==` w lekcji 4.1.

### E. `switch` jako wyrażenie — krótsza forma

Gdy wszystkie gałęzie robią **to samo, tylko z inną wartością** — jak wyżej, gdzie każda tylko wypisuje tekst — da się to zapisać zwięźlej:

```csharp
string napoj = przycisk switch
{
    1 => "Cola",
    2 => "Woda",
    3 => "Sok",
    _ => "Nie ma takiego przycisku",
};

Console.WriteLine(napoj);
```

> „Porównaj z wersją z kroku 2. Co zniknęło?"
→ `case`, `break`, klamry przy gałęziach, powtarzane `Console.WriteLine`.

Zwróć uwagę na trzy rzeczy:
- nazwa zmiennej stoi **przed** słowem `switch`, nie w nawiasie
- `=>` zamiast dwukropka
- `_` zamiast `default`

> „To nie jest inny `switch` — to ten sam pomysł zapisany jako **wyrażenie**, czyli coś, co **daje wartość**. Tak jak `?:` z lekcji 4.2, tylko dla wielu przypadków zamiast dwóch."

### F. Niepełne wyrażenie `switch`

Uczeń usuwa gałąź `_`:
```csharp
string napoj = przycisk switch
{
    1 => "Cola",
    2 => "Woda",
};
```
→ buduje się, ale z ostrzeżeniem:
```
warning CS8509: The switch expression does not handle all possible values of its input type (it is not exhaustive). For example, the pattern '0' is not covered.
```

Uczeń ustawia `przycisk = 9` i uruchamia:
```
Unhandled exception. System.Runtime.CompilerServices.SwitchExpressionException: Non-exhaustive switch expression failed to match its input.
```

> „Trzecie ostrzeżenie w tym kursie — i znowu takie, które oznacza prawdziwy błąd. Pamiętasz `CS8600` z 3.2 i `CS0642` z 4.1?"

**Zasada:** w wyrażeniu `switch` **zawsze pisz `_`**. Instrukcja `switch` bez `default` po prostu nic nie robi; wyrażenie bez `_` przewraca program, bo musi zwrócić jakąś wartość, a nie ma jakiej.

## Krok 4 — Pogłębienie (10 min)

**`switch` i `enum` — para, na którą czekaliśmy od lekcji 2.2**

```csharp
DzienTygodnia dzis = DzienTygodnia.Sobota;

string plan = dzis switch
{
    DzienTygodnia.Sobota => "Wolne",
    DzienTygodnia.Niedziela => "Wolne",
    _ => "Praca",
};

Console.WriteLine(plan);

enum DzienTygodnia
{
    Poniedzialek, Wtorek, Sroda, Czwartek, Piatek, Sobota, Niedziela,
}
```

> „W lekcji 2.2 mówiliśmy, że `enum` chroni przed literówką. Spróbuj napisać `DzienTygodnia.Sobtoa` i zobacz, co powie kompilator."
→ `CS0117`, ten sam co w 2.2.

> „A gdyby dzień był zwykłym tekstem? `case \"Sobtoa\"` przeszłoby bez słowa i gałąź po prostu nigdy by nie zadziałała."

**To jest domknięcie obietnicy z lekcji 2.2.** Enum sam w sobie wyglądał na formalność; dopiero w połączeniu z `switch` widać, co daje.

> **Uwaga o kolejności w pliku:** `enum` nadal musi być na końcu, po instrukcjach (`CS8803` z lekcji 2.2).

**Kiedy `switch`, a kiedy `if`?**

| Sytuacja | Zapis |
| --- | --- |
| jedno pytanie, wiele konkretnych odpowiedzi | `switch` |
| różne pytania w każdej gałęzi | `if / else if` |
| warunek z `&&`, `||`, zakresem (`wiek >= 18`) | `if` — w tym kursie |
| wybór **wartości**, nie czynności | wyrażenie `switch` albo `?:` |

> „W tym kursie `switch` służy do porównywania na równość: jedna wartość, wiele konkretnych przypadków. »Wiek powyżej 18« to zakres — do tego używasz `if`."

> **Uczciwie:** nowoczesny C# **potrafi** zapisać zakres w `switch` (`case >= 18:`) i taki kod się skompiluje. To dopasowywanie wzorców — mechanizm, którego kurs świadomie nie wprowadza, bo mnoży składnię na to samo. Jeśli uczeń trafi na to w internecie: „da się, to inny sposób zapisu; my zostajemy przy `if`". Nie rozwijaj.

**Instrukcja czy wyrażenie — którą wybrać?**

| Gałęzie… | Forma |
| --- | --- |
| tylko wybierają wartość | wyrażenie (`=>`) |
| robią różne rzeczy, po kilka linii | instrukcja (`case` / `break`) |

Obie są poprawne i obie spotkasz w cudzym kodzie.

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „`switch`". Propozycje:

- 🔥 **Rozgrzewka** (`10-switch-a.cs`): zapytaj o numer miesiąca (1–12). Instrukcją `switch` wypisz porę roku: 12, 1, 2 → zima; 3, 4, 5 → wiosna; 6, 7, 8 → lato; 9, 10, 11 → jesień. Dla innej liczby — `Nie ma takiego miesiąca`. Wykorzystaj etykiety pod rząd z kroku 3.C.
- ⭐ **Główne** (`10-switch-b.cs`): przepisz swoje ćwiczenie z ocenami z lekcji 4.1 (`08-if-b.cs`) na **wyrażenie** `switch`. Porównaj oba pliki i powiedz mi, o ile linii krótsza jest nowa wersja i czy czyta się ją łatwiej.
- ⚡ **Gwiazdka** (`10-switch-c.cs`): prosty kalkulator. Zapytaj o dwie liczby i o działanie (`+`, `-`, `*`, `/`) wczytane jako tekst. Wynik policz **wyrażeniem** `switch`. Zadbaj o dwie rzeczy: dzielenie przez zero nie może przewrócić programu, a nieznane działanie ma dać czytelny komunikat, nie wyjątek.

Gwiazdka łączy `switch`, `TryParse` z 3.2, `if` z 4.1 i `&&` z 4.2 — plus każe pomyśleć o dwóch przypadkach brzegowych naraz. To pierwsze ćwiczenie, w którym uczeń składa cały moduł.

## Pułapki

- **Brak `break`** → `CS0163`. Kompilator ratuje; nie da się tego przeoczyć.
- **Brak `_` w wyrażeniu `switch`** → ostrzeżenie `CS8509` przy budowaniu i `SwitchExpressionException` przy działaniu. Ostrzeżenie łatwo przeoczyć, bo program się buduje.
- **Brak `default` w instrukcji `switch`** — kompilator milczy, program nic nie robi. Częstsze i cichsze niż powyższe.
- **`switch` do zakresów** — `case wiek >= 18:` nie zadziała (nie powtarza się nazwy zmiennej). Samo `case >= 18:` **działa**, ale to dopasowywanie wzorców, którego kurs nie wprowadza. Jeśli uczeń to napisze, bo znalazł w sieci — nie jest to błąd, tylko materiał spoza kursu. W ćwiczeniach zostajemy przy `if`.
- **Wielkość liter przy `switch` na tekście** — `"PON"` nie trafi w `case "pon"`.
- **Przecinek po ostatniej gałęzi wyrażenia** — `_ => "..."`**,** jest dozwolony i wygodny; nie poprawiaj ucznia w żadną stronę.
- **Mylenie dwóch form** — `=>` w instrukcji albo `break` w wyrażeniu. Objaw: komunikat o nieoczekiwanym tokenie. Wróć do kroku 3.E i policz różnice.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Sekcja `[moduł 4]`. **Wyrażenie `switch` (`=>`) to C# 8** — starsze materiały znają wyłącznie instrukcję z `case` i `break`.

Kolejność w tej lekcji jest celowa: **najpierw instrukcja, potem wyrażenie.** Uczeń musi rozumieć `case` i `break`, bo spotka je w każdym starszym kodzie; wyrażenie jest wtedy widoczne jako skrót, a nie jako osobna magia.

Czego **nie** wprowadzamy: dopasowywania wzorców w `switch` (`case > 18:`, `case Kot k:`, `when`). To rozszerzenia z C# 7–9, bardzo wygodne dla kogoś, kto już czyta C#, i zupełnie nieczytelne dla początkującego. Patrz `INDEX.md`.

## Notatki tutora

- **Krok 2 musi zacząć się od `else if`**, którego uczeń już używa. `switch` pokazany od zera wygląda na nową składnię do zapamiętania; pokazany jako **skrót powtarzanego pytania** ma powód.
- **Krok 4 (enum) domyka lekcję 2.2.** W tamtej lekcji obiecałem uczniowi, że `enum` wróci przy `switch`. Odwołaj się do tego wprost — uczeń pamięta obietnice.
- **Nie wprowadzaj dopasowywania wzorców.** Uczeń zapyta „a czy w `case` może być warunek?" — odpowiedź: „da się, poznasz kiedyś, na razie do warunków jest `if`". Nazwa i numer, dalej.
- **Nie rozstrzygaj, która forma jest »lepsza«.** Obie są używane. Tabela w kroku 4 wystarczy.
- **Uczeń będzie chciał pętli** przy kalkulatorze z gwiazdki („a jak policzyć jeszcze raz?"). Moduł 5.
- Jeśli uczeń przepisuje ćwiczenie ⭐ i wychodzi mu dłużej niż `else if` — sprawdź, czy nie użył instrukcji zamiast wyrażenia. To najczęstszy powód, dla którego `switch` „nie skraca".
