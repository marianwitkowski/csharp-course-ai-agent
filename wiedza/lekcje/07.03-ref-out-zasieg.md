# Lekcja 7.3 — `ref`, `out` i zasięg zmiennych

## Cel
Po lekcji uczeń:
- Wie, że metoda dostaje **kopię** liczby, a nie samą zmienną
- Rozumie, czemu tablica przekazana do metody **zmienia się naprawdę**
- Używa `out`, żeby oddać z metody więcej niż jedną wartość — i wreszcie rozumie `TryParse`
- Zna `ref` i wie, czemu używa się go rzadko
- Wie, gdzie zmienna „żyje" i kiedy przestaje istnieć

> **Ta lekcja domyka `out` z lekcji 2.3.** Uczeń pisze `int.TryParse(tekst, out int wynik)` od siedmiu lekcji i za każdym razem słyszał: „to sposób, żeby metoda oddała dwie rzeczy naraz, wyjaśnimy w 7.3".

## Krok 1 — Zakotwiczenie (5-8 min)

**Pytanie wejściowe:**
> „Dajesz koledze **kserokopię** swojej umowy. On coś na niej skreśla i dopisuje. Czy zmieniła się twoja umowa?"

**Co chcesz usłyszeć:** nie — on ma swoją kopię.

**Drugie pytanie:**
> „A teraz dajesz mu **klucze do swojego mieszkania**. On przestawia meble. Czy zmieniło się twoje mieszkanie?"

**Co chcesz usłyszeć:** tak — bo dostał dostęp do tego samego mieszkania, nie do jego kopii.

**To jest cała lekcja.** Niektóre rzeczy przekazuje się jak kserokopię, inne jak klucze — nie nazywaj tego jeszcze.

**Trzecie pytanie:**
> „Prosisz kogoś: »sprawdź, czy w skrzynce jest list, i jeśli jest, przynieś go«. Ile rzeczy ta osoba ci oddaje?"

**Co chcesz usłyszeć:** dwie — odpowiedź „tak/nie" **i** ewentualny list. Zapamiętaj; to jest `TryParse`.

## Krok 2 — Mostek (10 min)

**Mostek:**
> „Gdy przekazujesz metodzie liczbę, metoda dostaje **kopię**. Cokolwiek z nią zrobi, twoja zmienna zostaje nietknięta."

Uczeń tworzy `kurs/zadania/20-ref-out.cs`:

```csharp
void Zwieksz(int x)
{
    x = x + 1;
    Console.WriteLine($"wewnątrz metody: {x}");
}

int a = 5;
Zwieksz(a);
Console.WriteLine($"po metodzie: {a}");
```
→
```
wewnątrz metody: 6
po metodzie: 5
```

**Pytania:**
- „Metoda zwiększyła `x` do sześciu. Czemu `a` nadal ma pięć?"
- „Co dokładnie dostała metoda: zmienną `a` czy jej wartość?"

Nazwij: **przekazywanie przez wartość**. To jest kserokopia z kroku 1 i **domyślne zachowanie** dla liczb, `bool` i innych typów prostych z lekcji 2.1.

## Krok 3 — Eksperyment (25 min)

### A. Tablica zachowuje się inaczej

```csharp
void ZmienPierwszy(int[] tablica)
{
    tablica[0] = 99;
}

int[] liczby = { 1, 2, 3 };
ZmienPierwszy(liczby);
Console.WriteLine(liczby[0]);
```
→ `99`

> „Zgadnij, zanim uruchomisz: będzie `1` czy `99`?"

Większość uczniów obstawia `1`, po tym co widzieli w kroku 2.

> „Czemu tutaj zmiana przetrwała, a przy liczbie nie?"

Wyjaśnienie **jednym zdaniem**, bez teorii:
> „Zmienna `liczby` nie trzyma samej tablicy, tylko **wskazanie, gdzie ona leży**. Metoda dostała kopię tego wskazania — ale wskazuje ono na tę samą tablicę. To są klucze do mieszkania, nie kserokopia."

To samo dotyczy list i słowników z modułu 6.

> **Praktyczny wniosek:** metoda, która dostaje tablicę albo listę, **może ją zmienić**. Czasem tego chcesz, czasem to niespodzianka. Dobra nazwa metody rozstrzyga: `Posortuj(lista)` zapowiada zmianę, `PoliczSume(lista)` — nie.

### B. `out` — oddaj więcej niż jedną rzecz

Wróć do listu ze skrzynki z kroku 1:

```csharp
void PodzielZReszta(int a, int b, out int wynik, out int reszta)
{
    wynik = a / b;
    reszta = a % b;
}

PodzielZReszta(17, 5, out int calosc, out int r);
Console.WriteLine($"{calosc} reszty {r}");
```
→ `3 reszty 2`

> „Ile wartości oddała ta metoda? A ile może oddać przez `return`?"
→ dwie kontra jedną. **`out` jest sposobem na oddanie dodatkowych wartości.**

**Dwie zasady `out`:**
1. Metoda **musi** przypisać każdy parametr `out` — inaczej `CS0177`
2. Przy wywołaniu **musisz** napisać `out`, tak jak przy definicji

### C. Teraz `TryParse` przestaje być magią

```csharp
bool ok = int.TryParse("42", out int liczba);
Console.WriteLine($"{ok}, {liczba}");
```

> „Popatrz na tę linię jeszcze raz, po tym, co przed chwilą napisałeś. Co zwraca `TryParse` przez `return`, a co przez `out`?"
→ przez `return` — `bool` „czy się udało"; przez `out` — samą liczbę.

> „Czemu twórcy C# nie zrobili tego przez zwykłe `return`?"
→ bo trzeba oddać **dwie** rzeczy naraz, a `return` oddaje jedną.

**To jest domknięcie wątku ciągnącego się od lekcji 2.3.** Uczeń używał tej konstrukcji siedem lekcji; teraz rozumie, dlaczego wygląda tak, a nie inaczej.

Napisz razem z uczniem **własny odpowiednik**:
```csharp
bool SprobujPodzielic(int a, int b, out int wynik)
{
    if (b == 0)
    {
        wynik = 0;
        return false;
    }

    wynik = a / b;
    return true;
}

if (SprobujPodzielic(10, 0, out int w))
{
    Console.WriteLine($"Wynik: {w}");
}
else
{
    Console.WriteLine("Nie da się podzielić przez zero.");
}
```

> „Zauważ `wynik = 0;` w gałęzi błędu. Czemu jest konieczne?"
→ bo metoda **musi** przypisać `out` na każdej ścieżce. To ta sama logika co `CS0161` z lekcji 7.1.

**Uczeń właśnie napisał metodę w konwencji `Try`** — tej samej, którą rozpoznał w lekcji 6.3.

### D. `ref` — daj klucze do liczby

```csharp
void ZwiekszNaprawde(ref int x)
{
    x = x + 1;
}

int a = 5;
ZwiekszNaprawde(ref a);
Console.WriteLine(a);
```
→ `6`

> „Czym to się różni od `out`?"

| | `out` | `ref` |
| --- | --- | --- |
| wartość początkowa | **nie** jest potrzebna | **musi** być nadana |
| metoda musi przypisać | tak | nie |
| po co | oddać dodatkową wartość | zmienić istniejącą |

> „`ref` używa się **rzadko**. Zwykle lepiej zwrócić nową wartość przez `return`, niż zmieniać cudzą zmienną — bo z wywołania nie widać, że coś się zmieniło."

Porównaj:
```csharp
ZwiekszNaprawde(ref a);      // czy `a` się zmieniło? trzeba zajrzeć do metody
a = Zwiekszone(a);           // widać od razu
```

### E. Zasięg — gdzie zmienna żyje

```csharp
int naZewnatrz = 1;

void Metoda()
{
    int wSrodku = 2;
    Console.WriteLine(naZewnatrz);
}

Metoda();
Console.WriteLine(wSrodku);
```
→ `CS0103: The name 'wSrodku' does not exist in the current context`

> „Metoda widziała `naZewnatrz`, ale na zewnątrz nie widać `wSrodku`. Skąd ta asymetria?"
→ zmienna żyje w **klamrach**, w których powstała, i we wszystkim, co jest w nich zagnieżdżone.

To ta sama zasada co przy liczniku `for` z lekcji 5.2 (`CS0103` po pętli) i przy zmiennych w pętli `while` z 5.1.

```csharp
if (true)
{
    int tylkoTutaj = 5;
}
// Console.WriteLine(tylkoTutaj);   // CS0103
```

> **Reguła jednym zdaniem:** zmienna żyje od miejsca deklaracji do zamykającej klamry swojego bloku.

## Krok 4 — Pogłębienie (10 min)

**Kiedy `out`, kiedy `return`, kiedy nic**

| Chcesz… | Użyj |
| --- | --- |
| oddać jedną wartość | `return` |
| oddać wynik **i** informację, czy się udało | `return bool` + `out` |
| zmienić tablicę/listę przekazaną do metody | nic — działa samo |
| zmienić liczbę przekazaną do metody | `ref` (ale zastanów się, czy nie lepiej `return`) |

**Metoda, która nie powinna zmieniać tego, co dostała**

```csharp
int Suma(int[] liczby)
{
    int suma = 0;
    foreach (int x in liczby)
    {
        suma = suma + x;
    }
    return suma;
}
```
> „Ta metoda dostała klucze do tablicy, ale niczego nie ruszyła. Czy to widać z nagłówka?"
→ nie. **Widać to dopiero z nazwy i z treści.** Dlatego nazwy metod mają znaczenie: `Suma` obiecuje, że tylko liczy.

**Zmienne w pętlach — częsty błąd**

```csharp
for (int i = 0; i < 3; i++)
{
    int licznik = 0;
    licznik = licznik + 1;
    Console.Write(licznik + " ");
}
```
→ `1 1 1`

> „Czemu nie `1 2 3`? Gdzie powstaje `licznik`?"
→ **w środku pętli**, więc powstaje na nowo w każdym obiegu. To ta sama pułapka co `suma` w środku pętli z lekcji 5.1, tylko teraz uczeń umie ją nazwać: **kwestia zasięgu**.

**Kopia kontra wskazanie — podsumowanie**

| Typ | Co dostaje metoda |
| --- | --- |
| `int`, `double`, `bool`, `char` | kopię wartości |
| `string` | w praktyce zachowuje się jak kopia |
| tablica, `List`, `Dictionary` | wskazanie na to samo |

> „`string` jest ciekawym przypadkiem: technicznie działa jak tablica, ale tekstu **nie da się zmienić w miejscu** — każda zmiana tworzy nowy tekst. Dlatego zachowuje się, jakbyś dostał kopię."

**Nie rozwijaj tematu niezmienności tekstów.** Jedno zdanie, żeby uczeń nie zbudował sobie fałszywej reguły.

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „`ref`, `out`, zasięg". Propozycje:

- 🔥 **Rozgrzewka** (`20-ref-out-a.cs`): napisz metodę `void MinMax(int[] liczby, out int naj, out int min)`, która znajduje największą i najmniejszą wartość. Wywołaj ją na tablicy pięciu liczb i wypisz oba wyniki.
- ⭐ **Główne** (`20-ref-out-b.cs`): napisz `bool SprobujWczytacWiek(string tekst, out int wiek)`, która zwraca `true` tylko wtedy, gdy tekst jest liczbą **i** mieści się w zakresie 0–120. W pozostałych przypadkach ustawia `wiek` na zero i zwraca `false`. Przetestuj na pięciu różnych tekstach, w tym `"200"`, `"abc"` i pustym. To twoja własna metoda w konwencji `Try`.
- ⚡ **Gwiazdka** (`20-ref-out-c.cs`): napisz `void Zamien(ref int a, ref int b)`, która zamienia wartości dwóch zmiennych miejscami. Wywołaj ją i sprawdź, czy zadziałało. Potem napisz drugą wersję **bez** `ref` i wyjaśnij mi na piśmie, czemu nie działa. Na koniec: napisz metodę odwracającą tablicę w miejscu (jak w ćwiczeniu 6.1) i odpowiedz, czemu tam `ref` **nie był** potrzebny.

Gwiazdka zderza trzy rzeczy naraz: `ref` przy liczbach, jego brak przy tablicach i zrozumienie, skąd ta różnica. Uczeń, który odpowie poprawnie na ostatnie pytanie, rozumie tę lekcję.

## Pułapki

- **Zapomniane `out` przy wywołaniu** → błąd kompilacji. `out` pisze się i przy definicji, i przy wywołaniu.
- **Nieprzypisany parametr `out`** → `CS0177`. Musi dostać wartość na **każdej** ścieżce, także w gałęzi błędu.
- **`ref` bez wartości początkowej** → `CS0165`. `ref` wymaga zmiennej, która już coś ma; `out` nie.
- **Oczekiwanie, że metoda zmieni liczbę** — bez `ref` nie zmieni. Objaw: „przecież zwiększyłem w metodzie".
- **Zaskoczenie, że metoda zmieniła tablicę** — bez `ref` **zmieni**. To odwrotna strona tej samej monety.
- **Zmienna zadeklarowana w pętli** — powstaje na nowo co obieg. Objaw: licznik zawsze równy jeden.
- **Za dużo `out`** — metoda z trzema `out` zwykle powinna zwracać coś złożonego. To zapowiedź modułu 8: czasem właściwą odpowiedzią jest własny typ.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Sekcja `[moduł 2]` wspomina jedną zmianę dotyczącą tej lekcji: **deklarację `out` w miejscu wywołania** (`out int wynik`) wprowadzono w C# 7. Starsze materiały pokazują dwie linie:
```csharp
int wynik;
bool ok = int.TryParse(s, out wynik);
```
Obie formy działają; uczymy krótszej.

`ref` i zasięg zmiennych nie zmieniły się od pierwszej wersji języka.

## Notatki tutora

- **Krok 3.A rób przez zgadywanie.** Uczeń, który obstawi `1` i zobaczy `99`, zapamięta różnicę na zawsze. Uczeń, któremu ją wytłumaczysz, przytaknie i pomyli się za tydzień.
- **Krok 3.C to domknięcie siedmiu lekcji.** Od 2.3 uczeń pisał `out` bez wyjaśnienia i słyszał „w 7.3". Powiedz mu wprost, że to jest ta chwila.
- **Nie tłumacz stosu i sterty.** „Zmienna trzyma wskazanie, gdzie leży tablica" wystarcza. Rozwijanie tego zabiera kwadrans i nie zmienia niczego w tym, co uczeń napisze.
- **Nie tłumacz niezmienności tekstów.** Jedno zdanie w kroku 4, żeby uczeń nie zbudował fałszywej reguły „tablice tak, teksty tak samo".
- **`ref` przedstaw z rezerwą.** Uczeń, który go polubi, zacznie zmieniać wszystko wszędzie. Podkreśl, że `return` jest zwykle lepszy.
- **Nie wprowadzaj `in` ani `ref readonly`.** Poza kursem.
- Jeśli uczeń pyta „a jak oddać z metody trzy rzeczy" — to dobre pytanie i właściwa odpowiedź brzmi: „można trzema `out`, ale zwykle znaczy to, że potrzebujesz własnego typu. Moduł 8."
