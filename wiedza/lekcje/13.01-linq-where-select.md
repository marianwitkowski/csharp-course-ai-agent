# Lekcja 13.1 — Where, Select, OrderBy

## Cel
Po lekcji uczeń:
- Filtruje kolekcję przez `Where`, przekształca przez `Select`, sortuje przez `OrderBy`
- Czyta zapis `x => x > 5` i wie, co oznacza `=>`
- Łączy operacje w łańcuch i wie, że kolejność ma znaczenie
- Wie, że zapytanie **nie wykonuje się** w chwili zapisania — i co robi `ToList`
- Wie, kiedy `foreach` jest lepszy od LINQ

## Krok 1 — Zakotwiczenie (8 min)

Poproś ucznia, żeby **na kartce albo z pamięci** napisał kod: z listy liczb wybrać te większe od 5.

Spodziewany kształt:
```csharp
List<int> duze = new List<int>();

foreach (int x in liczby)
{
    if (x > 5)
    {
        duze.Add(x);
    }
}
```

**Pytania:**
> „Ile linii? Ile z nich mówi coś o **twoim** problemie, a ile to obsługa listy?"

**Co chcesz usłyszeć:** interesujące jest `x > 5`. Reszta — nowa lista, pętla, `Add` — powtarza się **za każdym razem**.

> „A teraz to samo, ale wybierz imiona uczniów z wynikiem powyżej 60, posortowane alfabetycznie. Ile pętli?"

**Co chcesz usłyszeć:** filtrowanie, wyciąganie imion, sortowanie — trzy przebiegi albo jeden zagmatwany.

> „Zauważ, że **schemat jest zawsze ten sam**, zmienia się tylko warunek."

## Krok 2 — Mostek (12 min)

**Mostek:**
> „Ten schemat napisano raz, za wszystkich. Nazywa się LINQ i mieszka na każdej kolekcji, jaką znasz."

```csharp
List<int> liczby = new List<int> { 5, 12, 3, 20, 8 };

var duze = liczby.Where(x => x > 5);

Console.WriteLine(string.Join(", ", duze));
```
→ `12, 20, 8`

**Nie tłumacz jeszcze `=>`. Najpierw pytaj:**
- „Gdzie tu jest twój warunek?" → `x > 5`, dokładnie jak w `if`
- „Co zniknęło w porównaniu z pętlą?" → nowa lista, `foreach`, `Add`
- „Czym jest `x`?" → **każdym kolejnym elementem po kolei**. Nazwa jest dowolna.

Dopiero teraz nazwij:
> „`x => x > 5` to **wyrażenie lambda**. Czytaj: »weź x i sprawdź, czy x jest większe od 5«. Strzałka oddziela to, co dostajesz, od tego, co z tym robisz. To zwykły kawałek kodu przekazany jako argument — skąd się bierze taka możliwość, powie lekcja 13.3."

> **`string.Join` z lekcji 6.2** — bierze separator i kolekcję, skleja w jeden tekst. Przyda się w całej tej lekcji do oglądania wyników.

Zwróć uwagę:
> „`Where` niczego nie zmienia w liście `liczby`. **Buduje nowy wynik.** Sprawdź: wypisz `liczby` po wywołaniu `Where`."

## Krok 3 — Eksperyment (25 min)

### A. `Select` — przekształcanie

```csharp
Console.WriteLine(string.Join(", ", liczby.Select(x => x * 2)));
```
→ `10, 24, 6, 40, 16`

> „Ile elementów wyszło? A przy `Where`?"
→ `Select` daje **tyle samo**, `Where` — tyle albo mniej.

**To najważniejsze rozróżnienie w lekcji.** Powiedz je wprost:

| Metoda | Odpowiada na pytanie | Liczba elementów |
| --- | --- | --- |
| `Where` | **które** | mniej lub tyle samo |
| `Select` | **co z każdego** | zawsze tyle samo |

`Select` może zmienić typ:
```csharp
Console.WriteLine(string.Join(", ", liczby.Select(x => $"[{x}]")));
```
→ `[5], [12], [3], [20], [8]` — z liczb zrobiły się teksty.

### B. `OrderBy` — sortowanie

```csharp
Console.WriteLine(string.Join(", ", liczby.OrderBy(x => x)));
Console.WriteLine(string.Join(", ", liczby.OrderByDescending(x => x)));
```
→ `3, 5, 8, 12, 20` i `20, 12, 8, 5, 3`

> „Po co `x => x`, skoro sortujemy same liczby?"
→ bo `OrderBy` pyta: **czym się kierować przy porównywaniu**. Przy liczbach to sama liczba; przy obiektach będzie to jedna z właściwości.

### C. Na obiektach

```csharp
List<Uczen> uczniowie = new List<Uczen>
{
    new Uczen { Imie = "Ala", Klasa = "1A", Punkty = 90 },
    new Uczen { Imie = "Bartek", Klasa = "1B", Punkty = 55 },
    new Uczen { Imie = "Celina", Klasa = "1A", Punkty = 70 }
};

Console.WriteLine(string.Join(", ", uczniowie.Select(u => u.Imie)));
Console.WriteLine(string.Join(", ", uczniowie.OrderByDescending(u => u.Punkty).Select(u => u.Imie)));
```
→ `Ala, Bartek, Celina` oraz `Ala, Celina, Bartek`

> **Zapis `new Uczen { Imie = ... }`** to inicjalizator obiektu z lekcji 12.3 — tworzy obiekt i od razu ustawia właściwości.

### D. Łańcuch

Teraz zadanie z kroku 1, w całości:
```csharp
var wynik = uczniowie
    .Where(u => u.Punkty > 60)
    .Select(u => u.Imie)
    .OrderBy(i => i);

Console.WriteLine(string.Join(", ", wynik));
```
→ `Ala, Celina`

> „Przeczytaj to na głos, po polsku."
→ „weź uczniów, zostaw tych powyżej 60 punktów, z każdego weź imię, posortuj".

> „Porównaj z trzema pętlami z kroku 1."

**Kolejność ma znaczenie.** Niech uczeń zamieni `Select` z `Where`:
```csharp
uczniowie.Select(u => u.Imie).Where(u => u.Punkty > 60)
```
→
```
error CS1061: Element „string” nie zawiera definicji „Punkty”
```
po `Select(u => u.Imie)` w rękach jest już **tekst**, a tekst nie ma `Punkty`.

> „Filtruj, **zanim** stracisz dane, których potrzebujesz do filtrowania."

### E. Wynik to nie lista

```csharp
var wynik = liczby.Where(x => x > 5);
wynik.Add(100);
```
→
```
error CS1061: Element „IEnumerable<int>” nie zawiera definicji „Add”
```

> „Co to za typ `IEnumerable`? Znasz go z lekcji 10.2."
→ kontrakt „da się po tym przejść `foreach`-em". Nie obiecuje ani dokładania, ani indeksowania.

Naprawa:
```csharp
List<int> lista = liczby.Where(x => x > 5).ToList();
lista.Add(100);
```

> „`ToList` domyka zapytanie do listy. Jest jeszcze `ToArray`."

### F. Zapytanie wykonuje się dopiero przy odczycie

To najbardziej zaskakujący eksperyment lekcji:

```csharp
List<int> zrodlo = new List<int> { 1, 2 };
var zapytanie = zrodlo.Where(x => x > 0);

zrodlo.Add(3);

Console.WriteLine(string.Join(", ", zapytanie));
```
→ `1, 2, 3`

> „Trójki nie było, gdy pisałeś `Where`. Skąd się wzięła w wyniku?"
→ `Where` **zapamiętało przepis**, nie wynik. Przepis wykonał się dopiero przy `string.Join`.

Teraz to samo z `ToList`:
```csharp
var zamrozone = zrodlo.Where(x => x > 0).ToList();
zrodlo.Add(4);
Console.WriteLine(string.Join(", ", zamrozone));
```
→ `1, 2, 3` — czwórki nie ma.

> „`ToList` wykonuje przepis **natychmiast** i zapisuje wynik. To jedyna różnica."

Nazwij: **odroczone wykonanie**.

### G. Kolekcji nie wolno zmieniać w trakcie przeglądania

```csharp
foreach (int x in zrodlo.Where(v => v > 0))
{
    zrodlo.Add(99);
}
```
→
```
System.InvalidOperationException: Collection was modified; enumeration operation may not execute.
```

> „Skoro zapytanie czyta listę na bieżąco, co się dzieje, gdy ta lista rośnie w trakcie?"
→ pętla nie ma jak dokończyć. **Najpierw `ToList`, potem zmieniaj.**

## Krok 4 — Pogłębienie (10 min)

**Skąd te metody się biorą?**

> „`Where` nie jest częścią `List`. To **metoda rozszerzająca** — sposób dopisania metody do gotowego typu, którego kodu nie masz. Dlatego `Where` działa jednakowo na liście, tablicy, słowniku i tekście. Sam takich metod w tym kursie nie napiszesz."

Sprawdźcie od razu:
```csharp
int[] tab = { 3, 1, 2 };
Console.WriteLine(string.Join(", ", tab.OrderBy(x => x)));
Console.WriteLine("Ala ma kota".Count(c => c == 'a'));
```
→ `1, 2, 3` oraz `3`

> „Ten sam `OrderBy` na tablicy. To ta sama zasada, co `foreach` z lekcji 10.2 — wszystko, po czym da się przejść, dostaje LINQ za darmo."

**Kilka metod, które warto rozpoznawać**

| Metoda | Robi |
| --- | --- |
| `First(warunek)` | pierwszy pasujący — **wyjątek**, gdy nie ma |
| `FirstOrDefault(warunek)` | pierwszy pasujący albo wartość domyślna (`0`, `null`) |
| `Take(n)` / `Skip(n)` | pierwsze `n` / wszystko poza pierwszymi `n` |
| `Distinct()` | bez powtórzeń |
| `ThenBy(...)` | drugie kryterium sortowania, po `OrderBy` |
| `Reverse()` | odwrócona kolejność |

**Kiedy NIE używać LINQ**

> „LINQ **czyta**. Gdy w pętli chcesz coś zapisywać do pliku, wypisywać na ekran albo modyfikować obiekty — zostań przy `foreach`. Zapytanie, które zmienia świat po drodze, jest trudne do wyśledzenia, bo nie wiadomo, kiedy się wykona."

To praktyczna zasada i warto ją powtórzyć: **`foreach` do robienia, LINQ do wybierania.**

**Druga składnia**

> „Zobaczysz też zapis `from x in liczby where x > 4 select x`. Robi dokładnie to samo — to **składnia zapytań**. W nowym kodzie prawie nie występuje; ta lekcja uczy zapisu z kropkami."

## Pułapki

- **`Select` przed `Where`** — po `Select` nie ma już właściwości, po których chcesz filtrować.
- **`.Add` na wyniku zapytania** → `CS1061`. Najpierw `ToList`.
- **Zmiana kolekcji w trakcie przeglądania** → `InvalidOperationException: Collection was modified`.
- **Zapamiętane zapytanie** wykonuje się przy każdym odczycie i widzi **aktualną** zawartość kolekcji. Chcesz zamrozić → `ToList`.
- **`First` na pustym wyniku** → `InvalidOperationException: Sequence contains no matching element`. Bezpieczniej `FirstOrDefault`.
- **Oczekiwanie, że LINQ zmienia listę** — nie zmienia. Zawsze buduje nowy wynik.
- **`Where` bez `string.Join` albo `foreach`** — nic się nie wypisze, bo zapytanie się nie wykonało.

## Notatki tutora

- **Krok 1 musi być napisany ręcznie.** Bez własnoręcznej pętli z `Add` uczeń nie zobaczy, co LINQ zabiera.
- **Nie tłumacz lambdy w kroku 2 dłużej niż dwoma zdaniami.** Cała lekcja 13.3 jest o tym. Tu wystarczy „warunek jak w `if`".
- **Krok 3.F (odroczone wykonanie) jest obowiązkowy.** To najczęstsze źródło zdziwienia przy LINQ i lepiej, żeby uczeń zobaczył je na trzech liczbach niż na danych z pliku.
- **Nie wprowadzaj typów anonimowych** (`Select(u => new { u.Imie, u.Punkty })`). Kuszące, ale to nowy rodzaj typu. Jeśli uczeń potrzebuje dwóch wartości — niech zrobi `Select` na własną klasę albo na tekst.
- **Nie wprowadzaj `Join`, `SelectMany`, `Aggregate`, `Zip`.** Poza kursem.
- **Składnię zapytań pokaż jednym zdaniem**, bez ćwiczeń. Uczeń trafi na nią w starszych poradnikach i ma ją rozpoznać, nie pisać.
- Jeśli uczeń zapyta o bazy danych i „LINQ to SQL" — jedno zdanie i odesłanie do 14.5.
