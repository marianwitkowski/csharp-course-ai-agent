# Lekcja 5.2 — Pętla `for`

## Cel
Po lekcji uczeń:
- Pisze pętlę `for` i rozpoznaje jej trzy części
- Umie przepisać `while` na `for` i odwrotnie
- Wie, kiedy `for` jest czytelniejszy od `while`, a kiedy odwrotnie
- Wie, że zmienna licznika **znika po pętli** — i czemu to dobrze
- Liczy w dół i co drugi element, zmieniając trzecią część

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Robisz dziesięć pompek. Co musisz mieć w głowie, żeby się nie pomylić?"

**Co chcesz usłyszeć:** ile już zrobiłeś, ile trzeba, i że po każdej dokładasz jedną.

**Drugie pytanie:**
> „Wymień te trzy rzeczy po kolei: od czego zaczynasz, do kiedy robisz, co robisz po każdej."

**Co chcesz usłyszeć:** zaczynam od zera, robię dopóki mniej niż dziesięć, po każdej dodaję jeden. **To są dokładnie trzy części pętli `for`** — nie nazywaj ich jeszcze.

**Trzecie pytanie:**
> „Czym to się różni od mieszania herbaty z poprzedniej lekcji?"

**Co chcesz usłyszeć:** tutaj **z góry wiadomo**, ile razy. To jest cała różnica między `for` a `while`.

## Krok 2 — Mostek (10 min)

Uczeń pisze **najpierw wersję, którą zna** — z lekcji 5.1:

```csharp
int i = 0;
while (i < 3)
{
    Console.WriteLine($"Pompka {i}");
    i++;
}
```

> „Zaznacz w tym kodzie trzy rzeczy: gdzie licznik powstaje, gdzie jest sprawdzany, gdzie zwiększany."

Uczeń wskaże trzy różne linie — jedna przed pętlą, jedna w nagłówku, jedna na końcu wnętrza.

**Mostek:**
> „Te trzy rzeczy zawsze chodzą razem, więc C# pozwala zapisać je w jednej linii. To jest pętla `for`."

Uczeń tworzy `kurs/zadania/12-for.cs`:

```csharp
for (int i = 0; i < 3; i++)
{
    Console.WriteLine($"Pompka {i}");
}
```
→ ten sam wynik co wyżej.

**Pytania:**
- „Które z trzech miejsc odpowiada której części nagłówka?"
- „Co oddziela części od siebie?" → **średniki**, nie przecinki
- „Ile razy wykona się każda z trzech części?"
  → pierwsza **raz**, druga **przed każdym** obiegiem, trzecia **po każdym** obiegu

Nazwij części: **inicjalizacja**, **warunek**, **krok**.

> **`for` to nie nowa pętla.** To ten sam `while`, tylko z trzema rzeczami zebranymi w jednym miejscu, żeby nie trzeba było ich szukać po całym kodzie.

## Krok 3 — Eksperyment (20 min)

### A. Kolejność wykonania — sprawdź, nie zgaduj

```csharp
for (int i = 0; i < 3; i++)
{
    Console.WriteLine($"wnętrze, i = {i}");
}
Console.WriteLine("po pętli");
```

> „Wypisz na kartce, w jakiej kolejności wykonują się: inicjalizacja, warunek, wnętrze, krok. Potem sprawdź, czy wynik się z tym zgadza."

Prawidłowa kolejność: inicjalizacja → warunek → wnętrze → krok → warunek → wnętrze → krok → ... → warunek (fałszywy) → wyjście.

> „Zauważ: warunek sprawdzany jest **o jeden raz więcej** niż wykonuje się wnętrze. Ostatnie sprawdzenie jest tym, które kończy pętlę."

### B. Zmienna licznika znika po pętli

```csharp
for (int i = 0; i < 3; i++)
{
    Console.WriteLine(i);
}
Console.WriteLine(i);
```
→ `CS0103: The name 'i' does not exist in the current context`

> „`i` powstało w nagłówku pętli i tam też się skończyło. Czy to przeszkadza, czy pomaga?"

Pomaga: licznik jest potrzebny **tylko** w pętli, a nazwa `i` zostaje wolna dla następnej. W wersji z `while` licznik zostawał na zawsze i łatwo było go przypadkiem użyć.

> „Kiedy to przeszkadza? Gdy wartość licznika jest ci potrzebna **po** pętli — wtedy używasz `while` z lekcji 5.1."

### C. Liczenie w dół

Uczeń zmienia **wszystkie trzy części**:
```csharp
for (int i = 5; i > 0; i--)
{
    Console.WriteLine(i);
}
Console.WriteLine("Start!");
```
→ `5 4 3 2 1 Start!`

> „Zmieniły się trzy rzeczy naraz. Spróbuj zmienić tylko jedną z nich i zobacz, co się stanie."

Warto, żeby uczeń popsuł to celowo: `i--` zamienione na `i++` przy warunku `i > 0` daje pętlę nieskończoną. **Uprzedź o Ctrl+C.**

### D. Co drugi, co dziesiąty

```csharp
for (int i = 0; i <= 20; i += 5)
{
    Console.Write(i + " ");
}
```
→ `0 5 10 15 20`

> „Trzecia część nie musi być `i++`. Co się stanie przy `i += 3`?"

### E. Suma — to samo co w 5.1, krócej

```csharp
int suma = 0;

for (int i = 1; i <= 100; i++)
{
    suma = suma + i;
}

Console.WriteLine($"Suma: {suma}");
```
→ `5050`

> „Porównaj z wersją z lekcji 5.1. Co zniknęło?"
→ deklaracja licznika przed pętlą i zwiększanie na końcu wnętrza. Zostało samo sumowanie.

> **Zwróć uwagę:** `suma` nadal jest **przed** pętlą. To ta sama zasada co w 5.1 — gdyby była w środku, zerowałaby się co obieg.

### F. Pusty nagłówek — zobacz, ale nie używaj

```csharp
// for (;;) { }   // pętla nieskończona
```
> „Wszystkie trzy części można pominąć. Wtedy nie ma warunku, więc pętla nigdy się nie kończy. Pokazuję, żebyś rozpoznał, gdy to zobaczysz — nie żebyś tego używał."

## Krok 4 — Pogłębienie (10 min)

**`for` czy `while`? Reguła praktyczna:**

| Sytuacja | Pętla |
| --- | --- |
| wiesz z góry, ile razy | `for` |
| powtarzasz, aż coś się stanie | `while` |
| pytasz użytkownika, aż poda dobre dane | `while` / `do...while` |
| licznik potrzebny po zakończeniu | `while` |

> „Obie pętle potrafią to samo — każdy `for` da się zapisać jako `while` i odwrotnie. Wybierasz tę, która **czytelniej opowiada**, co się dzieje."

**Pomyłka o jeden — teraz w `for`:**
```csharp
for (int i = 1; i < 5; i++) { Console.Write(i + " "); }   // 1 2 3 4
for (int i = 1; i <= 5; i++) { Console.Write(i + " "); }  // 1 2 3 4 5
```
> „Który zapis wybrać, gdy chcesz pięć obiegów zaczynając od 1? A gdy zaczynasz od 0?"
→ od 0: `i < 5`. Od 1: `i <= 5`. **Nie zapamiętuj — licz na małych liczbach.**

**Pętla w pętli:**
```csharp
for (int wiersz = 1; wiersz <= 3; wiersz++)
{
    for (int kolumna = 1; kolumna <= 3; kolumna++)
    {
        Console.Write($"{wiersz}-{kolumna} ");
    }
    Console.WriteLine();
}
```
→
```
1-1 1-2 1-3 
2-1 2-2 2-3 
3-1 3-2 3-3 
```

> „Ile razy wykona się wnętrze wewnętrznej pętli? Skąd ta liczba?"
→ 3 × 3 = 9. Wewnętrzna pętla przebiega **całą** dla każdego obiegu zewnętrznej.

**Nie rozwijaj zagnieżdżania.** Jeden przykład, jedno pytanie. Dwa poziomy wystarczą do końca kursu.

**Zmienna licznika i wcięcia** — przypomnienie z 4.1: każdy poziom pętli to kolejne wcięcie. Przy dwóch pętlach kod ma już trzy poziomy i bez formatowania robi się nieczytelny.

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „pętla `for`". Propozycje:

- 🔥 **Rozgrzewka** (`12-for-a.cs`): wypisz liczby parzyste od 2 do 20, oddzielone spacjami, w jednej linii. Zrób to **bez** `if` — samą trzecią częścią nagłówka.
- ⭐ **Główne** (`12-for-b.cs`): tabliczka mnożenia. Zapytaj o liczbę od 1 do 10 (przez `TryParse`, z powtarzaniem, aż poda poprawnie — jak w 5.1). Wypisz jej tabliczkę: `7 x 1 = 7`, `7 x 2 = 14`, … do dziesięciu.
- ⚡ **Gwiazdka** (`12-for-c.cs`): choinka z gwiazdek. Zapytaj o wysokość. Dla wysokości 4 wypisz:
  ```
     *
    ***
   *****
  *******
  ```
  Użyj dwóch pętli zagnieżdżonych: jedna na wiersze, druga na znaki. Podpowiedź: w wierszu numer `w` (licząc od 1) jest `wysokosc - w` spacji i `2 * w - 1` gwiazdek.

Gwiazdka wymaga policzenia dwóch wzorów na kartce, zanim padnie pierwsza linia kodu. To celowe — od tej lekcji warto zacząć planować przed pisaniem.

## Pułapki

- **Przecinki zamiast średników** w nagłówku → komunikat o nieoczekiwanym tokenie. Trzy części rozdziela **średnik**.
- **Zmiana licznika także we wnętrzu** — `i++` w nagłówku i drugie `i++` w środku daje przeskakiwanie co drugi. Kompilator milczy.
- **Użycie licznika po pętli** → `CS0103`. Trzeba wtedy `while` albo zmienna zadeklarowana przed pętlą.
- **Pomyłka o jeden** — `<` kontra `<=`, ta sama co w 5.1. Sprawdzaj na małych liczbach.
- **Nieskończony `for`** — gdy krok oddala od warunku (`i--` przy `i < 10`). Ctrl+C.
- **`suma` deklarowana w pętli** — zeruje się co obieg, wynik zły, kompilator milczy.
- **Zagnieżdżenie z tą samą nazwą licznika** — `for (int i…)` w środku `for (int i…)` nie skompiluje się; użyj innych nazw, najlepiej mówiących (`wiersz`, `kolumna`).

## Notatki tutora

- **Krok 2 musi zacząć się od `while`**, który uczeń już zna. `for` pokazany od zera jest trzema niezrozumiałymi rzeczami w nawiasie; pokazany jako **zebranie trzech linii w jedną** ma powód.
- **Krok 3.A (kolejność) rób na kartce, nie na ekranie.** Uczeń, który wypisze kolejność sam i potem ją sprawdzi, zapamięta. Uczeń, któremu ją podasz, przytaknie i zapomni.
- **Nie rozstrzygaj, która pętla jest lepsza.** Tabela w kroku 4 wystarczy; obie są używane i obie zobaczy w cudzym kodzie.
- **Nie wprowadzaj `foreach`.** Uczeń zapyta („a jak przejść po literach tekstu?") — lekcja 5.3, następna.
- **Nie wprowadzaj `break`.** To 5.3.
- **Nie wprowadzaj tablic.** Największa pokusa tej lekcji: `for` naturalnie chodzi z indeksem, a indeks bez tablicy wygląda dziwnie. Wytrzymaj — moduł 6 jest zaraz po.
- **Choinka z gwiazdki bywa trudniejsza, niż wygląda.** Jeśli uczeń utknie, nie podawaj wzorów — poproś, żeby narysował choinkę na kratkowanym papierze i policzył spacje w każdym wierszu. Odpowiedź wyjdzie sama.
