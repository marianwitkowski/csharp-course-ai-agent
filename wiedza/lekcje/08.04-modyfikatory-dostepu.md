# Lekcja 8.4 — Modyfikatory dostępu

## Cel
Po lekcji uczeń:
- Rozróżnia `public` i `private` i wie, co jest domyślne
- Ukrywa dane, zostawiając na zewnątrz tylko sensowne operacje
- Umie powiedzieć, czego jego klasa **nie pozwala** zepsuć
- Rozpoznaje `CS0122` (dostęp do składowej prywatnej)
- Wie, że `protected` i `internal` istnieją — i gdzie o nich usłyszy

> **To lekcja o odpowiedzialności, nie o składni.** Słów kluczowych są dwa; cała reszta to pytanie „co ma prawo zepsuć ktoś, kto używa twojej klasy".

## Krok 1 — Zakotwiczenie (5-8 min)

**Pytanie wejściowe:**
> „Bankomat. Wpłacasz, wypłacasz, sprawdzasz saldo. Czy możesz sięgnąć do środka i przestawić licznik banknotów?"

**Co chcesz usłyszeć:** nie — dostajesz kilka przycisków, nie dostęp do wnętrza.

**Drugie pytanie:**
> „Gdyby ktoś dał ci klucz do środka, czy bank nadal mógłby ręczyć za saldo?"

**Co chcesz usłyszeć:** nie. **Jeśli każdy może zmienić wszystko, nikt nie odpowiada za poprawność.**

**Trzecie pytanie:**
> „Co takiego bankomat gwarantuje, czego ty sam nie musisz pilnować?"

**Co chcesz usłyszeć:** że saldo się zgadza, że nie wypłacisz więcej, niż masz. **To jest niezmiennik** — nie nazywaj jeszcze.

## Krok 2 — Mostek (10 min)

Wróć do konta z lekcji 8.3 i pokaż, co jeszcze da się zepsuć:

```csharp
class Konto
{
    public string Wlasciciel { get; set; }
    public decimal Saldo { get; private set; }
    public List<string> Historia = new List<string>();

    public Konto(string wlasciciel) { Wlasciciel = wlasciciel; }

    public void Wplac(decimal kwota)
    {
        if (kwota > 0)
        {
            Saldo = Saldo + kwota;
            Historia.Add($"wpłata {kwota}");
        }
    }
}
```

```csharp
Konto k = new Konto("Ala");
k.Wplac(100);
k.Historia.Clear();
Console.WriteLine($"{k.Saldo}, wpisów w historii: {k.Historia.Count}");
```
→ `100, wpisów w historii: 0`

> „Saldo jest chronione przez `private set`. A historia?"
→ **otwarta na oścież.** Ktoś z zewnątrz właśnie skasował dowody wpłaty.

> „Czy `private set` na `Historia` by pomogło?"
→ **nie!** `private set` blokuje **podmianę całej listy**, ale nie zmianę jej zawartości. To ta sama zasada co „klucze do mieszkania" z lekcji 7.3.

**Mostek:**
> „Słowo `private` znaczy: »widoczne tylko z wnętrza tej klasy«. `public` znaczy »widoczne dla wszystkich«. Decyzja, co jest czym, to najważniejsza decyzja przy pisaniu klasy."

## Krok 3 — Eksperyment (22 min)

### A. `private` w praktyce

```csharp
class Kot
{
    private int wiek;
}
```

```csharp
Kot k = new Kot();
Console.WriteLine(k.wiek);
```
→ `CS0122: 'Kot.wiek' is inaccessible due to its protection level`

> „Przeczytaj: »niedostępne ze względu na poziom ochrony«. Kto może odczytać `wiek`?"
→ tylko kod wewnątrz klasy `Kot`.

### B. Domyślnie jest `private`

```csharp
class Kot
{
    int wiek;          // bez słowa — private
    void Miaucz() { }  // bez słowa — private
}
```

> „Spróbuj sięgnąć po `wiek` i `Miaucz` z zewnątrz."
→ oba dają `CS0122`.

**W C# domyślnie wszystko w klasie jest prywatne.** `public` trzeba napisać świadomie — i to jest dobre ustawienie domyślne: łatwiej coś udostępnić później, niż odebrać dostęp, z którego ktoś już korzysta.

### C. Naprawa konta

```csharp
class Konto
{
    private decimal saldo;
    private List<string> historia = new List<string>();

    public string Wlasciciel { get; }
    public decimal Saldo => saldo;
    public int LiczbaOperacji => historia.Count;

    public Konto(string wlasciciel)
    {
        Wlasciciel = wlasciciel;
    }

    public void Wplac(decimal kwota)
    {
        if (kwota <= 0)
        {
            Console.WriteLine("Kwota musi być dodatnia.");
            return;
        }

        saldo = saldo + kwota;
        historia.Add($"wpłata {kwota}");
    }

    public bool SprobujWyplacic(decimal kwota)
    {
        if (kwota <= 0 || kwota > saldo)
        {
            return false;
        }

        saldo = saldo - kwota;
        historia.Add($"wypłata {kwota}");
        return true;
    }

    public void PokazHistorie()
    {
        foreach (string wpis in historia)
        {
            Console.WriteLine($"  {wpis}");
        }
    }
}
```

```csharp
Konto k = new Konto("Ala");
k.Wplac(100);
Console.WriteLine(k.SprobujWyplacic(500));
Console.WriteLine(k.SprobujWyplacic(30));
Console.WriteLine($"{k.Wlasciciel}: {k.Saldo}, operacji: {k.LiczbaOperacji}");
k.PokazHistorie();
```
→ `False`, `True`, `Ala: 70, operacji: 2`, dwie linie historii

Zapytaj ucznia:
> „Wypisz mi wszystko, czego **nie da się** zrobić z zewnątrz z tym kontem."

Doprowadź do listy:
- ustawić saldo na dowolną liczbę
- wypłacić więcej, niż jest
- wpłacić kwotę ujemną
- skasować albo podmienić historię
- zmienić właściciela po utworzeniu

> „Czego pilnuje ta klasa, czego nikt inny nie musi pilnować?"
→ **że saldo zawsze zgadza się z historią i nigdy nie spada poniżej zera.**

Nazwij to: **niezmiennik** — warunek, który jest prawdziwy przez cały czas życia obiektu. To jest gwarancja bankomatu z kroku 1.

> **Zwróć uwagę na `SprobujWyplacic`.** Zwraca `bool` i nie przewraca programu — to konwencja `Try` z lekcji 6.3 i 7.3, tym razem w twojej własnej klasie.

### D. Metoda prywatna — pomocnik, nie usługa

```csharp
private void Zapisz(string opis)
{
    historia.Add($"{DateTime.Now:HH:mm} {opis}");
}
```

> „Kto ma prawo wywołać tę metodę?"
→ tylko wnętrze klasy. Z zewnątrz nikt nie powinien dopisywać do historii, co mu się podoba.

**Metody prywatne dzielą długą metodę publiczną na kawałki**, nie udostępniając ich światu. To ta sama zasada wydzielania co w lekcji 7.1, tylko z kontrolą dostępu.

### E. Co udostępniać, a co nie — ćwiczenie na sucho

Pokaż uczniowi klasę i pozwól zdecydować **przed** obejrzeniem odpowiedzi:

```csharp
class Uczen
{
    // Imie
    // Oceny (lista)
    // Srednia
    // DodajOcene(int)
    // liczbaWpisow (licznik pomocniczy)
}
```

> „Które z tych pięciu rzeczy powinny być `public`?"

Rozsądna odpowiedź: `Imie` (właściwość), `Srednia` (liczona, tylko odczyt), `DodajOcene` (metoda). `Oceny` — **nie**, bo ktoś dopisze ocenę 100. `liczbaWpisow` — nie, to sprawa wewnętrzna.

> „Reguła: **publiczne jest to, co ktoś ma robić z twoim obiektem. Prywatne — to, jak on to robi w środku.**"

## Krok 4 — Pogłębienie (10 min)

**Cztery modyfikatory — dwa dziś, dwa do rozpoznania**

| Słowo | Widoczne dla | W tym kursie |
| --- | --- | --- |
| `private` | tylko ta klasa | **używasz** |
| `public` | wszystkich | **używasz** |
| `protected` | tej klasy i klas dziedziczących | moduł 9 |
| `internal` | tego projektu | rozpoznanie |

> „`protected` zobaczysz w module 9, gdy pojawi się dziedziczenie. `internal` jest domyślne dla samych klas i przy jednym pliku nie ma znaczenia."

**Jak udostępnić listę, nie oddając nad nią władzy**

Uczeń zapyta: „a jeśli ktoś **musi** zobaczyć oceny?". Trzy wyjścia, od najprostszego:

1. **właściwość liczona zamiast listy** — `Srednia`, `Najwyzsza`, `LiczbaOcen`
2. **metoda wypisująca** — `PokazOceny()`
3. **kopia listy** — `public List<int> Oceny => new List<int>(oceny);`

> „Trzecie wyjście oddaje **kopię**: ktoś może ją zmieniać, ale twoja lista zostaje nietknięta. Pamiętasz kopię kontra wskazanie z lekcji 7.3?"

**Nie rozwijaj** poza te trzy zdania; `IReadOnlyList` jest poza kursem.

**Kiedy pole publiczne jest w porządku?**

> „Prawie nigdy — ale »prawie« ma znaczenie. Przy kilkulinijkowym programie na własny użytek publiczne pole nikomu nie zaszkodzi. Zasada zaczyna się liczyć, gdy klasy używa ktoś inny albo ty za pół roku."

**Nie strasz.** Uczeń ma rozumieć powód, nie bać się reguły.

**Co się psuje bez enkapsulacji**

Zbierz w jednym miejscu to, co uczeń zobaczył przez cały moduł:

| Bez ochrony | Skutek |
| --- | --- |
| pole publiczne | ktoś ustawia bzdurę (8.3, wiek −500) |
| lista publiczna | ktoś kasuje historię (krok 2) |
| brak konstruktora | obiekt powstaje niekompletny (8.2) |
| wartość liczona trzymana w polu | rozjeżdża się z danymi (8.3) |

> „Zauważ, że każda z tych rzeczy to **cudzy** kod psujący **twój** obiekt. Enkapsulacja to nie ozdoba — to jedyny sposób, żeby dało się za coś ręczyć."

## Pułapki

- **Dostęp do składowej prywatnej** → `CS0122`.
- **`private set` na kolekcji nie chroni zawartości** — blokuje podmianę listy, nie jej zmianę. Trzeba prywatnego pola i metod.
- **Brak modyfikatora** oznacza `private` — kod się kompiluje, a użycie z zewnątrz nie. Objaw: „przecież dodałem tę metodę".
- **Wszystko `public` „na wszelki wypadek"** — łatwo dać, trudno odebrać.
- **Publiczne pole zaplecza obok właściwości** — obchodzi całą kontrolę. Pole zaplecza zawsze `private`.
- **Metoda pomocnicza jako `public`** — powiększa to, za co musisz ręczyć.
- **Mylenie `private` z bezpieczeństwem** — to porządek w kodzie, nie ochrona przed złośliwym użytkownikiem. Warto powiedzieć wprost.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Ta lekcja nie ma zmian. `public` i `private` działają w C# tak samo od pierwszej wersji języka.

## Notatki tutora

- **Krok 2 jest sercem lekcji.** Uczeń wyszedł z 8.3 przekonany, że `private set` załatwia sprawę. Publiczna lista pokazuje, że nie — i dopiero wtedy `private` na polu ma sens.
- **Krok 3.C zakończ pytaniem „czego NIE da się zrobić".** To odwrócenie perspektywy: uczeń zwykle myśli o tym, co jego kod potrafi, a projektowanie klasy polega na decydowaniu, czego ma **nie** pozwalać.
- **Nie tłumacz `protected`.** Jedno zdanie w tabeli i moduł 9.
- **Nie wprowadzaj interfejsów.** Uczeń może zapytać, jak wymusić, żeby klasa „coś umiała" — moduł 10.
- **Nie mów, że `private` to bezpieczeństwo.** To częste nieporozumienie; `private` porządkuje kod, a nie chroni przed atakiem.
- **Nie każ uczniowi przepisywać wszystkich wcześniejszych klas.** Zasada ma być zrozumiana, nie odpokutowana.
- Jeśli uczeń pyta, czemu w tym kursie do tej pory były pola publiczne — powiedz wprost: „bo najpierw musiałeś zobaczyć, co się psuje bez ochrony. Teraz wiesz."
