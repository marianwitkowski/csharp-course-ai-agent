# Lekcja 4.2 — Operatory logiczne i operator warunkowy

## Cel
Po lekcji uczeń:
- Łączy warunki przez `&&` (oba) i `||` (przynajmniej jeden)
- Odwraca warunek przez `!`
- Zamienia zagnieżdżone `if` z lekcji 4.1 na jeden warunek
- Wie, że `&&` i `||` **przestają liczyć**, gdy wynik jest już przesądzony
- Używa operatora warunkowego `?:` tam, gdzie chodzi o wybór jednej z dwóch wartości

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Ochroniarz wpuszcza na koncert. Wpuszcza cię, gdy masz bilet **i** masz ukończone 16 lat. Co się stanie, gdy masz bilet, ale 14 lat?"

**Co chcesz usłyszeć:** nie wpuści — muszą być spełnione oba warunki.

**Drugie pytanie:**
> „A teraz inna sytuacja: zostajesz w domu, gdy pada **albo** gdy jesteś chory. Ile z tych rzeczy musi być prawdą, żebyś został?"

**Co chcesz usłyszeć:** jedna wystarczy.

**Trzecie pytanie:**
> „Czym różnią się te dwa »albo« w polszczyźnie: »kawa albo herbata« i »zostaję, gdy pada albo gdy jestem chory«?"

To ciekawe pytanie i uczeń zwykle wyczuwa różnicę: w pierwszym „albo" wyklucza, w drugim nie. **W programowaniu `||` jest tym drugim** — nie przeszkadza mu, że prawdziwe są obie rzeczy naraz.

**Czego NIE rób:** nie mów jeszcze „operator logiczny", „koniunkcja", „alternatywa".

## Krok 2 — Mostek (10 min)

**Mostek:**
> „»Oba naraz« zapisuje się dwoma znakami `&&`. »Przynajmniej jeden« — dwoma kreskami `||`. A »nie« — wykrzyknikiem `!` przed warunkiem."

Uczeń tworzy `kurs/zadania/09-logiczne.cs`:

```csharp
int wiek = 20;
bool maBilet = true;

Console.WriteLine(wiek >= 16 && maBilet);
Console.WriteLine(wiek < 16 || maBilet);
Console.WriteLine(!maBilet);
```
→ `True`, `True`, `False`

> „Jakiego typu są te trzy wyniki? Sprawdź przez `GetType()`."
→ znowu `bool`. **Operatory logiczne biorą `bool`-e i oddają `bool`.** To ta sama rodzina co `>` i `==` z lekcji 2.4.

**Teraz to, po co ta lekcja naprawdę jest.** Przypomnij uczniowi zagnieżdżenie z lekcji 4.1:

```csharp
if (ok)
{
    if (rok > 2000)
    {
        Console.WriteLine("Rocznik dwutysięczny");
    }
}
```

i pokaż tę samą rzecz krócej:

```csharp
if (ok && rok > 2000)
{
    Console.WriteLine("Rocznik dwutysięczny");
}
```

> „Dwa poziomy wcięcia zamieniły się w jeden. Który zapis szybciej przeczytasz?"

Teraz nazwij: **operatory logiczne**.

## Krok 3 — Eksperyment (20 min)

### A. Tabelka prawdy — ale zbudowana, nie podana

Uczeń wpisuje cztery kombinacje i **zgaduje przed uruchomieniem**:

```csharp
Console.WriteLine(true  && true);
Console.WriteLine(true  && false);
Console.WriteLine(false && true);
Console.WriteLine(false && false);
```
→ `True`, `False`, `False`, `False`

> „Jednym zdaniem: kiedy `&&` daje prawdę?"
→ tylko gdy **obie** strony są prawdą.

To samo dla `||`:
```csharp
Console.WriteLine(true  || true);
Console.WriteLine(true  || false);
Console.WriteLine(false || true);
Console.WriteLine(false || false);
```
→ `True`, `True`, `True`, `False`

> „A kiedy `||` daje fałsz?"
→ tylko gdy **obie** strony są fałszem.

**Nie każ uczniowi zapamiętywać tabelek.** Ma umieć je odtworzyć zdrowym rozsądkiem: „oba" i „przynajmniej jeden".

### B. Warunek z trzech części

```csharp
Console.Write("Wiek: ");
bool okWiek = int.TryParse(Console.ReadLine(), out int wiek);

if (okWiek && wiek >= 16 && wiek < 120)
{
    Console.WriteLine("Wiek wygląda sensownie.");
}
else
{
    Console.WriteLine("Coś tu nie gra.");
}
```

> „Ile warunków musi być spełnionych, żeby wypisało pierwszą linię? Wpisz 15, potem 200, potem `abc`."

Zwróć uwagę na kolejność: **`okWiek` stoi pierwsze i to nie przypadek.** Wraca w kroku D.

### C. Zaprzeczenie

```csharp
bool pada = false;
if (!pada)
{
    Console.WriteLine("Idziemy na spacer");
}
```

> „Przeczytaj warunek na głos. »Jeśli nie pada«."

Teraz coś trudniejszego — niech uczeń **zgadnie**:
```csharp
bool maBilet = false;
bool pelnoletni = true;
Console.WriteLine(!(maBilet && pelnoletni));
Console.WriteLine(!maBilet || !pelnoletni);
```
→ obie linie dają `True`

> „Dwa różne zapisy, ten sam wynik. Spróbuj powiedzieć po polsku, co znaczy każdy."
→ „nieprawda, że ma bilet i jest pełnoletni" oraz „nie ma biletu albo nie jest pełnoletni". To to samo zdanie.

**Nie nazywaj tego prawem De Morgana** i nie ćwicz przekształceń. Wystarczy, że uczeń zobaczył, że da się to powiedzieć dwojako.

### D. `&&` przestaje liczyć, gdy już wie

To najciekawszy eksperyment lekcji.

```csharp
int zero = 0;
Console.WriteLine(zero != 0 && 10 / zero > 1);
```

> „Popatrz na prawą stronę: `10 / zero`. Dzielenie przez zero — pamiętasz z lekcji 2.4, co robi na liczbach całkowitych?"
→ przewraca program wyjątkiem `DivideByZeroException`.

> „Więc czy ten program się przewróci? Zgadnij, potem uruchom."
→ **nie przewraca się.** Wypisuje `False`.

> „Dlaczego? Lewa strona `zero != 0` jest fałszem. Skoro w `&&` muszą być prawdziwe obie strony, to wynik jest już przesądzony — i C# **nie liczy prawej strony w ogóle**."

To się nazywa **skrócone obliczanie** i ma praktyczne znaczenie:

```csharp
if (okWiek && wiek >= 16)   // bezpieczne
```
> „Gdyby odczyt się nie powiódł, `wiek` byłby zerem — ale prawa strona i tak by się nie policzyła. Dlatego sprawdzenie »czy w ogóle mam dane« stawia się **jako pierwsze**."

`||` działa lustrzanie: gdy lewa strona jest prawdą, prawa nie jest liczona.

### E. Pierwszeństwo — `&&` przed `||`

```csharp
Console.WriteLine(true || false && false);
Console.WriteLine((true || false) && false);
```
→ `True` i `False`

> „Ten sam zestaw wartości, dwa różne wyniki. Co je różni?"
→ nawiasy. Bez nich `&&` liczy się **pierwsze** — jak mnożenie przed dodawaniem.

> **Zasada praktyczna, ta sama co w 2.4:** jeśli musisz się zastanowić, jaka jest kolejność — postaw nawiasy. Kompilatorowi obojętne, czytelnikowi nie.

## Krok 4 — Pogłębienie (10 min)

**Operator warunkowy `?:` — wybór jednej z dwóch wartości**

Uczeń zna już taki zapis:
```csharp
string opis;
if (wiek >= 18)
{
    opis = "pełnoletni";
}
else
{
    opis = "niepełnoletni";
}
```

Sześć linii, żeby wybrać jeden z dwóch tekstów. Krócej:
```csharp
string opis = wiek >= 18 ? "pełnoletni" : "niepełnoletni";
```
→ dla `wiek = 15` wypisze `niepełnoletni`

> „Przeczytaj to na głos: »czy wiek jest co najmniej 18? jeśli tak — pierwsze, jeśli nie — drugie«. Znak zapytania zadaje pytanie, dwukropek rozdziela odpowiedzi."

**Kiedy `?:`, a kiedy `if`?**

| Sytuacja | Zapis |
| --- | --- |
| wybierasz jedną z dwóch **wartości** | `?:` |
| wykonujesz jedną z dwóch **czynności** | `if` |
| gałęzie mają po kilka linii | `if` — zawsze |

> „`?:` to nie skrót od `if`. To wyrażenie, które **daje wartość** — jak `2 + 2`. Dlatego stoi po prawej stronie znaku równości."

**Nie zagnieżdżaj `?:`.** Uczeń szybko wpadnie na `a ? b : c ? d : e`. Powiedz raz: to się da napisać i nie da się przeczytać.

**`== true` jeszcze raz:**
```csharp
if (maBilet == true)   // działa
if (maBilet)           // to samo, krócej
if (!maBilet)          // zamiast maBilet == false
```
> „`maBilet` **jest** odpowiedzią prawda/fałsz. Porównywanie jej z `true` to pytanie »czy to prawda, że prawda«."

**Czego nie da się połączyć:**
```csharp
// if (wiek >= 16 && wiek)     // CS0019: Operator '&&' cannot be applied to operands of type 'bool' and 'int'
// if (16 <= wiek <= 120)      // CS0019: Operator '<=' cannot be applied to operands of type 'bool' and 'int'
```
> „Zapis »od 16 do 120« znany z matematyki w C# nie istnieje. Piszesz `wiek >= 16 && wiek <= 120`."

Warto przeczytać drugi komunikat do końca: `bool` i `int`. C# policzył `16 <= wiek`, dostał `bool`, i próbował porównać **to** ze 120. Nie odrzucił zapisu jako bezsensownego — po prostu zrobił dokładnie to, co napisano, i utknął w połowie.

Ten drugi przypadek warto pokazać, bo uczeń **na pewno** go spróbuje.

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „operatory logiczne". Propozycje:

- 🔥 **Rozgrzewka** (`09-logiczne-a.cs`): zapytaj o wiek i o to, czy ktoś ma bilet (wczytaj tekst i porównaj z `"tak"`). Wypisz `Wpuszczam` tylko wtedy, gdy wiek to co najmniej 16 **i** jest bilet. W przeciwnym razie `Nie wpuszczam`.
- ⭐ **Główne** (`09-logiczne-b.cs`): sprawdzarka hasła. Zapytaj o hasło. Wypisz `Hasło mocne`, gdy ma co najmniej 8 znaków (`haslo.Length >= 8`) **i** nie jest równe `"password"`. W przeciwnym razie wypisz `Hasło słabe`. Dodatkowo, jednym `?:`, wypisz w osobnej linii `Długie` albo `Krótkie`.
- ⚡ **Gwiazdka** (`09-logiczne-c.cs`): rok przestępny. Zapytaj o rok. Rok jest przestępny, gdy dzieli się przez 4 **i** nie dzieli się przez 100 — **albo** gdy dzieli się przez 400. Wypisz odpowiedź jednym zdaniem. Sprawdź na latach 2024, 1900, 2000 i 2023 i powiedz mi wszystkie cztery wyniki.

Gwiazdka to klasyczny warunek, w którym pierwszeństwo `&&` przed `||` ma znaczenie — a `%` uczeń zna z lekcji 2.4. Poprawne wyniki: 2024 tak, 1900 nie, 2000 tak, 2023 nie.

## Pułapki

- **`16 <= wiek <= 120`** — zapis z matematyki, w C# nie działa. Trzeba `wiek >= 16 && wiek <= 120`.
- **Pojedynczy `&` zamiast `&&`** — istnieje i robi coś podobnego, ale **nie skraca obliczania**: policzy obie strony nawet wtedy, gdy wynik jest już przesądzony. Przy `10 / zero` po prawej stronie oznacza to przewrócony program. Uczeń nie potrzebuje `&` w tym kursie; jeśli sam na nie trafi — jedno zdanie i wracacie.
- **`||` mylone z „albo-albo"** — `||` jest prawdą także wtedy, gdy obie strony są prawdą.
- **Brak nawiasów przy mieszaniu `&&` i `||`** — `&&` wiąże mocniej i cicho zmienia sens warunku.
- **Kolejność w `&&`** — sprawdzenie „czy w ogóle mam dane" musi stać pierwsze, inaczej skrócone obliczanie nie uratuje przed błędem.
- **Zagnieżdżony `?:`** — kompiluje się, nie da się czytać.
- **`?:` zamiast `if` przy czynnościach** — `wiek >= 18 ? Console.WriteLine("a") : Console.WriteLine("b");` → `CS0201: Only assignment, call, increment, decrement, await, and new object expressions can be used as a statement`. Komunikat jest długi i nieczytelny, ale sedno jest proste: `?:` **daje wartość**, a wartość trzeba gdzieś włożyć. Tu nie ma gdzie. To dobra okazja, żeby uczeń zobaczył różnicę między wyrażeniem a instrukcją.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Ta lekcja nie ma zmian. `&&`, `||`, `!` i `?:` wyglądają w C# tak samo od początku języka.

Jedna rzecz, której **nie** wprowadzamy: operatory `??` i `?.` (obsługa brakujących wartości). Wyglądają podobnie do `?:` i są zupełnie o czym innym — kurs ich świadomie nie ma, patrz `INDEX.md`.

## Notatki tutora

- **Krok 3.D (skrócone obliczanie) to serce lekcji.** Uczeń widzi program, który **powinien** się przewrócić i nie przewraca się. Bez tego eksperymentu kolejność w `&&` zostaje regułą do zapamiętania zamiast czegoś, co ma powód.
- **Nie wprowadzaj pojedynczego `&`** jako materiału. Jest w Pułapkach dla ciebie, na wypadek gdyby uczeń sam trafił.
- **Nie nazywaj praw De Morgana.** Krok 3.C pokazuje zjawisko; nazwa i przekształcenia to matematyka, nie ta lekcja.
- **Nie wprowadzaj `switch`** — to następna lekcja, 4.3. Przy dłuższym łańcuchu warunków pokusa będzie duża.
- **Nie wprowadzaj pętli.** Rok przestępny w gwiazdce uczeń sprawdza, uruchamiając program cztery razy ręcznie. To celowe: pętle to moduł 5.
- **`haslo.Length` w ćwiczeniu ⭐ jest nowe**, ale nie wymaga tłumaczenia: „`.Length` mówi, ile znaków ma tekst". Jedno zdanie. Właściwości poznaje w module 8; dziś to tylko narzędzie.
- Jeśli uczeń pisze `if (x == true)` — powiedz raz i odpuść. To kwestia stylu; walka o nią kosztuje więcej, niż daje.
