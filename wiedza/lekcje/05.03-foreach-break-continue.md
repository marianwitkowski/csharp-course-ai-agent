# Lekcja 5.3 — `foreach`, `break` i `continue`

## Cel
Po lekcji uczeń:
- Przechodzi po znakach tekstu przez `foreach`, bez indeksu
- Wie, kiedy `foreach` jest czytelniejszy od `for`, a kiedy nie wystarczy
- Przerywa pętlę przez `break` i pomija jeden obieg przez `continue`
- Wie, że zmiennej z `foreach` nie da się zmienić — i czemu
- Umie zapisać „pętla bez z góry znanego końca" jako `while (true)` z `break`

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Masz w ręku plik kartek i musisz przejrzeć każdą. Czy do tego potrzebujesz numerów stron?"

**Co chcesz usłyszeć:** nie — bierzesz po kolei, aż się skończą.

**Drugie pytanie:**
> „A kiedy numer strony **byłby** ci potrzebny?"

**Co chcesz usłyszeć:** gdybyś chciał powiedzieć „na której stronie to znalazłem", albo porównać stronę trzecią z siódmą.

**To jest cała różnica między `foreach` a `for`** — nie nazywaj jej jeszcze.

**Trzecie pytanie:**
> „Przeglądasz kartki, szukając jednej konkretnej. Znajdujesz ją na trzeciej. Co robisz z resztą?"

**Co chcesz usłyszeć:** przestajesz przeglądać. To `break`.

## Krok 2 — Mostek (10 min)

**Mostek:**
> „Gdy chcesz przejść po **wszystkim po kolei**, a numery nie są ci potrzebne, C# ma na to krótszą pętlę: `foreach`."

Zacznij od tego, co uczeń zna — `for` po znakach tekstu:

```csharp
string imie = "Anna";

for (int i = 0; i < imie.Length; i++)
{
    Console.WriteLine(imie[i]);
}
```
→ `A`, `n`, `n`, `a`

> „`imie.Length` to liczba znaków — znasz z ćwiczenia w 4.2. `imie[i]` to znak numer `i`, licząc **od zera**."

Teraz to samo przez `foreach`:

```csharp
foreach (char znak in "Anna")
{
    Console.WriteLine(znak);
}
```
→ ten sam wynik.

**Pytania:**
- „Co zniknęło z nagłówka?" → licznik, warunek, krok, indeksowanie — **wszystko**
- „Skąd `foreach` wie, kiedy skończyć?" → sam dochodzi do końca tekstu
- „Jakiego typu jest `znak`?" → `char`, czyli pojedynczy znak. Wzmiankowany w lekcji 2.1, teraz jest potrzebny.

Nazwij: **`foreach`** — „dla każdego". Czyta się dosłownie: „dla każdego znaku w słowie Anna".

> **Tekst jest ciągiem znaków** i to pierwsza rzecz w kursie, po której da się przejść pętlą. W module 6 dojdą kolekcje i `foreach` będzie działał na nich dokładnie tak samo.

## Krok 3 — Eksperyment (20 min)

### A. Policz coś w tekście

```csharp
Console.Write("Podaj zdanie: ");
string zdanie = Console.ReadLine();

int spacje = 0;

foreach (char znak in zdanie)
{
    if (znak == ' ')
    {
        spacje = spacje + 1;
    }
}

Console.WriteLine($"Spacji: {spacje}, czyli słów mniej więcej: {spacje + 1}");
```

> „Zwróć uwagę na `' '` — apostrofy, nie cudzysłowy. To pojedynczy znak, nie tekst. Pamiętasz różnicę z lekcji 2.1?"

Uczeń sprawdza na zdaniu z podwójną spacją i na pustym wejściu.

### B. Zmiennej z `foreach` nie da się zmienić

```csharp
foreach (char znak in "abc")
{
    znak = 'x';
}
```
→ `CS1656: Cannot assign to 'znak' because it is a 'foreach iteration variable'`

> „Co C# ci mówi? I czemu tak jest?"
→ `foreach` **pokazuje** ci kolejne elementy; nie daje ich do przerabiania. Gdybyś chciał coś zmieniać, potrzebujesz `for` z indeksem.

To jest praktyczna granica `foreach`: **do oglądania tak, do zmieniania nie.**

### C. `break` — przerwij, gdy już wiesz

```csharp
Console.Write("Podaj słowo: ");
string slowo = Console.ReadLine();

bool maCyfre = false;

foreach (char znak in slowo)
{
    if (znak >= '0' && znak <= '9')
    {
        maCyfre = true;
        break;
    }
}

Console.WriteLine($"Czy zawiera cyfrę: {maCyfre}");
```

> „Po co tu `break`? Co by się zmieniło w **wyniku**, gdybyś go usunął?"
→ nic. Zmieniłaby się tylko liczba obiegów: bez `break` pętla przeszłaby cały tekst, choć odpowiedź była znana po pierwszej cyfrze.

> „Kiedy to ma znaczenie?"
→ gdy tekst ma milion znaków, a cyfra jest druga.

### D. `continue` — pomiń ten jeden

```csharp
foreach (char znak in "a1b2c3")
{
    if (znak >= '0' && znak <= '9')
    {
        continue;
    }
    Console.Write(znak);
}
Console.WriteLine();
```
→ `abc`

> „Czym `continue` różni się od `break`?"
→ `break` **kończy** pętlę, `continue` kończy **jeden obieg** i przechodzi do następnego.

Uczeń zamienia `continue` na `break` i porównuje wyniki: `a` zamiast `abc`.

### E. `while (true)` z `break` — pętla bez warunku w nagłówku

Wróć do zgadywanki z ćwiczenia lekcji 5.1 i pokaż drugi sposób zapisu:

```csharp
int sekret = 7;
int proby = 0;

while (true)
{
    Console.Write("Zgadnij liczbę: ");
    bool ok = int.TryParse(Console.ReadLine(), out int strzal);
    proby++;

    if (!ok)
    {
        Console.WriteLine("To nie jest liczba.");
        continue;
    }

    if (strzal == sekret)
    {
        break;
    }

    Console.WriteLine(strzal < sekret ? "Za mało" : "Za dużo");
}

Console.WriteLine($"Trafione w {proby} próbach.");
```

> „`while (true)` znaczy »powtarzaj zawsze«. Co w takim razie kończy tę pętlę?"
→ wyłącznie `break`.

> „Czy to lepsze od wersji z flagą `ok` z lekcji 5.1?"

Nie ma jednej odpowiedzi i warto to powiedzieć wprost: `while (true)` z `break` bywa czytelniejsze, gdy wyjść jest kilka albo warunek wyjścia jest w środku obiegu. Ale łatwo o pętlę, z której nie ma wyjścia. **Zawsze sprawdź, czy `break` jest osiągalny.**

Zwróć uwagę na `?:` w przedostatniej linii — to operator warunkowy z lekcji 4.2, użyty dokładnie tam, gdzie ma sens: wybór jednej z dwóch **wartości**.

## Krok 4 — Pogłębienie (10 min)

**`foreach` czy `for`? Reguła praktyczna:**

| Sytuacja | Pętla |
| --- | --- |
| przejrzeć wszystko po kolei | `foreach` |
| potrzebujesz numeru elementu | `for` |
| chcesz **zmieniać** elementy | `for` |
| co drugi, od końca, część zakresu | `for` |
| nie wiesz, ile razy | `while` |

> „`foreach` jest krótszy i trudniej się w nim pomylić — nie ma licznika, więc nie ma pomyłki o jeden. Wybieraj go, gdy pasuje."

**`break` w zagnieżdżonych pętlach:**
```csharp
for (int i = 1; i <= 3; i++)
{
    for (int j = 1; j <= 3; j++)
    {
        if (j == 2) { break; }
        Console.Write($"{i}-{j} ");
    }
}
```
→ `1-1 2-1 3-1`

> „`break` przerwał którą pętlę — wewnętrzną czy obie?"
→ **tylko wewnętrzną.** Zewnętrzna leci dalej. To zaskakuje i warto sprawdzić samemu.

**Indeks w `foreach` — czego nie ma:**
> „`foreach` nie daje ci numeru elementu. Jeśli go potrzebujesz, masz dwa wyjścia: wrócić do `for` albo prowadzić własny licznik obok."

```csharp
int numer = 0;
foreach (char znak in "abc")
{
    Console.WriteLine($"{numer}: {znak}");
    numer++;
}
```
> „To działa, ale jeśli robisz tak często — `for` jest po prostu właściwszym narzędziem."

**Pusty tekst:**
```csharp
foreach (char znak in "")
{
    Console.WriteLine("nigdy");
}
```
> „Ile razy wykona się wnętrze?"
→ zero. `foreach` po pustej sekwencji nie wykonuje się ani razu — tak samo jak `while` z fałszywym warunkiem.

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „`foreach`, `break`, `continue`". Propozycje:

- 🔥 **Rozgrzewka** (`13-foreach-a.cs`): zapytaj o słowo. Wypisz każdą jego literę w osobnej linii, a na końcu podaj, ile ich było — licząc samodzielnie w pętli, **nie** przez `.Length`.
- ⭐ **Główne** (`13-foreach-b.cs`): policz samogłoski. Zapytaj o zdanie i policz, ile zawiera samogłosek (`a e i o u y`, wystarczy małe litery). Wypisz liczbę oraz — w drugiej linii — samo zdanie bez samogłosek, używając `continue`.
- ⚡ **Gwiazdka** (`13-foreach-c.cs`): sprawdzarka hasła. Zapytaj o hasło i sprawdź trzy rzeczy naraz, jednym przejściem pętli: czy zawiera cyfrę, czy zawiera wielką literę (`znak >= 'A' && znak <= 'Z'`), czy ma co najmniej 8 znaków. Wypisz trzy linie z odpowiedziami `True`/`False` i czwartą: `Hasło mocne` tylko wtedy, gdy wszystkie trzy warunki są spełnione. Użyj `break`, gdy wszystkie trzy są już znane — i powiedz mi, czy dało się to zrobić sensownie.

Gwiazdka ma haczyk: `break` przy trzech warunkach naraz wymaga sprawdzenia, czy **wszystkie** są już prawdziwe — co samo w sobie jest warunkiem z `&&` z lekcji 4.2. Jeśli uczeń uzna, że `break` się tu nie opłaca, to **dobra odpowiedź**, byle uzasadniona.

## Pułapki

- **Cudzysłowy zamiast apostrofów przy znaku** — `znak == "a"` nie skompiluje się (`CS0019`), bo to porównanie `char` z `string`. Pojedynczy znak zapisuje się `'a'`.
- **Próba zmiany zmiennej `foreach`** → `CS1656`. Do zmieniania potrzebny `for`.
- **`break` przerywa tylko najbliższą pętlę** — przy zagnieżdżeniu zewnętrzna leci dalej.
- **`continue` w `while` bez zmiany licznika** → pętla nieskończona, bo `continue` przeskakuje także zwiększanie licznika. W `for` tego problemu nie ma — krok wykonuje się zawsze.
- **`while (true)` bez osiągalnego `break`** — pętla nieskończona. Sprawdź, czy jest wyjście.
- **Licznik obok `foreach`** — działa, ale jeśli jest potrzebny, właściwym narzędziem jest `for`.
- **Wielkość liter przy porównywaniu znaków** — `'A'` i `'a'` to różne znaki. Widoczne w ćwiczeniu ⚡.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Ta lekcja nie ma zmian. `foreach`, `break` i `continue` wyglądają w C# tak samo od pierwszej wersji języka.

## Notatki tutora

- **Krok 2 musi zacząć się od `for` po znakach**, żeby uczeń zobaczył, co `foreach` upraszcza. Pokazany od razu, wygląda na kolejną pętlę do zapamiętania.
- **Nie wprowadzaj tablic ani list.** To największa pokusa tej lekcji — `foreach` naturalnie chodzi z kolekcjami. Wytrzymaj: tekst wystarczy, a moduł 6 jest zaraz po i wtedy `foreach` będzie już znany.
- **Nie tłumacz `IEnumerable`** ani tego, co dokładnie `foreach` robi pod spodem. „Sam dochodzi do końca" wystarcza do modułu 10.
- **Krok 4 z `break` w zagnieżdżeniu warto zrobić przez zgadywanie.** Większość początkujących obstawia, że `break` wychodzi z obu pętli.
- **Nie pokazuj `goto`** ani etykietowanego wyjścia z zagnieżdżenia. Jeśli uczeń pyta, jak wyjść z obu naraz — „da się, ale zwykle znaczy to, że kod prosi się o metodę; moduł 7".
- **Ćwiczenie ⚡ ma otwartą odpowiedź.** Uczeń, który uzasadni, że `break` się tam nie opłaca, rozumie więcej niż ten, który go wciśnie na siłę. Doceń to.
