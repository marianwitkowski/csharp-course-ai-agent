# Lekcja 15.1 — `Task`, `async` i `await`

> **Moduł 15 to dodatek po kursie.** Uczeń ma skończony projekt i wie z 14.7, że `async`/`await` czeka na niego pierwszego dnia z ASP.NET Core. Te dwie lekcje dają mu podstawy w tym samym stylu co reszta kursu: na plikach, bez sieci, z eksperymentami, w których kod robi coś innego, niż się wydaje.

## Cel
Po lekcji uczeń:
- Czyta nagłówek `async Task<int> Policz(...)` i wie, co obiecuje
- Pisze metodę z `await` i wywołuje ją z `await`
- Rozpoznaje dwa błędy: brak `await` (`CS4014`) i `await` bez `async` (`CS4032`)
- Wie, że `await` **nie przyspiesza** operacji — pozwala nie stać w miejscu, gdy ona trwa
- Obsługuje wyjątek z operacji asynchronicznej zwykłym `try`/`catch`

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Kelner zaniósł twoje zamówienie do kuchni. Kucharz potrzebuje dwudziestu minut. Co robi kelner przez te dwadzieścia minut — stoi pod drzwiami kuchni?"

**Co chcesz usłyszeć:** nie — obsługuje inne stoliki. Wróci po danie, gdy będzie gotowe.

**Drugie pytanie:**
> „Czy danie przez to będzie gotowe szybciej?"

**Co chcesz usłyszeć:** nie. Kuchnia pracuje tyle samo. Zyskują **inne stoliki**, nie to zamówienie.

> „Zapamiętaj oba wnioski. Cała dzisiejsza lekcja to kelner, który nie stoi pod drzwiami — i który przez to niczego nie przyspiesza."

## Krok 2 — Mostek (10 min)

**Mostek:**
> „Czytanie pliku, zapis, sieć — to operacje, w których program **czeka na coś spoza siebie**: dysk, kabel, serwer. W C# taka operacja może zamiast wyniku oddać **`Task`** — obietnicę, że wynik będzie. `await` znaczy: »zaczekaj na obietnicę, ale nie stój bezczynnie«."

Uczeń tworzy `kurs/zadania/41-async.cs` i obok plik `a.txt` z trzema liniami tekstu:

```csharp
string tresc = await File.ReadAllTextAsync("a.txt");
Console.WriteLine(tresc.Length);
```
→ liczba znaków w pliku (dla trzech linii `linia 1`, `linia 2`, `linia 3` — `24`).

> „Czym to się różni od `File.ReadAllText` z lekcji 12.1?"
→ z zewnątrz **niczym**. Ten sam wynik. Różnica jest w tym, co program robił, **gdy** dysk pracował — i przy jednym małym pliku jej nie widać.

Nazwij: **`Task`** (obietnica wyniku), **`await`** (czekaj bez blokowania), **operacja asynchroniczna**. Metody z `Async` na końcu nazwy zwracają `Task` — to konwencja całej biblioteki .NET.

> „`await` na najwyższym poziomie pliku działa od razu. Za chwilę zobaczysz, że w **metodzie** wymaga jednego słowa więcej."

## Krok 3 — Eksperyment (22 min)

### A. Własna metoda asynchroniczna

```csharp
int n = await PoliczLinie("a.txt");
Console.WriteLine(n);

async Task<int> PoliczLinie(string plik)
{
    string[] linie = await File.ReadAllLinesAsync(plik);
    return linie.Length;
}
```
→ `3`

**Rozbierz nagłówek pytaniami:**
- „`Task<int>` — co metoda oddaje?" → obietnicę liczby, nie liczbę
- „`return linie.Length` — a tu oddajesz liczbę. Sprzeczność?" → nie: `async` opakowuje ją w `Task<int>` za ciebie
- „`async` przed typem — po co?" → to **pozwolenie na `await` w środku**. Bez niego `await` nie skompiluje się (krok C)

> „Dwie rzeczy do zapamiętania: `async` w nagłówku, `await` przy każdej operacji, która zwraca `Task`."

### B. Zapomniany `await` — kod, który działa źle

```csharp
Console.WriteLine(PoliczLinie("a.txt"));
```
→ kompilator ostrzega:
```
warning CS4014: Because this call is not awaited, execution of the current method continues before the call is completed. Consider applying the 'await' operator to the result of the call.
```
→ a program wypisuje **długi napis z nazwą typu** (coś w rodzaju `System.Runtime.CompilerServices.AsyncTaskMethodBuilder…Task…Int32…`) zamiast `3`.

> „Co wypisałeś?"
→ **obietnicę**, nie wynik. `Console.WriteLine` dostał `Task<int>` i wypisał jego nazwę.

> „Kompilator ostrzegł. Które słowo w ostrzeżeniu jest najważniejsze?"
→ `continues before the call is completed` — program **poszedł dalej, nie czekając**. Tak wygląda najczęstszy błąd asynchroniczności: kod się kompiluje, działa, a wynik jest bzdurą.

### C. `await` bez `async` — kompilator nie pozwoli

```csharp
int PoliczLinie(string plik)
{
    string[] linie = await File.ReadAllLinesAsync(plik);
    return linie.Length;
}
```
→
```
error CS4032: The 'await' operator can only be used within an async method. Consider marking this method with the 'async' modifier and changing its return type to 'Task<int>'.
```

> „Przeczytaj do końca. Co kompilator każe zrobić?"
→ dopisać `async` **i** zmienić `int` na `Task<int>`. Komunikat podaje gotowe rozwiązanie — to jeden z najbardziej pomocnych błędów w C#.

### D. Metoda bez wyniku — `Task` zamiast `void`

```csharp
await Zapisz("d.txt");
Console.WriteLine(File.ReadAllText("d.txt"));

async Task Zapisz(string plik)
{
    await File.WriteAllTextAsync(plik, "zapisane\n");
}
```
→ `zapisane`

> „`Zapisz` niczego nie zwraca. Czemu nagłówek mówi `Task`, a nie `void`?"
→ bo `Task` bez `<int>` to obietnica, że **operacja się skończy** — i tylko na taką da się zaczekać `await`. `async void` istnieje, ale nie da się na nie czekać; w tym kursie go nie ma.

### E. Wyjątek przechodzi przez `await`

```csharp
try
{
    string t = await File.ReadAllTextAsync("nie-ma.txt");
}
catch (FileNotFoundException e)
{
    Console.WriteLine("Brak pliku: " + Path.GetFileName(e.FileName));
}
```
→ `Brak pliku: nie-ma.txt`

> „Czy `try`/`catch` z lekcji 11.1 zmienił się przez `await`?"
→ nie. Wyjątek z operacji asynchronicznej wyskakuje **w miejscu `await`** i łapie go zwykły `catch`.

### F. `await` nie przyspiesza — pomiar

Nowe narzędzie, jedno zdanie: `System.Diagnostics.Stopwatch` mierzy czas; `StartNew()` uruchamia, `ElapsedMilliseconds` odczytuje. Szczegóły w dokumentacji, jak w 14.3.

```csharp
var zegar = System.Diagnostics.Stopwatch.StartNew();
await Task.Delay(1000);
await Task.Delay(1000);
await Task.Delay(1000);
Console.WriteLine($"{zegar.ElapsedMilliseconds} ms");
```
→ około `3012 ms` (u ciebie kilkanaście ms więcej lub mniej).

> „`Task.Delay(1000)` to obietnica »za sekundę skończę«. Trzy takie po kolei — ile czasu?"
→ trzy sekundy. **`await` nie przyspiesza niczego** — to kelner z kroku 1: nie stoi pod drzwiami, ale kuchnia pracuje tyle samo.

> „Więc co zyskaliśmy?"
→ przy jednym programie w konsoli — na razie nic widocznego. Zysk pojawia się, gdy **kilka** operacji może czekać naraz. To lekcja 15.2.

## Krok 4 — Pogłębienie (8 min)

**Asynchroniczność to nie wielowątkowość**

> „Ilu kelnerów obsługuje stoliki w kroku 1?"
→ **jeden**. Nie zatrudniliśmy trzech; jeden przestał stać pod drzwiami. `async`/`await` nie tworzy nowych wątków — pozwala jednemu nie marnować czasu na czekanie. Wielowątkowość (kilku kucharzy naraz) to osobny temat, poza kursem.

**Trzy reguły na resztę życia z `async`**

| Reguła | Dlaczego |
| --- | --- |
| Metoda z `await` w środku ma `async` i zwraca `Task` albo `Task<T>` | krok C — kompilator i tak tego wymaga |
| Każde wywołanie metody zwracającej `Task` ma przed sobą `await` | krok B — bez tego dostajesz obietnicę zamiast wyniku |
| Nazwa metody asynchronicznej kończy się na `Async` | konwencja biblioteki: `ReadAllTextAsync`, `WriteAllTextAsync`; w projekcie trzymaj się jej |

**`.Result` — istnieje, nie używaj**

```csharp
int n = PoliczLinie("a.txt").Result;
```
→ w konsoli wypisze `3`. Ale `.Result` **blokuje** — to kelner, który jednak stoi pod drzwiami. W aplikacji z oknem albo na serwerze potrafi zawiesić cały program. Zobaczysz to w cudzym kodzie; sam pisz `await`.

**Skąd `Task.Delay` w prawdziwym kodzie**

> „`Task.Delay` udaje wolną operację — dysk, sieć. W lekcji 15.2 użyjemy go, żeby **zobaczyć** różnicę między czekaniem po kolei a czekaniem naraz, bo trzy małe pliki czytają się za szybko, żeby cokolwiek zmierzyć."

## Pułapki

- **Brak `await` przy wywołaniu** → `CS4014` i obietnica zamiast wyniku. Najczęstszy błąd; kompilator ostrzega, ale nie zatrzymuje.
- **`await` w metodzie bez `async`** → `CS4032`. Komunikat podaje rozwiązanie.
- **`void` zamiast `Task`** — nie da się zaczekać na taką metodę; wyjątek z niej wywraca program w nieoczekiwanym miejscu. Zawsze `Task`.
- **`.Result` albo `.Wait()`** — blokują. W konsoli niegroźne, gdzie indziej zawieszają program.
- **Oczekiwanie, że `await` przyspieszy** — nie przyspiesza. Krok F.
- **Metoda `async` bez ani jednego `await`** — kompiluje się i działa synchronicznie; `async` nic wtedy nie robi. Jeśli nie ma na co czekać, nie pisz `async`.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Sekcja `[moduł 15]`. Starsze materiały (przed C# 5, czyli przed 2012) robiły to samo inaczej i uczeń trafi na to w poradnikach:

| Stare materiały | Dzisiaj |
| --- | --- |
| `new Thread(...)`, `BackgroundWorker` | `async`/`await` — bez ręcznego zarządzania wątkami |
| `.ContinueWith(t => ...)` łańcuchy | `await` — ten sam efekt, czytelny jak zwykły kod |
| `Task.Run(() => File.ReadAllText(...))` | `File.ReadAllTextAsync` — biblioteka ma wersje `Async` dla operacji na dysku i sieci |
| `.Result` / `.Wait()` „żeby było prościej" | `await` od góry do dołu, także na najwyższym poziomie pliku (C# 7.1) |

> „`Task.Run` ma swoje miejsce — dla obliczeń, które **liczą**, a nie **czekają**. To poza kursem; dla dysku i sieci zawsze wersja `Async`."

## Notatki tutora

- **Krok 1 ustawia dwa wnioski i oba muszą paść:** kelner nie stoi pod drzwiami **i** danie nie jest szybciej. Bez drugiego uczeń wychodzi z przekonaniem, że `await` = szybciej, i krok F go zaskoczy w złą stronę.
- **Krok B jest sercem lekcji** — kod, który kompiluje się, działa i wypisuje bzdurę. Niech uczeń sam usunie `await` i zobaczy napis zamiast liczby. To ten sam typ zaskoczenia co `7 / 2` w 2.1.
- **Nie tłumacz maszyny stanów, kontekstu synchronizacji ani `ConfigureAwait`.** „Kelner nie stoi pod drzwiami" wystarcza na cały moduł.
- **Nie wprowadzaj `Task.Run`, `Parallel`, `Thread`, `lock`, `CancellationToken`.** Jedno zdanie o `Task.Run` jest w Aktualizacji; reszta poza kursem.
- **Nie wprowadzaj `IAsyncEnumerable` ani `await foreach`.**
- **Czasy z `Stopwatch` różnią się między komputerami** — porównuj rząd wielkości (3000 kontra 1000), nie dokładne liczby.
- Jeśli uczeń pyta, czemu `dotnet run plik.cs` pozwala na `await` bez żadnej metody — „instrukcje najwyższego poziomu są asynchroniczne, gdy w środku jest `await`; kompilator dopisuje `async Task Main` za ciebie", jedno zdanie.
- Jeśli uczeń pyta o `async void` — „tylko do zdarzeń w aplikacjach z oknami; w tym kursie nie ma ani jednego".
