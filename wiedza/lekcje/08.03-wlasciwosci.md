# Lekcja 8.3 — Właściwości

## Cel
Po lekcji uczeń:
- Zamienia pole na właściwość automatyczną `{ get; set; }`
- Pisze właściwość z własnym `set`, który sprawdza wartość
- Tworzy właściwość tylko do odczytu (`{ get; private set; }`)
- Wie, czemu w C# prawie zawsze pisze się właściwości zamiast pól publicznych
- Rozpoznaje `CS0272` (próba zapisu do właściwości bez dostępnego `set`)

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Licznik kilometrów w samochodzie. Możesz go **odczytać**. Czy możesz go **ustawić** na dowolną liczbę?"

**Co chcesz usłyszeć:** nie — i to jest celowe.

**Drugie pytanie:**
> „Czemu producent tak to zrobił? Komu to przeszkadza, a komu pomaga?"

**Co chcesz usłyszeć:** utrudnia oszustwo przy sprzedaży. **Ograniczenie chroni dane przed niesensownymi wartościami.**

**Trzecie pytanie:**
> „A termostat? Temperaturę **ustawiasz** — ale czy da się ustawić minus tysiąc stopni?"

**Co chcesz usłyszeć:** nie, urządzenie na to nie pozwoli. **To jest właściwość ze sprawdzaniem** — nie nazywaj jeszcze.

## Krok 2 — Mostek (12 min)

Przypomnij kota z lekcji 8.2 i pokaż problem:

```csharp
Kot mruczek = new Kot("Mruczek", 3);
mruczek.Wiek = -500;
Console.WriteLine(mruczek);
```
→ `Mruczek (-500 lat)`

> „W lekcji 8.2 konstruktor sprawdzał wiek i poprawiał ujemny na zero. Zadziałało?"
→ **nie** — bo konstruktor pilnuje tylko **momentu tworzenia**. Potem pole jest otwarte dla każdego.

> „Więc do czego było to sprawdzanie w konstruktorze?"
→ pilnowało jednego wejścia. Ale wejść jest więcej.

**Mostek:**
> „Pole, do którego dostęp przechodzi przez twój kod, nazywa się **właściwością**. Wygląda jak pole, ale możesz decydować, co się dzieje przy odczycie i przy zapisie."

Najprostsza postać — **właściwość automatyczna**:

```csharp
class Kot
{
    public string Imie { get; set; }
    public int Wiek { get; set; }

    public Kot(string imie, int wiek)
    {
        Imie = imie;
        Wiek = wiek;
    }

    public override string ToString() => $"{Imie} ({Wiek} lat)";
}
```

> „Co się zmieniło w porównaniu z polem? Czy kod, który używa kota, wymaga poprawek?"
→ zmienił się tylko `{ get; set; }` w klasie. **Użycie wygląda identycznie** — `mruczek.Wiek = 3` nadal działa.

Nazwij: **właściwość**, **`get`** (odczyt), **`set`** (zapis).

> **To jest domyślna forma w C#.** Od tej lekcji pola publiczne znikają z twojego kodu; zostają właściwości.

## Krok 3 — Eksperyment (25 min)

### A. `set`, który sprawdza

Właściwość automatyczna niczego jeszcze nie pilnuje. Rozwiń ją:

```csharp
class Kot
{
    private int wiek;

    public int Wiek
    {
        get { return wiek; }
        set
        {
            if (value < 0)
            {
                wiek = 0;
            }
            else
            {
                wiek = value;
            }
        }
    }
}
```

```csharp
Kot k = new Kot();
k.Wiek = -500;
Console.WriteLine(k.Wiek);
```
→ `0`

> „Skąd wzięło się słowo `value`? Nigdzie go nie zadeklarowałeś."
→ to **wartość podana przy przypisaniu**. C# wstawia ją automatycznie w `set`.

> „Co to jest `private int wiek` z małej litery?"
→ **prawdziwe miejsce**, w którym leży liczba. Właściwość to brama; pole jest magazynem.

Nazwij: **pole zaplecza** (pisane `camelCase` i `private`), **`value`**.

> „Zwróć uwagę: właściwość `Wiek` i pole `wiek` różnią się tylko wielkością pierwszej litery. To standardowa konwencja C# i teraz widać, po co ona jest."

### B. Właściwość automatyczna to skrót

```csharp
public int Wiek { get; set; }
```
> „Ta jedna linia robi dokładnie to samo, co pole zaplecza plus `get` zwracający je i `set` przypisujący. C# pisze to za ciebie."

> „Kiedy więc pisać pełną wersję?"
→ **tylko wtedy, gdy `get` albo `set` mają robić coś więcej** niż zwykły odczyt i zapis.

To ważne, żeby uczeń nie zaczął rozpisywać wszystkiego ręcznie.

### C. Tylko do odczytu — licznik z kroku 1

> **`decimal` wraca z lekcji 2.1** — tam uczeń zobaczył, że `0.1 + 0.2` w `double` daje `0,30000000000000004`. Saldo konta to kwota, więc `decimal`. Przypomnij jednym zdaniem: literał z przecinkiem wymaga przyrostka `m` (`19.99m`), liczby całkowite (`500`) piszesz bez przyrostka.

```csharp
class Konto
{
    public string Wlasciciel { get; set; }
    public decimal Saldo { get; private set; }

    public Konto(string wlasciciel)
    {
        Wlasciciel = wlasciciel;
        Saldo = 0;
    }

    public void Wplac(decimal kwota)
    {
        if (kwota > 0)
        {
            Saldo = Saldo + kwota;
        }
    }
}
```

```csharp
Konto k = new Konto("Ala");
k.Wplac(100);
Console.WriteLine($"{k.Wlasciciel}: {k.Saldo}");

k.Saldo = 1000000;
```
→ najpierw `Ala: 100`, a ostatnia linia:
```
CS0272: The property or indexer 'Konto.Saldo' cannot be used in this context because the set accessor is inaccessible
```

> „Przeczytaj komunikat: »zapis jest niedostępny«. Co to znaczy dla kogoś, kto używa twojej klasy?"
→ saldo da się **odczytać**, ale zmienić tylko przez `Wplac`.

**To jest licznik kilometrów z kroku 1.** Wartość jest widoczna, ale nie da się jej ustawić z palca.

> „Czy `Wplac` może zmienić `Saldo`, skoro `set` jest prywatny?"
→ tak — `private` znaczy „tylko z wnętrza tej klasy", a `Wplac` jest w środku.

### D. Właściwość liczona — bez własnego pola

```csharp
class Prostokat
{
    public double Szerokosc { get; set; }
    public double Wysokosc { get; set; }

    public double Pole
    {
        get { return Szerokosc * Wysokosc; }
    }
}
```

```csharp
Prostokat p = new Prostokat();
p.Szerokosc = 3;
p.Wysokosc = 4;
Console.WriteLine(p.Pole);
p.Szerokosc = 10;
Console.WriteLine(p.Pole);
```
→ `12` i `40`

> „Gdzie przechowywane jest pole prostokąta?"
→ **nigdzie.** Liczy się przy każdym odczycie.

> „Co by się stało, gdyby `Pole` było zwykłą właściwością z `set`, ustawianą raz w konstruktorze?"
→ po zmianie szerokości pokazywałoby starą wartość. **Wartość liczona nie może się rozjechać z danymi.**

Krócej, wyrażeniem:
```csharp
public double Pole => Szerokosc * Wysokosc;
```
> „Ta sama strzałka co przy metodach jednowyrażeniowych z 7.1."

### E. Właściwość, która coś robi przy odczycie

```csharp
public string Opis
{
    get
    {
        Console.WriteLine("(ktoś odczytał opis)");
        return $"{Imie}, {Wiek} lat";
    }
}
```

> „Czy widać z zewnątrz, że odczyt czegoś dotyka?"
→ nie. Z zewnątrz `kot.Opis` wygląda jak zwykłe pole.

**To jest jednocześnie siła i pułapka właściwości.** Zasada: `get` powinien być **szybki i bez skutków ubocznych**. Jeśli coś ma zajmować czas albo zmieniać stan — niech to będzie metoda, nie właściwość.

## Krok 4 — Pogłębienie (10 min)

**Właściwość czy metoda?**

| Sytuacja | Wybór |
| --- | --- |
| odczyt cechy obiektu | właściwość |
| wartość liczona szybko z innych cech | właściwość (`Pole`) |
| czynność, która coś zmienia | metoda (`Wplac`) |
| coś, co może potrwać albo się nie udać | metoda |

> „Reguła praktyczna: właściwość odpowiada na pytanie »jaki jesteś«, metoda wykonuje polecenie »zrób coś«."

**Wartość początkowa właściwości**

```csharp
public string Imie { get; set; } = "bezimienny";
```
> „Bez tego właściwość tekstowa startuje jako `null` — pamiętasz z lekcji 8.1."

**Właściwość tylko do odczytu, ustawiana raz**

```csharp
public string Imie { get; }
```
> „Taką właściwość da się ustawić **wyłącznie w konstruktorze**. Potem jest zamrożona — nawet dla kodu wewnątrz klasy."

Pokaż różnicę:

| Zapis | Zapis z zewnątrz | Zapis z wnętrza klasy |
| --- | --- | --- |
| `{ get; set; }` | ✅ | ✅ |
| `{ get; private set; }` | ❌ | ✅ |
| `{ get; }` | ❌ | tylko w konstruktorze |

**Czemu nie pola publiczne?**

Zbierz trzy powody, które uczeń już zobaczył:
1. **kontrola** — `set` może odrzucić bzdurę (krok 3.A)
2. **tylko do odczytu** — pole tego nie potrafi (krok 3.C)
3. **wartość liczona** — pole musiałoby być aktualizowane ręcznie (krok 3.D)

I czwarty, którego jeszcze nie widział:
4. **zmiana bez psucia cudzego kodu** — pole zamienione na właściwość zmusiłoby wszystkich do przepisania kodu; właściwość od początku daje swobodę

> „Dlatego w C# konwencja jest prosta: **publiczne są właściwości, pola są prywatne.**"

**Zapowiedź:** w module 12 uczeń zapisze obiekt do pliku JSON. Warto wspomnieć jednym zdaniem: „`System.Text.Json` zapisuje **właściwości**, nie pola — to kolejny praktyczny powód".

## Pułapki

- **Zapis do właściwości bez dostępnego `set`** → `CS0272`.
- **Pole zaplecza o tej samej nazwie co właściwość** — `public int Wiek { get { return Wiek; } }` woła samo siebie w nieskończoność i program się przewraca (przepełnienie stosu). Pole zaplecza pisz `camelCase`.
- **Właściwość automatyczna ze sprawdzaniem** — `{ get; set; }` **niczego nie sprawdza**. Do sprawdzania potrzebna pełna forma.
- **Wartość liczona zapisana w polu** — rozjeżdża się z danymi po zmianie składników. Licz w `get`.
- **Ciężki `get`** — właściwość wygląda jak pole, więc nikt się nie spodziewa, że odczyt trwa. Ciężkie rzeczy rób metodą.
- **Właściwość tekstowa bez wartości początkowej** — startuje jako `null`, jak pole w 8.1.
- **Mieszanie pól publicznych i właściwości w jednej klasie** — działa, ale wygląda na niedokończone przepisywanie.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Sekcja `[moduł 8]`. Trzy rzeczy:

- **Właściwości automatyczne** (`{ get; set; }`) to C# 3. Starsze materiały pokazują pełną formę z polem zaplecza **wszędzie**, nawet gdy nic nie sprawdza.
- **Jeszcze starsze** materiały używają metod `GetImie()` / `SetImie(...)`. To wzorzec przeniesiony z innych czasów; w C# nie pisze się tak od dwudziestu lat.
- **Wartość początkowa przy właściwości** (`{ get; set; } = "..."`) działa od C# 6.

## Notatki tutora

- **Krok 2 musi zacząć się od porażki konstruktora.** Uczeń widział w 8.2 sprawdzanie w konstruktorze i uznał sprawę za załatwioną. `mruczek.Wiek = -500` pokazuje, że nie — i dopiero to uzasadnia całą lekcję.
- **Krok 3.B (właściwość automatyczna to skrót) jest ważny profilaktycznie.** Bez niego uczeń zaczyna rozpisywać pole zaplecza przy każdej właściwości, bo „tak było w przykładzie".
- **`value` wyjaśnij raz i krótko.** To słowo kluczowe dostępne tylko w `set`.
- **Nie wprowadzaj `private` jako tematu.** Pojawia się przy `private set` i polu zaplecza — powiedz „tylko z wnętrza klasy" i odłóż. Pełne wyjaśnienie to 8.4.
- **Nie wprowadzaj `init`** ani `required`. Poza kursem.
- **Pułapka z nieskończoną rekurencją w `get`** jest warta pokazania, jeśli starczy czasu — objaw (przepełnienie stosu) jest spektakularny i uczy czytać nazwy uważnie.
- Jeśli uczeń pyta, czy właściwość jest wolniejsza od pola — „w praktyce nie, kompilator to upraszcza". Nie rozwijaj.
