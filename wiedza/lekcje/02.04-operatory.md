# Lekcja 2.4 — Operatory i wyrażenia

## Cel
Po lekcji uczeń:
- Zna operatory arytmetyczne, w tym `%` (reszta z dzielenia) i wie, do czego służy
- Używa zapisów skróconych (`+=`, `-=`, `*=`) i rozumie, co skracają
- Rozumie, czemu `licznik = licznik + 1` ma sens, choć w matematyce nie ma
- Zna operatory porównania i wie, że dają `bool`
- Wie, że `+` na tekstach dokleja, i rozpoznaje pułapkę `"30" + 5`

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Dzielisz 17 cukierków między 5 dzieci po równo. Ile dostanie każde i ile ci zostanie?"

**Co chcesz usłyszeć:** po 3, zostaną 2.

> „Ta druga liczba — reszta — do czego mogłaby ci się przydać w programie?"

Pociągnij, jeśli uczeń nie ma pomysłu. Przykłady, które warto naprowadzić: sprawdzenie, czy liczba jest parzysta (reszta z dzielenia przez 2), rozłożenie czegoś na strony po 10, cykliczne kolory na liście.

**Drugie pytanie:**
> „Licznik odwiedzin na stronie. Przychodzi nowy gość. Co robisz z licznikiem?"

**Co chcesz usłyszeć:** zwiększam o jeden. Trzymaj to — wraca w kroku 3.

## Krok 2 — Mostek (8 min)

**Mostek:**
> „Wszystkie działania, które robisz na liczbach, w C# nazywamy **operatorami**. Cztery znasz ze szkoły. Piąty — reszta z dzielenia — nie ma swojego znaku w matematyce szkolnej, a w programowaniu jest jednym z najużyteczniejszych."

Uczeń tworzy `kurs/zadania/05-operatory.cs`:

```csharp
int a = 17;
int b = 5;

Console.WriteLine(a + b);
Console.WriteLine(a - b);
Console.WriteLine(a * b);
Console.WriteLine(a / b);
Console.WriteLine(a % b);
```

> „Zgadnij wszystkie pięć wyników, **zanim** uruchomisz. Potem uruchom i porównaj."

To ważne, żeby zgadywał przed uruchomieniem. `a / b` da `3` — jeśli uczeń powiedział `3,4`, lekcja 2.3 nie usiadła i warto wrócić do niej na moment.

Nazwij: `%` to **reszta z dzielenia**, czytana „modulo".

## Krok 3 — Eksperyment (20 min)

### A. Do czego naprawdę służy `%`

```csharp
Console.WriteLine(10 % 2);
Console.WriteLine(11 % 2);
Console.WriteLine(12 % 2);
Console.WriteLine(13 % 2);
```
> „Co zauważasz w wynikach? Jak jednym zdaniem opisałbyś, kiedy wychodzi zero?"
→ gdy liczba jest parzysta. To najczęstsze zastosowanie `%` w całym programowaniu.

Drugie zastosowanie, warte pokazania:
```csharp
int sekundy = 250;
Console.WriteLine(sekundy / 60);
Console.WriteLine(sekundy % 60);
```
→ `4` i `10`, czyli 4 minuty i 10 sekund.
> „Dzielenie całkowite i reszta pracują tu razem. Zauważ, że to, co w lekcji 2.3 było pułapką, tutaj jest dokładnie tym, czego chcesz."

To dobre domknięcie poprzedniej lekcji: dzielenie całkowite nie jest wadą języka, tylko narzędziem — problemem jest tylko użycie go tam, gdzie się nie chciało.

### B. `licznik = licznik + 1`

```csharp
int licznik = 0;
Console.WriteLine(licznik);

licznik = licznik + 1;
Console.WriteLine(licznik);

licznik = licznik + 1;
Console.WriteLine(licznik);
```

> „`licznik = licznik + 1`. W matematyce to zdanie jest fałszywe — nic nie jest równe sobie plus jeden. Czemu tutaj działa?"

To jest **najważniejsze pytanie tej lekcji**. Doprowadź ucznia do odpowiedzi: `=` nie znaczy „równa się", tylko **„policz prawą stronę i włóż wynik do lewej"**. Prawa strona liczy się pierwsza, na starej wartości.

Wróć tu do lekcji 2.1, gdzie było to powiedziane jednym zdaniem. Teraz uczeń widzi, czemu to miało znaczenie.

### C. Zapisy skrócone

```csharp
int x = 10;
x += 5;     // to samo co x = x + 5
x -= 3;
x *= 2;
Console.WriteLine(x);
```
> „Zgadnij wynik przed uruchomieniem."
→ `24`

> „Czy `x += 5` robi coś, czego nie robi `x = x + 5`?"
→ nie. To wyłącznie krótszy zapis. Ale spotkasz go w każdym kodzie, więc trzeba go znać.

### D. Inkrementacja — i jej pułapka

```csharp
int i = 0;
Console.WriteLine(i++);
Console.WriteLine(i);
Console.WriteLine(++i);
```
> „Zgadnij wszystkie trzy, zanim uruchomisz."
→ `0`, `1`, `2`

> „Pierwsza linia wypisała zero, choć `i++` miało zwiększyć. Co się stało?"
→ `i++` **najpierw wypisuje, potem zwiększa**. `++i` odwrotnie.

**Powiedz wprost:** „Ta różnica jest źródłem błędów i w prawdziwym kodzie prawie nigdy nie warto na niej polegać. Używaj `i++` jako samodzielnej instrukcji, nie w środku innego wyrażenia. Pokazuję ci to, żebyś rozpoznał, gdy zobaczysz — nie żebyś tego używał."

### E. Porównania dają `bool`

```csharp
int a = 17;
int b = 5;

Console.WriteLine(a > b);
Console.WriteLine(a == b);
Console.WriteLine(a != b);

bool czyWiekszy = a > b;
Console.WriteLine(czyWiekszy);
```
> „Jakiego typu jest wynik porównania? Sprawdź przez `GetType()`."
→ `System.Boolean`, czyli `bool` z lekcji 2.1.

> „Czemu `==`, a nie `=`?"
→ bo `=` jest już zajęte przez „włóż do". Porównanie musiało dostać własny znak.

A co, gdyby ktoś przez pomyłkę napisał jeden znak zamiast dwóch? Niech uczeń spróbuje:
```csharp
bool test = (a = b);
```
→ `CS0029: Cannot implicitly convert type 'int' to 'bool'`

> „Co tu się stało? `a = b` nie porównuje — **wkłada** `b` do `a`, a wynikiem takiego wkładania jest liczba, nie odpowiedź prawda/fałsz."

To jest miejsce, w którym C# jest dla ciebie łaskawy: warunek musi być typu `bool`, więc pomyłka `=` zamiast `==` nie ma jak przejść niezauważona. Kompilator zatrzyma cię, zanim program ruszy.

### F. `+` na tekstach

```csharp
string imie = "Anna";
string nazwisko = "Kowalska";
Console.WriteLine(imie + " " + nazwisko);
```
> „`+` między dwoma tekstami — co zrobił?"
→ skleił. To się nazywa **konkatenacja**.

Teraz pułapka, którą uczeń już raz widział:
```csharp
string wiekTekst = "30";
Console.WriteLine(wiekTekst + 5);
```
→ `305`
> „Czemu nie 35? Co C# zrobił z piątką?"
→ zamienił ją na tekst i skleił. Gdy jedna strona `+` jest tekstem, **cała operacja staje się sklejaniem**.

> „Jak to naprawić, żeby wyszło 35?"
→ `int.Parse(wiekTekst) + 5`. To odwołanie do lekcji 2.3 i dobre sprawdzenie, czy zostało.

## Krok 4 — Pogłębienie (8-10 min)

**Kolejność działań** — jak w matematyce, plus nawiasy:
```csharp
Console.WriteLine(2 + 3 * 4);
Console.WriteLine((2 + 3) * 4);
```
→ `14` i `20`

> „Reguła praktyczna: jeśli musisz się zastanowić, jaka jest kolejność — dodaj nawiasy. Kompilatorowi jest obojętne, a człowiekowi nie."

**Dzielenie przez zero — dwa różne zachowania:**
```csharp
Console.WriteLine(7.0 / 0);
```
→ `∞` (nieskończoność)

```csharp
int zero = 0;
Console.WriteLine(7 / zero);
```
→ program się przewraca: `System.DivideByZeroException`

> „Ta sama operacja, dwa różne zachowania. Skąd różnica?"
→ `double` ma reprezentację nieskończoności, `int` nie ma. Zaskakujące i warte zapamiętania.

> **Uwaga dla agenta:** drugi przykład musi używać zmiennej (`7 / zero`), nie stałej. `7 / 0` wpisane wprost kompilator odrzuci już na etapie budowania — sam zauważy, że dzielisz przez zero.

**Operatory logiczne — tylko wzmianka:**
```csharp
bool a = true;
bool b = false;
Console.WriteLine(a && b);   // oba muszą być prawdziwe
Console.WriteLine(a || b);   // wystarczy jeden
Console.WriteLine(!a);       // odwrócenie
```
> „Pokazuję, żebyś rozpoznał. Do czego to służy, zobaczysz w module 4, gdy zaczniesz podejmować decyzje."

Trzy linie, jedno zdanie, dalej. **Nie rozwijaj** — bez `if` to wisi w próżni.

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „operatory i wyrażenia". Propozycje:

- 🔥 **Rozgrzewka** (`05-operatory-a.cs`): masz `int minuty = 500;`. Wypisz, ile to pełnych godzin i ile minut zostaje. Użyj `/` i `%`.
- ⭐ **Główne** (`05-operatory-b.cs`): kalkulator paragonu. `int cenaGroszy = 1299;` (czyli 12,99 zł). Sztuk: 3. Wypisz: łączną cenę w groszach, tę samą kwotę jako złote i grosze osobno (np. „38 zł 97 gr"), oraz — dodatkowo — czy liczba sztuk jest parzysta (jako `true`/`false`, bez `if`).
- ⚡ **Gwiazdka** (`05-operatory-c.cs`): masz liczbę sekund, np. `int sekundy = 93784;`. Rozłóż ją na dni, godziny, minuty i sekundy, i wypisz w formacie `1 d 2 h 3 min 4 s`. Użyj wyłącznie `/` i `%`.

Gwiazdka jest ładnym zadaniem: wymaga myślenia o kolejności (najpierw największa jednostka), a rozwiązanie ma sześć linii. Uczeń, który je zrobi, naprawdę rozumie `%`.

## Pułapki

- **`=` zamiast `==`** — w C# złapie to kompilator (`CS0029`), bo warunek musi być `bool`. To rzadka sytuacja, w której C# jest bezpieczniejszy niż większość języków. Warto to uczniowi powiedzieć.
- **`"30" + 5` daje `"305"`** — najczęstsza pułapka na tekstach. Rozpoznanie: wynik wygląda jak sklejone liczby.
- **`i++` w środku wyrażenia** — nie rób tego. Osobna instrukcja.
- **Dzielenie przez zero na `int`** przewraca program, na `double` daje `∞`. Dwa różne światy.
- **`7 / 0` wpisane wprost** nie skompiluje się (`CS0020`) — kompilator to zauważy. Przez zmienną już nie.
- **Kolejność działań w długim wyrażeniu** — nawiasy kosztują nic, a oszczędzają godzinę szukania.
- **`%` na liczbach ujemnych** — `-7 % 3` daje `-1`, nie `2`. Rzadko potrzebne, ale potrafi zaskoczyć.

## Notatki tutora

- **Krok 3.B (`licznik = licznik + 1`) to serce lekcji.** Bez tego uczeń nie zrozumie pętli w module 5. Jeśli masz poświęcić dziesięć minut na jedną rzecz, to na to.
- **Nie wprowadzaj `if`.** Operatory porównania i logiczne pokazujesz jako „wynik typu `bool`", nie jako część warunku. Pokusa jest duża — to jedno zdanie od `if (a > b)` — ale moduł 4 ma to zrobić porządnie.
- **`i++` kontra `++i`:** pokaż różnicę, ale od razu powiedz, żeby na niej nie polegał. To wiedza rozpoznawcza, nie warsztatowa.
- **Nie rób tabeli wszystkich operatorów.** Uczeń nie potrzebuje `>>`, `&`, `??`, `?.` ani `is`. Pięć arytmetycznych, cztery porównania, trzy logiczne — koniec.
- **Zgadywanie przed uruchomieniem** jest w tej lekcji użyte cztery razy i to jest celowe. Uczeń, który przewiduje wynik i się myli, zapamiętuje lepiej niż ten, który tylko patrzy.
- **Moduł 2 kończy się tą lekcją.** Warto podsumować: uczeń umie już przechowywać dane, zmieniać je i liczyć na nich. Czego mu brakuje, to porozmawiać z użytkownikiem (moduł 3) i podjąć decyzję (moduł 4). Powiedzenie tego wprost daje poczucie kierunku.
