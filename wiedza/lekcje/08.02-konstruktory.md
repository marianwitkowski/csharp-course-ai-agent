# Lekcja 8.2 — Konstruktory

## Cel
Po lekcji uczeń:
- Pisze konstruktor i tworzy obiekt gotowy od razu, jednym wywołaniem
- **Przeciąża konstruktory** — i tym samym spłaca dług z lekcji 7.2
- Wie, że własny konstruktor usuwa ten domyślny
- Używa `this`, gdy nazwa parametru jest taka sama jak pola
- Nadpisuje `ToString()`, żeby obiekt dało się sensownie wypisać

> **Ta lekcja spłaca dwa długi naraz.** Z 7.2: przeciążania nie dało się napisać poza klasą. Z 8.1: `Console.WriteLine(kot)` wypisywało `Kot` zamiast danych.

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Urzędnik daje ci pusty formularz i mówi: »wypełnij imię, potem nazwisko, potem PESEL«. Co może pójść nie tak?"

**Co chcesz usłyszeć:** można o czymś zapomnieć i oddać formularz niekompletny.

**Drugie pytanie:**
> „A gdyby okienko nie wydawało pustych formularzy — tylko od razu wypełnione tym, co podasz przy okienku?"

**Co chcesz usłyszeć:** nie da się zapomnieć, bo bez danych nie dostaniesz kartki.

**To jest cała lekcja.** Konstruktor to okienko, przez które trzeba przejść, żeby obiekt w ogóle powstał.

## Krok 2 — Mostek (12 min)

Przypomnij uczniowi, jak wyglądało tworzenie kota w 8.1:
```csharp
Kot mruczek = new Kot();
mruczek.Imie = "Mruczek";
mruczek.Wiek = 3;
```

> „Trzy linie, żeby powstał jeden gotowy kot. A między pierwszą a trzecią — kot bez imienia. Czy taki kot ma sens?"

**Mostek:**
> „Metoda, która wykonuje się **w momencie tworzenia obiektu**, nazywa się **konstruktorem**. Wygląda jak metoda o nazwie klasy i bez typu zwracanego."

Uczeń tworzy `kurs/zadania/22-konstruktory.cs`:

```csharp
Kot mruczek = new Kot("Mruczek", 3);
Console.WriteLine($"{mruczek.Imie} ma {mruczek.Wiek} lat");

class Kot
{
    public string Imie;
    public int Wiek;

    public Kot(string imie, int wiek)
    {
        Imie = imie;
        Wiek = wiek;
    }
}
```
→ `Mruczek ma 3 lat`

**Pytania:**
- „Czym różni się nagłówek konstruktora od nagłówka metody z lekcji 7.1?" → **nie ma typu zwracanego** i nazywa się **jak klasa**
- „Kiedy się wykonuje?" → w chwili `new`
- „Ile linii zajmuje teraz utworzenie gotowego kota?" → jedna

Nazwij: **konstruktor**.

### Niespodzianka: stary sposób przestał działać

Niech uczeń spróbuje:
```csharp
Kot bezimienny = new Kot();
```
→ `CS7036` albo `CS1729` — kompilator mówi, że nie ma konstruktora bez argumentów.

> „Do tej pory `new Kot()` działało. Co się zmieniło?"
→ **gdy nie napiszesz żadnego konstruktora, C# daje ci domyślny, pusty. Gdy napiszesz własny, ten domyślny znika.**

> „Czy to dobrze?"
→ zwykle tak: jeśli kot **musi** mieć imię, to dobrze, że nie da się utworzyć kota bez imienia.

## Krok 3 — Eksperyment (25 min)

### A. Przeciążone konstruktory — dług z lekcji 7.2 spłacony

Przypomnij uczniowi `CS0128` z lekcji 7.2: dwie metody o tej samej nazwie nie przeszły. Teraz:

```csharp
class Kot
{
    public string Imie;
    public int Wiek;

    public Kot(string imie, int wiek)
    {
        Imie = imie;
        Wiek = wiek;
    }

    public Kot(string imie)
    {
        Imie = imie;
        Wiek = 1;
    }

    public Kot()
    {
        Imie = "bezimienny";
        Wiek = 1;
    }
}
```

```csharp
Kot a = new Kot("Mruczek", 3);
Kot b = new Kot("Filemon");
Kot c = new Kot();

Console.WriteLine($"{a.Imie} {a.Wiek}");
Console.WriteLine($"{b.Imie} {b.Wiek}");
Console.WriteLine($"{c.Imie} {c.Wiek}");
```
→ `Mruczek 3`, `Filemon 1`, `bezimienny 1`

> „Trzy konstruktory o tej samej nazwie. W lekcji 7.2 to samo dało `CS0128`. Co się zmieniło?"
→ **jesteśmy w klasie.** Dokładnie o to chodziło, gdy mówiłem „w module 8 będzie można".

**Zatrzymaj się tutaj.** To jest odpowiedź na przeszkodę, którą uczeń napotkał dwa moduły temu — i konkretny dowód, po co są klasy.

> „Skąd C# wie, którego konstruktora użyć?"
→ po liczbie i typach argumentów. Tak samo jak przy `Console.WriteLine` z 7.2.

### B. `this` — gdy parametr nazywa się jak pole

Naturalna nazwa parametru to `imie`, ale pole też chciałoby się tak nazywać. Zobacz, co się dzieje:

```csharp
class Kot
{
    public int Wiek;

    public Kot(int Wiek)
    {
        Wiek = Wiek;
    }
}
```
→ kompiluje się i **działa źle**: `new Kot(5).Wiek` daje `0`. Kompilator ostrzega dwa razy:
```
warning CS1717: Assignment made to same variable; did you mean to assign something else?
warning CS0649: Field 'Kot.Wiek' is never assigned to, and will always have its default value 0
```

> „Co przypisało się do czego?"
→ parametr sam do siebie. Pole nie zostało dotknięte — drugie ostrzeżenie mówi to wprost.

To już czwarte ostrzeżenie w kursie, które oznacza prawdziwy błąd. (Przy polu tekstowym zamiast `CS0649` zobaczysz `CS8618` — o wartości, której może zabraknąć.)

Rozwiązanie — `this` wskazuje pole, nie parametr:
```csharp
public Kot(int Wiek)
{
    this.Wiek = Wiek;
}
```

`this` znaczy **„ten konkretny obiekt"**.

> „W naszej klasie pole nazywa się `Imie` z wielkiej litery, a parametr `imie` z małej — więc `this` nie jest konieczne. Ale zobaczysz je w cudzym kodzie i teraz wiesz, co znaczy."

**Konwencja C# ratuje przed tym problemem:** pola i właściwości `PascalCase`, parametry `camelCase`. Przy trzymaniu się jej nazwy nigdy się nie zderzają.

### C. `ToString()` — domknięcie 8.1

W lekcji 8.1 `Console.WriteLine(mruczek)` wypisywało `Kot`. Teraz:

```csharp
class Kot
{
    public string Imie;
    public int Wiek;

    public Kot(string imie, int wiek)
    {
        Imie = imie;
        Wiek = wiek;
    }

    public override string ToString()
    {
        return $"{Imie} ({Wiek} lat)";
    }
}
```

```csharp
Kot mruczek = new Kot("Mruczek", 3);
Console.WriteLine(mruczek);
Console.WriteLine($"Mój kot: {mruczek}");
```
→ `Mruczek (3 lat)` i `Mój kot: Mruczek (3 lat)`

> „Zadziałało w dwóch miejscach naraz — i w `WriteLine`, i w interpolacji. Skąd?"
→ oba proszą obiekt o opis tekstowy. Do tej pory dostawały odpowiedź domyślną; teraz twoją.

**Słowo `override` znaczy „zamiast domyślnego".** Nie tłumacz więcej — pełne wyjaśnienie to lekcja 9.2.

> „Od tej chwili każdą swoją klasę warto wyposażyć w `ToString`. Kosztuje trzy linie, a oszczędza pisania przy każdym wypisywaniu."

### D. Konstruktor, który sprawdza dane

```csharp
public Kot(string imie, int wiek)
{
    if (string.IsNullOrWhiteSpace(imie))
    {
        imie = "bezimienny";
    }

    if (wiek < 0)
    {
        wiek = 0;
    }

    Imie = imie;
    Wiek = wiek;
}
```

```csharp
Kot dziwny = new Kot("", -5);
Console.WriteLine(dziwny);
```
→ `bezimienny (0 lat)`

> „Gdzie to sprawdzenie musiałoby być, gdyby nie było konstruktora?"
→ w **każdym miejscu**, w którym ktoś tworzy kota. Konstruktor jest jedynym wejściem, więc wystarczy raz.

`string.IsNullOrWhiteSpace` to nowe narzędzie — jedno zdanie: „sprawdza, czy tekst jest `null`, pusty albo złożony z samych spacji". Wraca w module 12.

### E. Wartość początkowa przy polu

```csharp
class Kot
{
    public string Imie = "bezimienny";
    public int Wiek = 1;
}
```

> „Teraz `new Kot()` daje kota z imieniem, bez pisania konstruktora. Kiedy to wystarczy, a kiedy potrzebny jest konstruktor?"
→ wartość przy polu wystarcza dla **stałej** wartości domyślnej; konstruktor jest potrzebny, gdy wartość **zależy od tego, co podał wywołujący**.

## Krok 4 — Pogłębienie (10 min)

**Konstruktor podstawowy — krótszy zapis (C# 12)**

```csharp
class Kot(string imie, int wiek)
{
    public string Imie { get; set; } = imie;
    public int Wiek { get; set; } = wiek;
    public override string ToString() => $"{Imie} ({Wiek} lat)";
}
```

> „Parametry stoją przy nazwie klasy, jak przy metodzie. Krócej, ale mniej widać, co się dzieje."

**Pokaż i idź dalej.** To zapis do rozpoznania; w tym kursie piszemy klasyczny konstruktor, bo lepiej widać w nim mechanizm. (Nawias `{ get; set; }` to lekcja 8.3 — powiedz „na razie czytaj to jak pole".)

**Kilka konstruktorów bez powtarzania kodu**

```csharp
public Kot(string imie) : this(imie, 1)
{
}
```

> „`: this(imie, 1)` znaczy »wywołaj najpierw tamten konstruktor z tymi argumentami«. Dzięki temu sprawdzanie danych jest w jednym miejscu."

To praktyczna rzecz i warto ją pokazać, ale **nie ćwiczyć** — uczeń użyje jej, gdy poczuje ból duplikacji.

**Czego konstruktor nie robi**

| | |
| --- | --- |
| nie ma typu zwracanego | ani `void`, ani żadnego innego |
| nie da się go wywołać ręcznie | tylko przez `new` |
| nie musi być jeden | patrz krok 3.A |
| nie musi istnieć | wtedy C# daje domyślny, pusty |

**Kiedy konstruktor jest konieczny?**

> „Gdy obiekt **nie ma sensu** bez pewnych danych. Kot bez imienia — może być. Konto bankowe bez właściciela — nie."

To zapowiedź lekcji 8.4, gdzie pojawi się pojęcie obiektu, który zawsze jest w poprawnym stanie.

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „konstruktory". Propozycje:

- 🔥 **Rozgrzewka** (`22-konstruktory-a.cs`): przepisz klasę `Ksiazka` z ćwiczenia 8.1 tak, żeby miała konstruktor przyjmujący tytuł, autora i rok. Dodaj `ToString()` i wypisz dwie książki jednym `Console.WriteLine` każdą.
- ⭐ **Główne** (`22-konstruktory-b.cs`): klasa `Uczen` z polami `Imie` i tablicą `int[] Oceny`. Napisz **dwa** konstruktory: jeden przyjmujący imię i oceny, drugi samo imię (wtedy oceny to pusta tablica). Dodaj `ToString()` wypisujący imię i średnią z dwoma miejscami po przecinku (dla braku ocen — `brak ocen`). Utwórz trzech uczniów, dwóch z ocenami, jednego bez, i wypisz wszystkich.
- ⚡ **Gwiazdka** (`22-konstruktory-c.cs`): klasa `Data` z polami `Dzien`, `Miesiac`, `Rok`. Konstruktor ma **sprawdzać** poprawność: miesiąc 1–12, dzień 1–31, a przy błędnych danych ustawiać 1 stycznia 2000. Napisz `ToString()` w formacie `2026-08-30` (z zerami wiodącymi — podpowiedź: format `D2` w interpolacji, jak `F2` z lekcji 3.1). Utwórz cztery daty, w tym dwie błędne.

Gwiazdka wymaga sprawdzania w konstruktorze i formatowania z zerami — obie rzeczy wracają w module 12 przy plikach.

## Pułapki

- **Własny konstruktor usuwa domyślny** → `new Kot()` przestaje działać. Jeśli chcesz obu, napisz oba.
- **Konstruktor z typem zwracanym** — `public void Kot(...)` to **nie** konstruktor, tylko zwykła metoda o mylącej nazwie. Kompilator nie protestuje; obiekt powstaje niewypełniony.
- **Nazwa konstruktora inna niż klasy** — to zwykła metoda. Ten sam objaw.
- **`Wiek = Wiek`** przy identycznych nazwach → `CS1717` plus `CS0649`, pole zostaje z wartością domyślną. Ratunek: `this.Wiek = Wiek` albo konwencja nazw (pole `PascalCase`, parametr `camelCase`).
- **Sprawdzanie danych poza konstruktorem** — trzeba je powtarzać w każdym miejscu tworzenia obiektu.
- **Brak `ToString`** → `Console.WriteLine(obiekt)` wypisuje nazwę klasy. To nie błąd, ale prawie zawsze nie o to chodziło.
- **`override` pominięte przy `ToString`** — kompilator ostrzeże, że ukrywasz metodę zamiast ją zastąpić. Pełne wyjaśnienie w 9.2.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Sekcja `[moduł 8]`. Dwie rzeczy:

- **Konstruktory podstawowe** (`class Kot(string imie, int wiek)`) to C# 12. Wprowadzaj **po** klasycznych — uczeń, który nie napisał ani razu zwykłego konstruktora, nie zrozumie, co skrót skraca.
- **Wartość początkowa przy polu** (`public int Wiek = 1;`) działa od C# 6. Starsze materiały ustawiały wszystko w konstruktorze.

## Notatki tutora

- **Krok 3.A to najważniejsze pięć minut modułu 8.** Uczeń zderzył się z `CS0128` w lekcji 7.2 i usłyszał „w module 8". To jest ten moment — powiedz to wprost i pozwól mu poczuć, że obietnica została spełniona.
- **Niespodzianka z kroku 2 (`new Kot()` przestaje działać) jest celowa.** Nie ostrzegaj wcześniej. Uczeń ma zobaczyć, że własny konstruktor coś zabiera, i sam ocenić, czy to dobrze.
- **`this` pokaż przez błąd**, nie przez regułę. Wiek równy zeru mimo `new Kot(5)` przekonuje lepiej niż wyjaśnienie.
- **Nie tłumacz `override`.** „Zamiast domyślnego" wystarcza; pełne wyjaśnienie to 9.2 i tam wróci.
- **Nie wprowadzaj właściwości.** Konstruktor podstawowy w kroku 4 używa `{ get; set; }` — powiedz „na razie czytaj to jak pole" i idź dalej. To lekcja 8.3.
- **Nie wprowadzaj `private`.** To 8.4.
- **`: this(...)` pokaż, nie ćwicz.** Uczeń sięgnie po to sam, gdy zacznie mu przeszkadzać duplikacja.
- Jeśli uczeń pyta, czy konstruktor może coś zwracać — dobre pytanie. Odpowiedź: nie, bo już „zwraca" gotowy obiekt; `new` oddaje ci go automatycznie.
