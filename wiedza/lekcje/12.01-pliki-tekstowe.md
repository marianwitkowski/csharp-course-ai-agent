# Lekcja 12.1 — Pliki tekstowe

## Cel
Po lekcji uczeń:
- Zapisuje i odczytuje plik tekstowy przez `File.WriteAllText` i `File.ReadAllText`
- Pracuje na liniach przez `ReadAllLines` i `WriteAllLines`
- Dopisuje do pliku bez kasowania zawartości
- Sprawdza istnienie pliku przez `File.Exists` **zamiast** łapać wyjątek
- Używa `StreamWriter`/`StreamReader` z `using` i wie, kiedy są potrzebne

> **To pierwsza lekcja, po której coś przetrwa zamknięcie programu.** Wszystko, co uczeń napisał przez jedenaście modułów, znikało bez śladu.

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Uruchamiasz swój program z listą zakupów z lekcji 6.2, wpisujesz dziesięć pozycji, zamykasz. Uruchamiasz ponownie. Co widzisz?"

**Co chcesz usłyszeć:** pustą listę. Wszystko przepadło.

**Drugie pytanie:**
> „Gdzie w prawdziwym świecie zapisujesz coś, co ma przetrwać?"

**Co chcesz usłyszeć:** na kartce, w zeszycie, w pliku.

**Trzecie pytanie:**
> „Zeszyt leży w szufladzie. Co musisz zrobić, zanim coś w nim zapiszesz, i co po zapisaniu?"

**Co chcesz usłyszeć:** otworzyć, napisać, **zamknąć**. Trzeci krok jest tym, o którym się zapomina — i to jest `using` z lekcji 11.2.

## Krok 2 — Mostek (12 min)

**Mostek:**
> „Plik na dysku to twój zeszyt. C# ma na niego dwie drogi: krótką, gdy chodzi o cały tekst naraz, i dłuższą, gdy plik jest duży albo pisze się go po kawałku."

Zacznij od krótkiej. Uczeń tworzy `kurs/zadania/34-pliki.cs`:

```csharp
File.WriteAllText("notatka.txt", "Pierwsza linia\nDruga linia\n");

string tresc = File.ReadAllText("notatka.txt");
Console.WriteLine(tresc);
```
→ dwie linie na ekranie.

**Niech uczeń teraz otworzy `notatka.txt` w edytorze.** Ten moment jest ważny: plik naprawdę istnieje, poza programem.

**Pytania:**
- „Gdzie powstał ten plik?" → w katalogu, z którego uruchomiłeś program (`kurs/zadania`)
- „Co się stanie, gdy uruchomisz program drugi raz?" → **nadpisze** plik, nie dopisze
- „Ile linii kodu potrzeba było na zapis i odczyt?" → po jednej

Nazwij: **`File`** — klasa statyczna (moduł 9.4!) z gotowymi operacjami na plikach.

> **`WriteAllText` kasuje poprzednią zawartość.** To najczęstsza niespodzianka tej lekcji. Do dopisywania jest `AppendAllText`.

## Krok 3 — Eksperyment (25 min)

### A. Dopisywanie kontra nadpisywanie

```csharp
File.WriteAllText("dziennik.txt", "start\n");
File.AppendAllText("dziennik.txt", "druga\n");
File.AppendAllText("dziennik.txt", "trzecia\n");

Console.WriteLine(File.ReadAllText("dziennik.txt"));
```
→ trzy linie.

Teraz niech uczeń zamieni **ostatni** `AppendAllText` na `WriteAllText` i uruchomi ponownie.
→ została jedna linia: `trzecia`.

> „Co się stało z pierwszymi dwiema?"

### B. Praca na liniach

```csharp
string[] linie = File.ReadAllLines("dziennik.txt");

Console.WriteLine($"Linii: {linie.Length}");
for (int i = 0; i < linie.Length; i++)
{
    Console.WriteLine($"{i + 1}: {linie[i]}");
}
```

> „Co zwraca `ReadAllLines`?"
→ **tablicę** z lekcji 6.1. Od tej chwili plik jest zwykłą tablicą tekstów i uczeń umie z nią wszystko.

Zapis działa lustrzanie:
```csharp
string[] zakupy = { "chleb", "mleko", "ser" };
File.WriteAllLines("zakupy.txt", zakupy);
```

> „Kto dopisał znaki nowej linii między pozycjami?"
→ `WriteAllLines` sam.

**To jest najwygodniejsza para metod w całej lekcji** i uczeń będzie jej używał najczęściej.

### C. Plik, którego nie ma

```csharp
string tresc = File.ReadAllText("nie-ma-mnie.txt");
```
→
```
Unhandled exception. System.IO.FileNotFoundException: Could not find file '...'
```

> „Znasz ten schemat z lekcji 11.1. Jakie masz dwie drogi?"

**Droga pierwsza — sprawdź wcześniej:**
```csharp
if (File.Exists("nie-ma-mnie.txt"))
{
    Console.WriteLine(File.ReadAllText("nie-ma-mnie.txt"));
}
else
{
    Console.WriteLine("Pliku nie ma.");
}
```

**Droga druga — złap wyjątek:**
```csharp
try
{
    Console.WriteLine(File.ReadAllText("nie-ma-mnie.txt"));
}
catch (FileNotFoundException)
{
    Console.WriteLine("Pliku nie ma.");
}
```

> „Która jest lepsza?"

**Obie są potrzebne** — i to jest ważne rozróżnienie:
- `File.Exists` załatwia przewidywalny przypadek („pliku jeszcze nie ma, bo to pierwsze uruchomienie")
- `catch` łapie resztę: brak uprawnień, plik zajęty przez inny program, dysk pełny

> „Sam `File.Exists` nie wystarczy: między sprawdzeniem a odczytem plik może zniknąć. W praktyce używa się **obu**."

To niuans, który uczeń zapamięta lepiej niż regułę, bo wygląda na paradoks.

### D. `StreamWriter` — pisanie po kawałku

```csharp
using (StreamWriter pisarz = new StreamWriter("raport.txt"))
{
    pisarz.WriteLine("Raport");
    pisarz.WriteLine("------");

    for (int i = 1; i <= 3; i++)
    {
        pisarz.WriteLine($"Pozycja {i}");
    }
}

Console.WriteLine(File.ReadAllText("raport.txt"));
```

> „Czy dałoby się to zrobić przez `WriteAllLines`?"
→ tak, budując wcześniej listę. Ale przy tysiącu linii trzymałbyś je wszystkie w pamięci naraz.

> „Czemu `using`?"
→ **plik musi zostać zamknięty.** Bez tego zmiany mogą nie trafić na dysk, a plik zostaje zablokowany dla innych programów.

Niech uczeń **usunie `using`** i zamieni na zwykłe `new StreamWriter(...)`, bez zamykania:
```csharp
StreamWriter p = new StreamWriter("test.txt");
p.WriteLine("coś");
Console.WriteLine(File.ReadAllText("test.txt"));
```
→ `[]` — **plik jest pusty**. I zostaje pusty także po zakończeniu programu: `wc -c test.txt` pokaże zero bajtów. Tekst nigdy nie opuścił pamięci.

> „To jest ten moment, o którym mówiłem w lekcji 11.2: `using` przestaje być ćwiczeniem."

### E. `StreamReader` — czytanie linia po linii

```csharp
using (StreamReader czytnik = new StreamReader("raport.txt"))
{
    string? linia;
    while ((linia = czytnik.ReadLine()) != null)
    {
        Console.WriteLine("> " + linia);
    }
}
```

> „`ReadLine` zwraca `null`, gdy plik się skończy. Skąd znasz `null`?"
→ z lekcji 8.1 — „żaden obiekt".

**Zapis `while ((linia = czytnik.ReadLine()) != null)` jest gęsty.** Rozłóż go:
1. `czytnik.ReadLine()` czyta linię
2. `linia = ...` przypisuje ją do zmiennej
3. całość porównuje się z `null`

> „To ten sam `=` co w `licznik = licznik + 1` z lekcji 2.4 — przypisanie **daje wartość**, którą można od razu sprawdzić."

**Kiedy `StreamReader` zamiast `ReadAllLines`?**
> „Gdy plik jest za duży, żeby zmieścić go w pamięci naraz. Przy plikach z twoich ćwiczeń `ReadAllLines` jest wygodniejsze."

### F. Gdzie właściwie leży ten plik?

```csharp
Console.WriteLine(Directory.GetCurrentDirectory());
```

> „Ścieżka `\"notatka.txt\"` jest **względna** — liczy się od katalogu, z którego uruchomiłeś program."

To jest częste źródło zdziwienia („napisałem plik, ale go nie widzę"). Pełne omówienie ścieżek to lekcja 12.2.

## Krok 4 — Pogłębienie (10 min)

**Cztery pary metod `File`**

| Zapis | Odczyt | Kiedy |
| --- | --- | --- |
| `WriteAllText` | `ReadAllText` | cały plik jako jeden tekst |
| `WriteAllLines` | `ReadAllLines` | plik jako tablica linii |
| `AppendAllText` | — | dopisanie na końcu |
| `StreamWriter` | `StreamReader` | duże pliki, pisanie po kawałku |

> „W tym kursie wystarczą ci dwa pierwsze wiersze. Pozostałe pokazuję, żebyś rozpoznał."

**Kodowanie**

```csharp
File.WriteAllText("polskie.txt", "Zażółć gęślą jaźń");
Console.WriteLine(File.ReadAllText("polskie.txt"));
```
→ działa poprawnie.

> „`File` domyślnie używa UTF-8, więc polskie znaki działają same z siebie. W starszych materiałach zobaczysz dodatkowy argument `Encoding.UTF8` — dziś zbędny."

**Usuwanie i kopiowanie**

```csharp
File.Copy("notatka.txt", "kopia.txt", overwrite: true);
File.Delete("kopia.txt");
```

> „`File.Delete` **nie protestuje**, gdy pliku nie ma. To jedna z niewielu metod, które milczą."

**Uwaga o kasowaniu:** przypomnij uczniowi, że kod, który kasuje pliki, warto uruchamiać ostrożnie i tylko na plikach, które sam stworzył w `kurs/zadania`.

**Wzorzec, który wraca w projekcie z modułu 14**

```csharp
List<string> pozycje = new List<string>();

if (File.Exists("dane.txt"))
{
    pozycje.AddRange(File.ReadAllLines("dane.txt"));
}

// ...praca na liście...

File.WriteAllLines("dane.txt", pozycje);
```

> **`AddRange`** to metoda listy z lekcji 6.2, której jeszcze nie widziałeś: dopisuje **całą kolekcję naraz**, zamiast dodawać element po elemencie w pętli. Jedno zdanie, nie rozwijaj.

> „Wczytaj, jeśli jest. Pracuj na liście. Zapisz na końcu. To jest **cały mechanizm trwałości** w małym programie."

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „pliki tekstowe". Propozycje:

- 🔥 **Rozgrzewka** (`34-pliki-a.cs`): zapytaj użytkownika o trzy ulubione filmy i zapisz je do `filmy.txt`, każdy w osobnej linii. Potem odczytaj plik i wypisz z numerami. Otwórz plik w edytorze i sprawdź, czy wygląda tak, jak myślisz.
- ⭐ **Główne** (`34-pliki-b.cs`): trwała lista zakupów. Przy starcie wczytaj `zakupy.txt`, jeśli istnieje. W pętli pozwól dodawać pozycje (Enter kończy) i wypisz całość. Na końcu zapisz plik. **Uruchom program trzy razy** i pokaż mi, że lista rośnie między uruchomieniami.
- ⚡ **Gwiazdka** (`34-pliki-c.cs`): dziennik z datami. Przy każdym uruchomieniu **dopisz** do `dziennik.txt` linię w formacie `2026-08-30 14:32 — treść wpisu` (użyj `DateTime.Now` z formatem z lekcji 3.1). Potem wypisz cały dziennik oraz **liczbę wpisów z dzisiaj** — porównując początek każdej linii z dzisiejszą datą. Obsłuż brak pliku przy pierwszym uruchomieniu.

Gwiazdka łączy dopisywanie, formatowanie dat i `ReadAllLines` — i po raz pierwszy program uczy się czegoś o swojej własnej historii. Porównanie początku linii uczeń może zrobić dowolnie: `linia.StartsWith(dzis)` albo `linia.Substring(0, 10) == dzis`. Żadnej z tych metod kurs nie pokazywał — niech sprawdzi w dokumentacji, to część ćwiczenia.

## Pułapki

- **`WriteAllText` kasuje zawartość** — do dopisywania jest `AppendAllText`. Najczęstsza pomyłka lekcji.
- **`FileNotFoundException` przy pierwszym uruchomieniu** — sprawdź `File.Exists` albo złap wyjątek.
- **Brak `using` przy `StreamWriter`** — plik zostaje pusty, bez żadnego błędu. Najtrudniejsza do wykrycia pomyłka w tej lekcji.
- **Zapomniana ścieżka względna** — plik powstaje tam, skąd uruchomiono program, nie tam, gdzie leży kod.
- **`ReadAllLines` na pustym pliku** — daje **pustą tablicę**, nie `null`. Pętla po niej po prostu się nie wykona.
- **Otwarty plik w edytorze podczas zapisu** — na Windows potrafi zablokować zapis.
- **Kasowanie pliku, którego nie ma** — `File.Delete` milczy; to nie błąd, ale bywa mylące.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Sekcja `[moduł 12]`. Dwie rzeczy:

- **`File.ReadAllText` i spółka** istnieją od dawna, ale starsze materiały pokazują wyłącznie `StreamReader`/`StreamWriter` — bo pochodzą z czasów, gdy `File.*` było mniej rozbudowane. Do małych plików krótsze metody są dziś domyślnym wyborem.
- **`Encoding.UTF8` jako dodatkowy argument** jest w nowym kodzie zbędny — UTF-8 jest domyślne.

## Notatki tutora

- **Każ uczniowi otworzyć zapisany plik w edytorze.** To najważniejsze pięć sekund lekcji: program przestaje być zamkniętym pudełkiem, a zaczyna zostawiać ślad w świecie.
- **Krok 3.D (`StreamWriter` bez `using`) domyka lekcję 11.2.** Tam `using` był ćwiczeniem na sztucznej klasie; tutaj jego brak psuje plik.
- **Nie wprowadzaj `Path`.** Uczeń zapyta o ścieżki po kroku 3.F — lekcja 12.2, następna.
- **Nie wprowadzaj JSON-a.** To 12.3.
- **Nie wprowadzaj `async`/`await`** ani metod `...Async`. Poza kursem.
- **Uważaj z kasowaniem.** Ćwiczenia operują na plikach w `kurs/zadania`; przypomnij, żeby nie testować `File.Delete` na czymkolwiek innym.
- **Uczeń może zapytać o pliki binarne** (zdjęcia, PDF). Jedno zdanie: „to inne metody, `ReadAllBytes`; w tym kursie zostajemy przy tekście".
- Jeśli uczeń nie może znaleźć zapisanego pliku — każ wypisać `Directory.GetCurrentDirectory()`. To rozwiązuje 90% takich zgłoszeń.
