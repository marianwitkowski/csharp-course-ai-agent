# Lekcja 8.5 — `null` i typy nullowalne

> **Krótka lekcja, która spłaca dług z lekcji 3.2.** Uczeń od modułu 3 widzi `CS8600` i słyszy „ostrzeżenie to nie błąd, wrócimy do tego". Teraz zna `null` (8.1), widział `CS8618` przy właściwościach (8.2-8.3) i ma wszystko, żeby zrozumieć, **o czym kompilator próbował mu powiedzieć przez pięć modułów**.

## Cel
Po lekcji uczeń:
- Rozróżnia `string` („tu zawsze jest tekst") od `string?` („tu może nie być")
- Czyta cztery ostrzeżenia `CS8600`, `CS8602`, `CS8604`, `CS8618` jako **jedną** informację: w tym miejscu może brakować wartości
- Sprawdza brak wartości przez `is null` / `is not null` i wie, że po sprawdzeniu ostrzeżenie znika
- Używa `??` (wartość zastępcza) i `?.` (wywołanie tylko, gdy coś jest)
- Stosuje regułę: **sprawdź raz na wejściu, dalej pracuj na zwykłym `string`**

## Krok 1 — Zakotwiczenie (3-5 min)

**Pytanie wejściowe:**
> „Lista gości na wesele: imię, nazwisko, telefon. Przy jednym gościu rubryka »telefon« jest pusta. Czy to błąd w liście?"

**Co chcesz usłyszeć:** nie — po prostu ten gość nie podał numeru. Brak numeru to **normalna sytuacja**, nie pomyłka.

**Drugie pytanie:**
> „Masz obdzwonić wszystkich gości. Co robisz przy tym jednym?"

**Co chcesz usłyszeć:** pomijam go albo piszę do niego inaczej. **Nie przerywam obdzwaniania.**

> „A gdybyś nie zauważył pustej rubryki i »zadzwonił« pod nic?"
→ to jest `NullReferenceException` z lekcji 8.1. Program, który nie sprawdził, czy jest numer.

## Krok 2 — Mostek (8 min)

**Mostek:**
> „W C# typ `string` to obietnica: **tu zawsze jest tekst**. Typ `string?` — ze znakiem zapytania — mówi co innego: **tu może być tekst, a może nie być nic**. Ten znak zapytania to informacja dla kompilatora, ale przede wszystkim **dla ciebie**: zanim tego użyjesz, sprawdź."

Uczeń pisze `kurs/zadania/24-null.cs`:

```csharp
string imie = null;
Console.WriteLine(imie.Length);
```
→ kompilator:
```
warning CS8600: Converting null literal or possible null value to non-nullable type.
warning CS8602: Dereference of a possibly null reference.
```
→ i uruchomienie:
```
Unhandled exception. System.NullReferenceException: Object reference not set to an instance of an object.
```

> „Dwa ostrzeżenia i wywrotka. Przeczytaj pierwsze: »konwersja `null` do typu, który `null` nie dopuszcza«. Co obiecał typ `string`?"
→ że tu zawsze jest tekst. A wpisałeś `null` — **złamałeś obietnicę** i kompilator to zauważył.

> „Drugie: »odwołanie do czegoś, co może być `null`«. Która linia?"
→ `imie.Length`. Kompilator **wiedział przed uruchomieniem**, że to się wywróci.

Teraz uczciwie:
```csharp
string? imie = null;
Console.WriteLine(imie.Length);
```
→ zostaje **jedno** ostrzeżenie:
```
warning CS8602: Dereference of a possibly null reference.
```

> „Które zniknęło i dlaczego?"
→ `CS8600` — bo `string?` **dopuszcza** `null`, więc wpisanie `null` nie łamie żadnej obietnicy. Zostało `CS8602`: nadal używasz czegoś, co może nie istnieć, **bez sprawdzenia**.

Nazwij: **typ nullowalny** (`string?`), **`null`** jako „brak wartości".

> „Kompilator nie zabrania `null`. Zabrania **udawać, że go nie ma**."

## Krok 3 — Eksperyment (15 min)

### A. Sprawdzenie — i ostrzeżenie znika

```csharp
string? imie = null;

if (imie is null)
{
    Console.WriteLine("brak imienia");
}

imie = "Ala";

if (imie is not null)
{
    Console.WriteLine(imie.Length);
}
```
→ `brak imienia`, `3` — i **zero ostrzeżeń**.

> „W drugim `if` używasz `imie.Length` tak jak w kroku 2. Czemu tym razem kompilator milczy?"
→ bo **w środku `if (imie is not null)`** kompilator wie, że `imie` nie jest `null`. Sprawdzenie **odblokowuje** użycie.

**To jest cała mechanika tej lekcji:** ostrzeżenie mówi „nie sprawdziłeś"; sprawdzenie je gasi.

> „`is null` czytaj dosłownie: »jest niczym«. Zapis `== null` z lekcji 8.1 działa tak samo; `is null` jest nowszy i wyraźniejszy, w tym kursie używamy tego."

### B. `??` — wartość zastępcza

Najczęstszy przypadek: brak wartości ma znaczyć „weź domyślną".

```csharp
string? podane = null;
string imie = podane ?? "bezimienny";
Console.WriteLine(imie);
Console.WriteLine(imie.Length);
```
→ `bezimienny`, `10` — bez ostrzeżeń.

> „Czytaj `??` jako **»a jeśli tego nie ma, to«**. Jakiego typu jest `imie` — z pytajnikiem czy bez?"
→ **bez.** Po `??` masz gwarancję, że tekst jest, bo w najgorszym razie jest `"bezimienny"`.

> „To dokładnie `Imie = "bezimienny"` z konstruktora w 8.2 — tylko w jednej linii, dla dowolnej wartości."

### C. `?.` — zrób tylko, jeśli jest

```csharp
string? imie = null;
Console.WriteLine(imie?.Length);
Console.WriteLine(imie?.Length ?? 0);

imie = "Ala";
Console.WriteLine(imie?.Length);
```
→ **pusta linia**, potem `0`, potem `3`.

> „Co wypisało `imie?.Length`, gdy `imie` było `null`?"
→ nic. `?.` znaczy: **jeśli jest — zrób; jeśli nie ma — wynik też jest »niczym«**. Bez wywrotki.

> „Kiedy `?.`, a kiedy `??`?"
→ `?.` gdy brak ma **przejść dalej** jako brak; `??` gdy brak ma **zostać zastąpiony**. Często razem, jak w drugiej linii: `imie?.Length ?? 0` — „długość, a jeśli imienia nie ma, to zero".

### D. Metoda, która wymaga wartości

```csharp
string? imie = null;
Powitaj(imie);

void Powitaj(string kto)
{
    Console.WriteLine($"Cześć, {kto}!");
}
```
→
```
warning CS8604: Possible null reference argument for parameter 'kto' in 'void Powitaj(string kto)'.
```
→ uruchomienie: `Cześć, !`

> „Metoda obiecuje w nagłówku: `string kto` — dostanę tekst. Ty jej dajesz coś, co może być niczym. Program się nie wywrócił, ale wypisał bzdurę. Jak to naprawić **bez zmiany metody**?"
→ `Powitaj(imie ?? "gościu");` — sprawdzenie **przed** wywołaniem.

> „To trzecie ostrzeżenie z tej samej rodziny. `CS8600` — wkładasz `null` do zmiennej bez pytajnika; `CS8602` — używasz czegoś z pytajnikiem bez sprawdzenia; `CS8604` — przekazujesz coś z pytajnikiem tam, gdzie pytajnika nie ma. **Jedna informacja, trzy miejsca.**"

### E. Dług z lekcji 3.2 — `Console.ReadLine` naprawdę

Uczeń otwiera dowolny program z modułu 3 z linią `string imie = Console.ReadLine();` i przypomina sobie `CS8600`.

> „Teraz umiesz to przeczytać. Co `ReadLine` obiecuje zwrócić?"
→ `string?` — tekst **albo `null`**, gdy wejście się skończy (np. Ctrl+D na macOS/Linux, Ctrl+Z na Windows).

Wersja bez ostrzeżeń i bez wywrotki:
```csharp
string? imie = Console.ReadLine();

if (string.IsNullOrWhiteSpace(imie))
{
    Console.WriteLine("nic nie wpisano");
    return;
}

Console.WriteLine(imie.Length);
```
→ dla `Ala`: `3`; dla pustego Entera: `nic nie wpisano`. **Zero ostrzeżeń.**

> „`string.IsNullOrWhiteSpace` znasz z 8.2. Zauważ, że po nim kompilator pozwala na `imie.Length` — ta metoda jest opisana tak, że kompilator wie: jeśli zwróciła `false`, tekst tam jest."

> „Wczesne wyjście `return` — lekcja 7.1. Sprawdź raz na górze, potem pisz resztę, jakby `null` nie istniał."

### F. Właściwość bez wartości — `CS8618` z lekcji 8.2

```csharp
class Kot
{
    public string Imie { get; set; }
}
```
→
```
warning CS8618: Non-nullable property 'Imie' must contain a non-null value when exiting constructor. Consider adding the 'required' modifier or declaring the property as nullable.
```

> „Przeczytaj: »właściwość bez pytajnika musi mieć wartość, gdy konstruktor się kończy«. Kot bez konstruktora — jakie ma `Imie` po `new Kot()`?"
→ `null`, jak w 8.1. A typ `string` obiecywał tekst.

Dwa uczciwe wyjścia — **uczeń wybiera, które pasuje do sensu**:

| Sytuacja | Zapis |
| --- | --- |
| kot **zawsze** ma imię | `public string Imie { get; set; } = "";` albo ustawienie w konstruktorze (8.2) |
| kot **może nie mieć** imienia | `public string? Imie { get; set; }` |

> „Pytajnik nie jest sposobem na uciszenie ostrzeżenia. Jest **decyzją projektową**: czy brak tej wartości to normalna sytuacja, czy błąd. Telefon gościa — normalna. Imię kota — raczej błąd."

Podpowiedź `required` w komunikacie — jedno zdanie: „to trzecie wyjście, poza kursem; wystarczą dwa powyższe".

## Krok 4 — Pogłębienie (6 min)

**Cztery ostrzeżenia, jedna informacja**

| Kod | Kiedy | Co zrobić |
| --- | --- | --- |
| `CS8600` | wkładasz `null` (albo coś, co może nim być) do typu bez `?` | dodaj `?` do typu **albo** `??` z wartością zastępczą |
| `CS8602` | używasz `.` na czymś, co może być `null` | `is not null` przed użyciem albo `?.` |
| `CS8604` | przekazujesz coś z `?` do parametru bez `?` | `??` przed wywołaniem |
| `CS8618` | właściwość bez `?` nie dostała wartości w konstruktorze | wartość początkowa **albo** `?`, zależnie od sensu |

> „Żadne z nich nie jest błędem. Wszystkie mają rację."

**Reguła na resztę kursu**

> „**Sprawdź na wejściu, pracuj na `string`.** Pytajnik ma żyć krótko: przy `ReadLine`, przy wczytaniu z pliku (moduł 12), przy szukaniu czegoś, czego może nie być. Zaraz po sprawdzeniu przechodzisz na typ bez pytajnika i reszta kodu nie musi o `null` myśleć."

**Skąd te ostrzeżenia w ogóle**

> „Pamiętasz, że w lekcji 3.2 mówiłem, że starsze poradniki tego ostrzeżenia nie mają? Sprawdzanie `null` przez kompilator jest **włączone** w twoim projekcie — zobaczysz to w lekcji 14.1 jako jedną linię `Nullable` w pliku projektu. W starym kodzie te same błędy istniały, tylko wychodziły dopiero u użytkownika."

**Liczby też mogą nie mieć wartości**

```csharp
int? wiek = null;
Console.WriteLine(wiek is null);
Console.WriteLine(wiek ?? 0);
wiek = 5;
Console.WriteLine(wiek + 1);
```
→ `True`, `0`, `6`

> „`int` nigdy nie jest `null` — startuje od zera (8.1). `int?` może być. Kiedy to potrzebne?"
→ gdy zero **coś znaczy**: wiek `0` to noworodek, wiek „nie podano" to co innego. Jedno zdanie i dalej; w tym kursie `int?` prawie się nie pojawi.

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „`null` i typy nullowalne". Propozycje:

- 🔥 **Rozgrzewka** (`24-null-a.cs`): weź swój program z lekcji 3.2, który wczytuje imię i wiek. Przepisz go tak, żeby `dotnet build` nie pokazał **ani jednego** `warning CS86xx`, a puste wejście (sam Enter) dawało komunikat zamiast wywrotki. Wklej mi wynik `dotnet build` (ma nie zawierać linii `warning`) i wynik dla pustego wejścia.
- ⭐ **Główne** (`24-null-b.cs`): klasa `Kontakt` z właściwościami `Imie` (zawsze jest), `Telefon` i `Email` (mogą nie być). `ToString()` ma wypisać `Ala, tel. 600100200, e-mail: brak` — dla brakujących danych słowo `brak` przez `??`. Metoda `bool MoznaZadzwonic()` zwraca, czy jest telefon. Utwórz trzech kontaktów: z kompletem danych, bez telefonu, bez niczego poza imieniem. Wypisz wszystkich i dla każdego, czy da się zadzwonić. **Zero ostrzeżeń.**
- ⚡ **Gwiazdka** (`24-null-c.cs`): klasa `Ksiazka` z `Tytul` i `string? Isbn`. Lista książek, w tym jedna bez ISBN. Metoda `Ksiazka? Znajdz(List<Ksiazka> lista, string tytul)` zwraca książkę **albo `null`**, gdy nie ma takiej — to twoja pierwsza metoda, która uczciwie mówi w nagłówku, że może nic nie znaleźć. Wywołaj ją trzy razy: dla książki z ISBN, bez ISBN i dla tytułu, którego nie ma, i wypisz w jednej linii każde z: `978-83-1`, `brak ISBN`, `nie ma takiej książki` — używając `?.` i `??`, bez ani jednego `if` po stronie wywołania. Zero ostrzeżeń.

Gwiazdka pokazuje, po co `?` w **typie zwracanym**: `Znajdz` nie musi rzucać wyjątku ani zwracać „pustej książki" — mówi wprost „może nic nie być" i wołający sam decyduje, co z tym zrobić. Wraca w 12.3 (`Deserialize` zwraca `T?`) i w 13.1 (`FirstOrDefault`).

## Pułapki

- **Pytajnik jako wyciszacz.** `string?` wszędzie, „bo kompilator się czepia" — wtedy każde użycie wymaga sprawdzenia i kod tonie w `if`. Pytajnik tylko tam, gdzie brak jest **normalny**.
- **Wykrzyknik `imie!`** — uczeń znajdzie go w internecie jako „sposób na ostrzeżenie". To obietnica „ja wiem lepiej, tu nie ma `null`" — kompilator milknie, a wywrotka zostaje. W tym kursie **nie używamy**.
- **`?.` w warunku** — `if (imie?.Length > 2)` działa (dla `null` całość jest fałszem), ale czyta się źle. Lepiej najpierw `is not null`.
- **Sprawdzenie zbyt daleko od użycia** — sprawdziłeś w linii 5, użyłeś w linii 40, a między nimi ktoś przypisał `null`. Reguła: sprawdź i **od razu** przejdź na typ bez pytajnika.
- **`== ""` zamiast `IsNullOrWhiteSpace`** — pusty tekst to nie `null`; oba trzeba obsłużyć, a `IsNullOrWhiteSpace` robi to naraz.
- **`CS8618` uciszone pytajnikiem bez zastanowienia** — kot bez imienia wchodzi do programu i wywraca go dwie klasy dalej.
- **Mieszanie `== null` i `is null`** — oba działają; wybierz jedno w pliku. Kurs używa `is null`.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Sekcja `[moduł 8]` i `[moduł 3]`. To, co uczeń zobaczy w starszych materiałach:

| Stare materiały | Dzisiaj |
| --- | --- |
| `string s = Console.ReadLine();` bez ostrzeżenia | to samo daje `CS8600` — sprawdzanie `null` włączone domyślnie w nowych projektach (C# 8, .NET 6+) |
| `if (s != null && s.Length > 0)` | `if (!string.IsNullOrWhiteSpace(s))` albo `is not null` |
| `s == null ? "brak" : s` | `s ?? "brak"` |
| `if (kot != null) kot.Miaucz();` | `kot?.Miaucz();` |

> „Stary kod bez tych ostrzeżeń **nie był bezpieczniejszy** — te same wywrotki działy się u użytkownika zamiast w kompilatorze. Ostrzeżenia to postęp, nie utrudnienie."

## Notatki tutora

- **Zacznij od kroku 2 z `string imie = null`** — uczeń ma zobaczyć dwa ostrzeżenia **i** wywrotkę naraz. Dopiero wtedy `string?` ma sens jako „uczciwość wobec kompilatora".
- **Krok 3.A jest sercem lekcji:** ostrzeżenie znika po sprawdzeniu. Niech uczeń sam usunie `if` i zobaczy, że wraca. To zamienia ostrzeżenie z „czerwonego szumu" w rozmowę z kompilatorem.
- **Nie wprowadzaj `!` (null-forgiving), `required`, `[NotNullWhen]`, `?[]`, `??=`.** Jedno zdanie o `!` jest w Pułapkach, bo uczeń na pewno go zobaczy.
- **Nie rozwijaj `int?`** poza przykład z kroku 4. `Nullable<T>`, `HasValue`, `.Value` — poza kursem.
- **Nie tłumacz, jak kompilator śledzi przepływ** („flow analysis"). „Po sprawdzeniu kompilator wie" wystarcza.
- **Uczeń z polskim systemem** zobaczy komunikaty po polsku (`CS8600: Konwertowanie literału null...`). Kod `CSxxxx` jest ten sam — czytajcie od kodu, jak w skillu `review-kodu`.
- Jeśli uczeń pyta, czemu tego nie było w 3.2 — powiedz wprost: „bo nie znałeś jeszcze `null` ani `if`. Teraz masz oba i lekcja zajęła pół godziny zamiast dwóch".
- **Moduł 8 zamyka się tutaj, nie w 8.4.** Powiedz uczniowi: umie tworzyć własne typy, które same pilnują swojej poprawności — także wtedy, gdy czegoś w nich brakuje. Gdy napisze `Kot` i `Pies`, okaże się, że połowa kodu jest identyczna — to moduł 9. Zaproponuj quiz przed dziedziczeniem.
