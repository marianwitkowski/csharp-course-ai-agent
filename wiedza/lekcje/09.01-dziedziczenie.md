# Lekcja 9.1 — Dziedziczenie

## Cel
Po lekcji uczeń:
- Wydziela wspólną część dwóch klas do klasy bazowej
- Zapisuje dziedziczenie dwukropkiem: `class Kot : Zwierze`
- Wywołuje konstruktor bazowy przez `: base(...)`
- Zna `protected` i wie, czym różni się od `private` i `public`
- Umie sprawdzić, czy dziedziczenie w ogóle ma sens (test „jest rodzajem")

## Krok 1 — Zakotwiczenie (5-8 min)

**Pytanie wejściowe:**
> „Pies i kot. Wymień trzy rzeczy, które je łączą, i trzy, które je różnią."

**Co chcesz usłyszeć:** wspólne — imię, wiek, jedzenie, oddychanie; różne — głos, sposób poruszania, zachowanie.

**Drugie pytanie:**
> „Gdybyś pisał encyklopedię, opisałbyś »ma imię i wiek« osobno przy psie i przy kocie?"

**Co chcesz usłyszeć:** nie — raz, w haśle „zwierzę", a przy psie i kocie tylko to, co je wyróżnia.

**Trzecie pytanie:**
> „Czy pies **jest rodzajem** zwierzęcia? A czy silnik jest rodzajem samochodu?"

**Co chcesz usłyszeć:** pies tak, silnik nie — silnik jest **częścią** samochodu. Zapamiętaj to rozróżnienie; wraca w kroku 4 i decyduje o tym, czy dziedziczenie jest właściwym narzędziem.

## Krok 2 — Mostek (12 min)

**Najpierw pokaż problem.** Niech uczeń napisze dwie klasy bez żadnych sztuczek:

```csharp
class Kot
{
    public string Imie { get; }
    public int Wiek { get; }
    public Kot(string imie, int wiek) { Imie = imie; Wiek = wiek; }
    public void Przedstaw() => Console.WriteLine($"Jestem {Imie}, mam {Wiek} lat");
}

class Pies
{
    public string Imie { get; }
    public int Wiek { get; }
    public Pies(string imie, int wiek) { Imie = imie; Wiek = wiek; }
    public void Przedstaw() => Console.WriteLine($"Jestem {Imie}, mam {Wiek} lat");
}
```

> „Zaznacz w tych dwóch klasach wszystko, co jest identyczne."
→ **prawie wszystko.** Różni się tylko nazwa.

> „Dodajesz teraz do obu pole `Wlasciciel`. Ile miejsc poprawiasz?"
→ dwa. A przy pięciu gatunkach — pięć.

**Mostek:**
> „Wspólną część można zapisać **raz**, w osobnej klasie, a pozostałe klasy powiedzą »jestem tym samym, tylko trochę innym«. To się nazywa **dziedziczenie**."

Uczeń tworzy `kurs/zadania/25-dziedziczenie.cs`:

```csharp
Kot k = new Kot("Mruczek", 3);
Pies p = new Pies("Burek", 5);

k.Przedstaw();
p.Przedstaw();

class Zwierze
{
    public string Imie { get; }
    public int Wiek { get; }

    public Zwierze(string imie, int wiek)
    {
        Imie = imie;
        Wiek = wiek;
    }

    public void Przedstaw() => Console.WriteLine($"Jestem {Imie}, mam {Wiek} lat");
}

class Kot : Zwierze
{
    public Kot(string imie, int wiek) : base(imie, wiek) { }
}

class Pies : Zwierze
{
    public Pies(string imie, int wiek) : base(imie, wiek) { }
}
```
→ dwa przedstawienia, tak jak wcześniej.

**Pytania:**
- „Gdzie jest teraz `Imie`? Ile razy je napisałeś?"
- „Co robi dwukropek w `class Kot : Zwierze`?" → „Kot **jest** zwierzęciem"
- „Czemu `Kot` ma metodę `Przedstaw`, skoro jej nie napisałeś?" → **odziedziczył ją**

Nazwij: **klasa bazowa** (`Zwierze`), **klasa pochodna** (`Kot`), **dziedziczenie**.

## Krok 3 — Eksperyment (25 min)

### A. `base(...)` — konstruktor bazowy

Niech uczeń **usunie** `: base(imie, wiek)` z konstruktora kota:

```csharp
public Kot(string imie, int wiek) { }
```
→ `CS7036: There is no argument given that corresponds to the required parameter 'imie' of 'Zwierze.Zwierze(string, int)'`

> „Kompilator mówi, że nie podałeś argumentów konstruktorowi zwierzęcia. Czemu w ogóle chce je od kota?"
→ bo **kot jest zwierzęciem** — zanim powstanie kot, musi powstać zwierzę pod spodem. A zwierzę wymaga imienia i wieku.

> „Kolejność: co powstaje pierwsze?"
→ najpierw część bazowa, potem pochodna. `base(...)` wykonuje się **przed** ciałem konstruktora kota.

Pokaż to:
```csharp
public Kot(string imie, int wiek) : base(imie, wiek)
{
    Console.WriteLine("konstruktor kota");
}
```
i dopisz `Console.WriteLine("konstruktor zwierzęcia");` w bazie.
→ najpierw „zwierzęcia", potem „kota".

### B. Klasa pochodna dokłada swoje

```csharp
class Kot : Zwierze
{
    public bool Wychodzacy { get; }

    public Kot(string imie, int wiek, bool wychodzacy) : base(imie, wiek)
    {
        Wychodzacy = wychodzacy;
    }

    public void Drapie() => Console.WriteLine($"{Imie} drapie kanapę");
}
```

```csharp
Kot k = new Kot("Mruczek", 3, true);
k.Przedstaw();
k.Drapie();
Console.WriteLine(k.Wychodzacy);
```

> „Ile rzeczy potrafi `Kot`?"
→ wszystko, co `Zwierze`, **plus** swoje własne.

> „A czy `Pies` potrafi `Drapie`?"
→ nie. Dziedziczenie idzie w jedną stronę: pochodna zna bazową, bazowa nie wie o pochodnych.

### C. `protected` — trzeci poziom dostępu

W lekcji 8.4 uczeń poznał `private` i `public`. Teraz:

```csharp
class Zwierze
{
    private int energia = 100;

    public void Biegnij()
    {
        energia = energia - 10;
    }
}

class Pies : Zwierze
{
    public void Aportuj()
    {
        energia = energia - 5;
    }
}
```
→ `CS0122: 'Zwierze.energia' is inaccessible due to its protection level`

> „`Pies` dziedziczy po `Zwierze`. Czemu nie widzi jego pola?"
→ bo `private` znaczy **„tylko ta klasa"**, a `Pies` to inna klasa.

Naprawa:
```csharp
protected int energia = 100;
```
→ działa.

| Modyfikator | Widoczne dla |
| --- | --- |
| `private` | tylko tej klasy |
| `protected` | tej klasy **i klas dziedziczących** |
| `public` | wszystkich |

> „`protected` to »rodzina, ale nie obcy«. Używaj go, gdy klasy pochodne naprawdę potrzebują dostępu — nie na zapas."

### D. Co się dziedziczy, a co nie

Niech uczeń sprawdzi:

| Element bazy | Dziedziczony? |
| --- | --- |
| pola i właściwości `public` / `protected` | tak |
| metody `public` / `protected` | tak |
| składowe `private` | **istnieją, ale są niewidoczne** |
| konstruktory | **nie** — trzeba napisać własny i wywołać `base(...)` |

> „Konstruktory się nie dziedziczą i to zaskakuje. Powód: konstruktor kota musi zdecydować, **co** przekazać zwierzęciu."

### E. Jedna baza, nie więcej

```csharp
class Dziwo : Kot, Pies { }
```
→ `CS1721: Class 'Dziwo' cannot have multiple base classes`

> „W C# klasa dziedziczy po **jednej** klasie. Czemu, jak myślisz?"
→ przy dwóch bazach z metodą o tej samej nazwie nie wiadomo, którą wziąć.

> „Co, jeśli coś naprawdę jest dwiema rzeczami naraz?"
→ do tego są **interfejsy**, moduł 10. Nazwa i numer, dalej.

### F. Łańcuch dziedziczenia

```csharp
class Zwierze { }
class Ssak : Zwierze { }
class Kot : Ssak { }
```

> „Ile poziomów widzi `Kot`?"
→ wszystkie w górę: `Ssak` i `Zwierze`.

**Nie buduj głębokich łańcuchów.** Dwa–trzy poziomy to praktyczna granica; głębiej trudno powiedzieć, skąd co pochodzi.

## Krok 4 — Pogłębienie (10 min)

**Test „jest rodzajem"**

Zanim napiszesz `class A : B`, przeczytaj na głos: **„A jest rodzajem B"**.

| Zdanie | Sens? | Wniosek |
| --- | --- | --- |
| Kot jest rodzajem zwierzęcia | tak | dziedziczenie |
| Kwadrat jest rodzajem figury | tak | dziedziczenie |
| Silnik jest rodzajem samochodu | **nie** | samochód **ma** silnik → pole |
| Adres jest rodzajem osoby | **nie** | osoba **ma** adres → pole |

> „Gdy zdanie brzmi głupio, właściwą odpowiedzią jest pole, nie dziedziczenie. To się nazywa »ma« zamiast »jest«."

To najczęstsza pomyłka początkujących w OOP i warto ją nazwać wprost.

**Kiedy dziedziczenie się nie opłaca**

- gdy wspólna część to jedno pole → prościej powtórzyć
- gdy klasy pochodne nie mają nic wspólnego poza nazwą
- gdy dziedziczysz tylko po to, żeby użyć jednej metody → wtedy lepsze pole albo metoda pomocnicza

> „Dziedziczenie kosztuje: związuje klasy na stałe. Zmiana w bazie dotyka wszystkich pochodnych."

**`sealed` — do rozpoznania**
```csharp
sealed class Kot : Zwierze { }
```
> „`sealed` znaczy »po tej klasie nie da się już dziedziczyć«. Zobaczysz to w bibliotekach. W kursie nie używamy."

**Wszystko dziedziczy po `object`**

```csharp
Kot k = new Kot("Mruczek", 3);
Console.WriteLine(k.GetType());
Console.WriteLine(k.ToString());
```
> „Skąd `Kot` ma `ToString` i `GetType`, skoro ich nie napisałeś ani ty, ani `Zwierze`?"
→ bo **każda klasa w C# dziedziczy po `object`**, nawet gdy tego nie napiszesz. Stamtąd pochodzi `ToString`, którego użyłeś w lekcji 8.2.

To domyka pytanie, które mogło się tam pojawić: **`override` w `ToString` nadpisywało metodę odziedziczoną po `object`.**

## Pułapki

- **Brak `: base(...)`, gdy baza wymaga argumentów** → `CS7036`.
- **`private` w bazie niewidoczne dla pochodnej** → `CS0122`. Do tego jest `protected`.
- **Dwie klasy bazowe** → `CS1721`. Jedna baza, koniec.
- **Oczekiwanie, że konstruktory się dziedziczą** — nie dziedziczą.
- **Dziedziczenie „bo wygodnie"** — zamiast testu „jest rodzajem". Objaw: klasa pochodna używa 10% tego, co odziedziczyła.
- **Głęboki łańcuch** — pięć poziomów i nikt nie wie, gdzie jest która metoda.
- **`protected` na wszystkim** — to `public` w przebraniu, tylko dla rodziny. Domyślnie `private`.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Ta lekcja nie ma zmian. Dziedziczenie wygląda w C# tak samo od pierwszej wersji języka.

Warto natomiast wiedzieć, że w nowszym kodzie dziedziczenia jest **mniej** niż w materiałach z lat 2000. Częściej używa się interfejsów (moduł 10) i składania obiektów z mniejszych części (lekcja 10.3). Dziedziczenie zostaje tam, gdzie „jest rodzajem" jest naprawdę prawdziwe.

## Notatki tutora

- **Krok 2 musi zacząć się od duplikatu.** Uczeń ma zobaczyć dwie prawie identyczne klasy i sam policzyć, ile miejsc trzeba poprawić. Bez tego dziedziczenie jest składnią bez powodu.
- **Krok 4 (test „jest rodzajem") jest ważniejszy niż cała składnia tej lekcji.** Uczeń, który go zapamięta, uniknie najczęstszego błędu w projektowaniu klas.
- **`object` w kroku 4 domyka `override` z lekcji 8.2** — ale nie tłumacz jeszcze samego `override`. To 9.2, następna lekcja.
- **Nie wprowadzaj `virtual`.** Uczeń zapyta, czemu `Przedstaw` mówi to samo dla psa i kota — to jest dokładnie pytanie otwierające lekcję 9.2. **Zanotuj je i odłóż.**
- **Nie wprowadzaj interfejsów.** Krok 3.E kończy się nazwą i numerem modułu.
- **Nie wprowadzaj `abstract`.** To 9.3.
- Jeśli uczeń chce dziedziczyć wszystko po wszystkim — wróć do testu „jest rodzajem" i każ przeczytać na głos. Zwykle wystarcza.
