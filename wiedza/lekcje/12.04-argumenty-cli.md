# Lekcja 12.4 — Argumenty wiersza poleceń

## Cel
Po lekcji uczeń:
- Odczytuje argumenty przekazane programowi przez tablicę `args`
- Uruchamia program z argumentami: `dotnet run plik.cs -- coś`
- Sprawdza liczbę argumentów **zanim** po nie sięgnie
- Rozumie różnicę między pytaniem użytkownika a przyjęciem argumentu
- Pisze program, który da się użyć w skrypcie, nie tylko ręcznie

> **To ostatnia lekcja modułu 12** i pierwsza, po której program przestaje wymagać człowieka przy klawiaturze.

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Wpisujesz w terminalu `dotnet run 34-pliki.cs`. Ile słów podałeś? Skąd `dotnet` wie, co uruchomić?"

**Co chcesz usłyszeć:** nazwa pliku jest **argumentem** dla `dotnet`.

**Drugie pytanie:**
> „Twój program z lekcji 12.1 pytał użytkownika o nazwę pliku przez `Console.ReadLine`. A gdybyś chciał uruchomić go sto razy dla stu plików?"

**Co chcesz usłyszeć:** ktoś musiałby sto razy coś wpisać. **To nie da się zautomatyzować.**

**Trzecie pytanie:**
> „Jak działają programy, których używasz w terminalu — `ls`, `cat`, `dotnet`? Pytają cię o coś po uruchomieniu?"

**Co chcesz usłyszeć:** nie, wszystko dostają od razu w linii poleceń.

## Krok 2 — Mostek (12 min)

**Mostek:**
> „Program dostaje to, co wpisano po jego nazwie, jako **tablicę tekstów**. W C# nazywa się ona `args` i jest dostępna od razu, bez deklarowania."

Uczeń tworzy `kurs/zadania/37-argumenty.cs`:

```csharp
Console.WriteLine($"Argumentów: {args.Length}");

for (int i = 0; i < args.Length; i++)
{
    Console.WriteLine($"  [{i}] {args[i]}");
}
```

Uruchomienie — **zwróć uwagę na podwójny myślnik**:
```sh
dotnet run 37-argumenty.cs -- raport.txt --pelny 42
```
→
```
Argumentów: 3
  [0] raport.txt
  [1] --pelny
  [2] 42
```

**Pytania:**
- „Czym jest `args`?" → **tablicą tekstów** z lekcji 6.1. Wszystko, co o niej wiesz, działa.
- „Po co `--` przed argumentami?" → oddziela argumenty **dla `dotnet run`** od argumentów **dla twojego programu**. Bez niego `dotnet` wziąłby je dla siebie.
- „Czy `42` jest liczbą?" → **nie.** Argumenty są zawsze tekstem — tak jak `Console.ReadLine` z lekcji 3.2.

Uruchom bez argumentów:
```sh
dotnet run 37-argumenty.cs
```
→ `Argumentów: 0`

> **`args` nigdy nie jest `null`** — przy braku argumentów jest **pustą tablicą**. Pętla po niej po prostu się nie wykona.

## Krok 3 — Eksperyment (22 min)

### A. Sprawdź, zanim sięgniesz

```csharp
Console.WriteLine(args[0]);
```
uruchomione bez argumentów →
```
Unhandled exception. System.IndexOutOfRangeException: Index was outside the bounds of the array.
```

> „Znasz ten wyjątek z lekcji 6.1. Jak się przed nim zabezpieczyć?"

```csharp
if (args.Length == 0)
{
    Console.WriteLine("Użycie: dotnet run 37-argumenty.cs -- <nazwa-pliku>");
    return;
}

Console.WriteLine($"Przetwarzam: {args[0]}");
```

> „`return` w programie jednoplikowym kończy cały program — jak `return` w metodzie z lekcji 7.1."

**Wypisanie sposobu użycia przy braku argumentów to standard.** Każdy program w terminalu tak robi.

### B. Argument jako nazwa pliku

To łączy całą wiedzę z modułu 12:

```csharp
if (args.Length == 0)
{
    Console.WriteLine("Użycie: ... -- <plik>");
    return;
}

string sciezka = args[0];

if (!File.Exists(sciezka))
{
    Console.WriteLine($"Nie ma pliku: {sciezka}");
    return;
}

string[] linie = File.ReadAllLines(sciezka);
Console.WriteLine($"{Path.GetFileName(sciezka)}: {linie.Length} linii");
```

Uczeń uruchamia to na pliku z lekcji 12.1:
```sh
dotnet run 37-argumenty.cs -- zakupy.txt
```

> „Ile razy program zapytał cię o cokolwiek?"
→ ani razu. **To jest narzędzie, nie rozmowa.**

### C. Argument jako liczba

```csharp
if (args.Length < 2 || !int.TryParse(args[1], out int ile))
{
    Console.WriteLine("Użycie: ... -- <plik> <liczba-linii>");
    return;
}

string[] linie = File.ReadAllLines(args[0]);

for (int i = 0; i < Math.Min(ile, linie.Length); i++)
{
    Console.WriteLine(linie[i]);
}
```

> „Czemu `TryParse`, a nie `Parse`?"
→ bo argument pochodzi **od użytkownika**, tak samo jak wpis z klawiatury. Zasada z lekcji 2.3 obowiązuje bez zmian.

> „Co robi `Math.Min`?"
→ bierze mniejszą z dwóch liczb — zabezpiecza przed żądaniem stu linii z pliku, który ma trzy.

### D. Przełączniki

```csharp
bool pelny = false;
string? plik = null;

foreach (string a in args)
{
    if (a == "--pelny")
    {
        pelny = true;
    }
    else
    {
        plik = a;
    }
}

Console.WriteLine($"plik: {plik}, tryb pełny: {pelny}");
```

Uruchom na trzy sposoby:
```sh
dotnet run 37-argumenty.cs -- dane.txt
dotnet run 37-argumenty.cs -- dane.txt --pelny
dotnet run 37-argumenty.cs -- --pelny dane.txt
```

> „Czy kolejność ma znaczenie?"
→ **nie** — bo pętla sprawdza każdy argument osobno. Tak działają prawdziwe narzędzia.

To jest pierwszy raz, gdy uczeń pisze coś, co zachowuje się jak `ls -l` czy `dotnet build`.

### E. Argumenty ze spacjami

```sh
dotnet run 37-argumenty.cs -- "moje dane.txt"
```
→ jeden argument, nie dwa.

> „Cudzysłowy nie trafiają do programu — to terminal decyduje, gdzie kończy się argument."

Niech uczeń sprawdzi bez cudzysłowów i porówna `args.Length`.

### F. Kompletne małe narzędzie

Połącz wszystko:

```csharp
if (args.Length == 0)
{
    Console.WriteLine("Użycie: dotnet run 37-argumenty.cs -- <plik> [--liczby]");
    return;
}

string? sciezka = null;
bool tylkoLiczby = false;

foreach (string a in args)
{
    if (a == "--liczby")
    {
        tylkoLiczby = true;
    }
    else
    {
        sciezka = a;
    }
}

if (sciezka == null)
{
    Console.WriteLine("Nie podałeś nazwy pliku.");
    return;
}

if (!File.Exists(sciezka))
{
    Console.WriteLine($"Nie ma pliku: {sciezka}");
    return;
}

int licznik = 0;

foreach (string linia in File.ReadAllLines(sciezka))
{
    if (tylkoLiczby && !int.TryParse(linia, out _))
    {
        continue;
    }

    licznik++;
    Console.WriteLine(linia);
}

Console.WriteLine($"--- pasujących linii: {licznik}");
```

> „Czemu nie `string sciezka = args[0];`?"
→ bo `args[0]` bywa **przełącznikiem**, gdy użytkownik napisze `-- --liczby dane.txt`. Pętla z kroku D rozdziela jedno od drugiego i kolejność przestaje mieć znaczenie.

> „`out _` — podkreślnik zamiast nazwy zmiennej. Co to znaczy?"
→ „nie interesuje mnie wynik, sprawdzam tylko, czy się udało". To ta sama zasada co `_` w wyrażeniu `switch` z lekcji 4.3.

## Krok 4 — Pogłębienie (10 min)

**Argumenty kontra `Console.ReadLine`**

| | argumenty | pytanie w programie |
| --- | --- | --- |
| kiedy podawane | przed uruchomieniem | w trakcie |
| da się zautomatyzować | **tak** | nie |
| dobre do | narzędzi, skryptów | programów interaktywnych |
| przy braku danych | wypisz sposób użycia | zapytaj ponownie |

> „To nie jest wybór »lepsze-gorsze«. Program instalacyjny pyta. Narzędzie do przetwarzania plików — nie."

Wiele programów robi **oba**: bierze argument, jeśli jest, a pyta, gdy go brak.

```csharp
string plik = args.Length > 0 ? args[0] : Console.ReadLine() ?? "";
```
> „Operator warunkowy z lekcji 4.2. Jedna linia, dwa sposoby użycia."

**Konwencje nazewnicze**

| Zapis | Znaczenie |
| --- | --- |
| `plik.txt` | argument pozycyjny — sama wartość |
| `--pelny` | przełącznik: jest albo go nie ma |
| `--wyjscie raport.txt` | opcja z wartością |
| `-p` | skrót przełącznika |

> „Nikt tego nie wymusza — to zwyczaj. Ale program, który go łamie, wygląda obco."

**Gotowe biblioteki**

> „Przy większej liczbie opcji ręczne rozbieranie `args` robi się męczące. Istnieją do tego biblioteki. W tym kursie zostajemy przy pętli — dla trzech argumentów to w zupełności wystarcza."

**W projekcie z modułu 14**

> „Twój projekt końcowy będzie narzędziem wiersza poleceń. Ta lekcja jest jego wejściem: `args` na początku, sposób użycia przy braku argumentów, `TryParse` na liczbach."

**Kod wyjścia**

```csharp
if (!File.Exists(sciezka))
{
    Console.WriteLine($"Nie ma pliku: {sciezka}");
    Environment.Exit(1);
}
```

> „Programy w terminalu zwracają liczbę: zero znaczy »udało się«, cokolwiek innego — »coś poszło źle«. Skrypty na tym polegają."

**Pokaż, nie ćwicz.** Wróci przy `dotnet publish` w lekcji 14.4.

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „argumenty wiersza poleceń". **Przypomnij o `--` przy uruchamianiu.** Propozycje:

- 🔥 **Rozgrzewka** (`37-argumenty-a.cs`): program wypisujący każdy argument w osobnej linii z numerem, a przy braku argumentów — komunikat o sposobie użycia. Uruchom go czterokrotnie: bez argumentów, z jednym, z trzema i z jednym zawierającym spację.
- ⭐ **Główne** (`37-argumenty-b.cs`): licznik słów. Program przyjmuje nazwę pliku i wypisuje: liczbę linii, słów i znaków. Przy braku argumentu — sposób użycia; przy nieistniejącym pliku — czytelny komunikat. Przetestuj na pliku z ćwiczeń lekcji 12.1.
- ⚡ **Gwiazdka** (`37-argumenty-c.cs`): wyszukiwarka w pliku, na wzór `grep`. Program przyjmuje **dwa** argumenty pozycyjne (szukany tekst i nazwę pliku) oraz opcjonalny przełącznik `--bez-wielkosci` (ignoruje wielkość liter). Wypisuje pasujące linie z numerami i na końcu ich liczbę. Zwróć uwagę na kolejność: przełącznik ma działać niezależnie od tego, gdzie stoi.

Gwiazdka to pierwsze narzędzie w kursie, którego uczeń może naprawdę używać poza nauką.

## Pułapki

- **Brak `--` przy `dotnet run`** — argumenty trafiają do `dotnet`, nie do programu. Objaw: `args.Length` równe zeru mimo podanych argumentów.
- **`args[0]` bez sprawdzenia długości** → `IndexOutOfRangeException`.
- **`args[0]` jako nazwa pliku, gdy program ma przełączniki** — użytkownik postawi przełącznik na początku i program dostanie `--pelny` zamiast nazwy pliku.
- **`Parse` zamiast `TryParse`** na argumencie — argument to dane od użytkownika.
- **Zakładanie kolejności argumentów** — użytkownik poda je w innej. Przełączniki sprawdzaj pętlą.
- **Brak komunikatu o sposobie użycia** — program uruchomiony bez argumentów milczy albo się przewraca.
- **Ścieżka względna w argumencie** — liczy się od katalogu uruchomienia, nie od położenia programu (12.2).
- **Spacje bez cudzysłowów** — `moje dane.txt` to dwa argumenty.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Sekcja `[moduł 1]` wspominała, że `string[] args` **nadal działa** w instrukcjach najwyższego poziomu. Tu widać, co to znaczy w praktyce: zmienna `args` jest dostępna sama z siebie, bez deklarowania.

W starszych materiałach argumenty przychodziły jako parametr `Main`:
```csharp
static void Main(string[] args) { ... }
```
To ta sama tablica, tylko podana jawnie. Dziś kompilator udostępnia ją bez pisania nagłówka.

## Notatki tutora

- **Nie wprowadzaj bibliotek do parsowania argumentów.** Jedno zdanie w kroku 4.
- **Nie rozwijaj kodów wyjścia.** Pokaz, wraca w 14.4.
