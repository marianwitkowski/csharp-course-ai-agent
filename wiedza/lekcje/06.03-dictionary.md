# Lekcja 6.3 — `Dictionary<TKey, TValue>`

## Cel
Po lekcji uczeń:
- Tworzy słownik i wie, że szuka się w nim po **kluczu**, nie po numerze
- Dodaje pary dwoma sposobami i zna różnicę między nimi
- Bezpiecznie odczytuje wartość przez `TryGetValue` — tym samym wzorcem co `TryParse`
- Przechodzi po słowniku pętlą `foreach`
- Rozpoznaje `KeyNotFoundException` i wie, czemu klucze muszą być unikalne

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Książka telefoniczna. Szukasz numeru do Kowalskiego. Czy przeglądasz ją od pierwszej strony, sprawdzając każdy wpis po kolei?"

**Co chcesz usłyszeć:** nie — otwierasz na literze K.

**Drugie pytanie:**
> „A gdybyś miał **numer** i szukał, do kogo należy?"

**Co chcesz usłyszeć:** wtedy trzeba by przejrzeć wszystko. Książka jest ułożona pod jedno pytanie, nie pod oba.

**To jest sedno tej lekcji:** słownik odpowiada szybko na **jedno** pytanie — „co jest pod tym kluczem".

**Trzecie pytanie:**
> „Czy w książce telefonicznej mogą być dwa wpisy o dokładnie tym samym nazwisku i imieniu?"

Uczeń zwykle mówi „mogą". Odpowiedz: „w słowniku w C# **nie mogą** — klucz musi być jedyny. Zaraz zobaczysz, co się stanie, gdy spróbujesz."

## Krok 2 — Mostek (10 min)

**Mostek:**
> „W tablicy i liście szukałeś po numerze: `zakupy[0]`. W **słowniku** szukasz po tym, co sam wybierzesz — po nazwisku, po nazwie produktu, po dowolnym kluczu."

Uczeń tworzy `kurs/zadania/16-dictionary.cs`:

```csharp
Dictionary<string, int> wiek = new Dictionary<string, int>();

wiek["Ala"] = 30;
wiek["Bo"] = 25;
wiek["Cyd"] = 40;

Console.WriteLine(wiek["Ala"]);
Console.WriteLine($"Wpisów: {wiek.Count}");
```
→ `30` i `Wpisów: 3`

**Pytania:**
- „Co jest w nawiasach ostrych?" → **dwa** typy: najpierw klucza, potem wartości. Tu: tekst → liczba.
- „Czym różni się `wiek[\"Ala\"]` od `zakupy[0]` z lekcji 6.2?" → w nawiasach stoi tekst, nie numer.
- „Czy kolejność wpisów ma tu znaczenie?" → nie. W słowniku nie ma „pierwszego" i „trzeciego" w sensie, w jakim ma je lista.

Nazwij: **klucz** i **wartość**, a całość — **słownik**.

> **Nazwa nie jest przypadkowa.** W słowniku języka też szukasz po haśle, a nie po numerze strony.

## Krok 3 — Eksperyment (25 min)

### A. Dwa sposoby dodawania — i różnica między nimi

```csharp
Dictionary<string, int> wiek = new Dictionary<string, int>();

wiek["Ala"] = 30;      // sposób 1: indeksator
wiek.Add("Bo", 25);    // sposób 2: Add
```

Obie linie dodają wpis. Ale teraz:

```csharp
wiek["Ala"] = 31;      // działa — nadpisuje
Console.WriteLine(wiek["Ala"]);
```
→ `31`

a potem:
```csharp
wiek.Add("Ala", 32);   // przewraca program
```
→
```
Unhandled exception. System.ArgumentException: An item with the same key has already been added. Key: Ala
```

> „Ta sama operacja, dwa różne zachowania. Które z nich chcesz w jakiej sytuacji?"
→ `[klucz] =` gdy nadpisanie jest w porządku (np. aktualizacja wieku); `Add` gdy duplikat oznacza błąd i chcesz o nim wiedzieć.

**To jest wybór świadomy, nie kwestia gustu.** Uczeń, który używa tylko `[klucz] =`, nigdy się nie dowie, że coś nadpisał przez pomyłkę.

### B. Klucz, którego nie ma

```csharp
Console.WriteLine(wiek["Nikt"]);
```
→
```
Unhandled exception. System.Collections.Generic.KeyNotFoundException: The given key 'Nikt' was not present in the dictionary.
```

> „Przeczytaj komunikat. Czy to przypomina ci coś z lekcji 6.1?"
→ `IndexOutOfRangeException` przy tablicy. Ta sama sytuacja: sięgasz po coś, czego nie ma.

### C. `TryGetValue` — znajomy wzorzec

```csharp
bool jest = wiek.TryGetValue("Nikt", out int ile);
Console.WriteLine($"Znaleziono: {jest}, wartość: {ile}");
```
→ `Znaleziono: False, wartość: 0`

> „Popatrz na tę linię i powiedz, co ci przypomina."
→ **`int.TryParse` z lekcji 2.3.** Ten sam wzorzec: zwraca `bool`, wartość wkłada do zmiennej po `out`, nie przewraca programu.

> „Skoro nazwa zaczyna się od `Try`, czego się spodziewasz po innych metodach o takiej nazwie?"

**To jest konwencja, nie przypadek.** W C# `TryCoś` znaczy: „spróbuję, powiem ci `bool`, czy się udało, i nie przewrócę programu". Uczeń rozpozna teraz każdą taką metodę, także tę, której jeszcze nie zna.

Wersja z reakcją:
```csharp
if (wiek.TryGetValue("Ala", out int wiekAli))
{
    Console.WriteLine($"Ala ma {wiekAli} lat.");
}
else
{
    Console.WriteLine("Nie znam takiej osoby.");
}
```

### D. `ContainsKey` — i czemu `TryGetValue` jest lepsze

```csharp
if (wiek.ContainsKey("Ala"))
{
    Console.WriteLine(wiek["Ala"]);
}
```

> „To też działa. Ile razy ten kod szuka klucza `Ala` w słowniku?"
→ **dwa razy**: raz w `ContainsKey`, raz przy odczycie.

> „A wersja z `TryGetValue`?"
→ raz.

Przy trzech wpisach to bez znaczenia. Przy stu tysiącach — już nie. **Używaj `TryGetValue`**; `ContainsKey` zostaw do sytuacji, w których sama wartość nie jest ci potrzebna.

### E. Przejście po słowniku

```csharp
foreach (KeyValuePair<string, int> para in wiek)
{
    Console.WriteLine($"{para.Key} ma {para.Value} lat");
}
```

> „`foreach` z lekcji 5.3 znowu działa tak samo. Co jest tym razem elementem?"
→ **para** klucz-wartość, nie sama wartość.

`KeyValuePair<string, int>` to długa nazwa; w praktyce pisze się:
```csharp
foreach (var para in wiek)
{
    Console.WriteLine($"{para.Key} -> {para.Value}");
}
```
> „`var` z lekcji 2.1 — kompilator sam wie, jakiego typu jest `para`. Tutaj to naprawdę pomaga."

Można też przejść po samych kluczach albo samych wartościach:
```csharp
foreach (string imie in wiek.Keys) { Console.Write(imie + " "); }
Console.WriteLine();
foreach (int lata in wiek.Values) { Console.Write(lata + " "); }
Console.WriteLine();
```

### F. Zliczanie — najczęstsze zastosowanie słownika

```csharp
Console.Write("Podaj zdanie: ");
string zdanie = Console.ReadLine();

Dictionary<char, int> ile = new Dictionary<char, int>();

foreach (char znak in zdanie)
{
    if (znak == ' ')
    {
        continue;
    }

    if (ile.ContainsKey(znak))
    {
        ile[znak] = ile[znak] + 1;
    }
    else
    {
        ile[znak] = 1;
    }
}

foreach (var para in ile)
{
    Console.WriteLine($"{para.Key}: {para.Value}");
}
```

> „Tego samego nie dałoby się zrobić listą. Czemu?"
→ bo trzeba by przy każdym znaku przeszukać całą listę, a tu klucz prowadzi prosto do licznika.

**To jest zadanie, dla którego słownik istnieje.** `continue` uczeń zna z lekcji 5.3.

## Krok 4 — Pogłębienie (10 min)

**Co może być kluczem?**

| Klucz | Sens |
| --- | --- |
| `string` — nazwa, login, symbol | najczęstszy |
| `int` — numer produktu, rok | częsty |
| `char` — znak, jak w kroku 3.F | rzadszy, ale wygodny |
| `enum` z lekcji 2.2 | świetny, gdy zbiór kluczy jest zamknięty |

> „Kluczem może być właściwie każdy typ, który da się porównać na równość. W tym kursie wystarczą te cztery."

**Kolejność wpisów**
> „Nie polegaj na kolejności, w jakiej `foreach` wypisuje wpisy. Słownik nie obiecuje żadnej. Jeśli potrzebujesz kolejności — użyj listy albo posortuj wynik."

**Usuwanie:**
```csharp
wiek.Remove("Bo");
Console.WriteLine(wiek.Count);
```
> „`Remove` zwraca `bool`, jak przy liście w 6.2 — mówi, czy było co usuwać."

**Trzy kolekcje, trzy pytania — podsumowanie modułu:**

| Chcesz… | Użyj |
| --- | --- |
| ustalona liczba elementów, dostęp po numerze | tablica (6.1) |
| rosnąca liczba elementów, dostęp po numerze | `List<T>` (6.2) |
| dostęp po nazwie / kluczu | `Dictionary` (6.3) |

> „Pytanie, które rozstrzyga: **po czym będziesz szukać?** Po numerze porządkowym czy po nazwie?"

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „`Dictionary`". Propozycje:

- 🔥 **Rozgrzewka** (`16-dictionary-a.cs`): utwórz słownik `stolica → kraj` z czterema wpisami wpisanymi na stałe. Wypisz wszystkie pary, a potem odczytaj jedną po kluczu i wypisz z opisem.
- ⭐ **Główne** (`16-dictionary-b.cs`): notes telefoniczny. W pętli pytaj o imię i numer, dopisując do słownika, aż użytkownik naciśnie sam Enter przy imieniu. Potem pytaj o imię do wyszukania i wypisz numer — przez `TryGetValue`, z komunikatem `Nie znam takiej osoby`, gdy klucza nie ma. Wyszukiwanie też w pętli, aż Enter.
- ⚡ **Gwiazdka** (`16-dictionary-c.cs`): zliczanie słów. Wczytaj zdanie, podziel je na słowa (`zdanie.Split(' ')` daje tablicę tekstów — z lekcji 6.1) i policz, ile razy występuje każde słowo. Wypisz wynik. Potem znajdź i wypisz słowo najczęstsze — przechodząc po słowniku i zapamiętując największą wartość, tym samym wzorcem co „największa ocena" z lekcji 6.1.

Gwiazdka łączy trzy lekcje modułu: `Split` daje tablicę, słownik zlicza, a wzorzec maksimum pochodzi z 6.1.

## Pułapki

- **Odczyt nieistniejącego klucza** → `KeyNotFoundException`. Używaj `TryGetValue`.
- **`Add` na istniejącym kluczu** → `ArgumentException`. `[klucz] =` nadpisuje po cichu — wybieraj świadomie.
- **Poleganie na kolejności wpisów** — słownik jej nie obiecuje.
- **`ContainsKey` plus odczyt** — dwa przeszukania zamiast jednego. Działa, ale `TryGetValue` jest właściwe.
- **Klucz to nie numer porządkowy** — `wiek[0]` przy kluczach tekstowych nie skompiluje się; przy kluczach `int` zadziała, ale zero **nie** oznacza „pierwszy wpis", tylko „wpis o kluczu 0".
- **Zmiana słownika w trakcie `foreach`** → `InvalidOperationException`, tak samo jak przy liście w 6.2.
- **Jeden typ w nawiasach ostrych** — `Dictionary<string>` nie istnieje; potrzebne są dwa.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Sekcja `[moduł 6]`. Dwie rzeczy:

- **`Hashtable`** ze starych poradników to poprzednik `Dictionary` bez kontroli typów. Ta sama historia co `ArrayList` kontra `List<T>`.
- **`ContainsKey` plus indeksator** to najczęstszy wzorzec w materiałach sprzed 2015 roku. `TryGetValue` istniał wcześniej, ale nie był powszechnie używany; dziś jest zalecany.

## Notatki tutora

- **Krok 3.C jest najważniejszy dydaktycznie.** Nie chodzi o `TryGetValue` samo w sobie, tylko o rozpoznanie **wzorca `Try`**. Uczeń, który go zauważy, przestanie się uczyć metod na pamięć, a zacznie je rozpoznawać po nazwie.
- **Krok 3.A pokaż jako wybór, nie jako ciekawostkę.** Różnica `Add` kontra `[klucz] =` to pierwsza w kursie decyzja projektowa: „czy duplikat to błąd?".
- **Nie tłumacz, czemu słownik jest szybki** (tablice mieszające, funkcje skrótu). „Klucz prowadzi prosto do wartości" wystarcza do końca kursu.
- **Nie wprowadzaj `HashSet`.** Uczeń może o niego zapytać przy usuwaniu duplikatów z ćwiczenia 6.2 — „istnieje coś takiego, na razie wystarczy `Contains` na liście".
- **Nie wprowadzaj LINQ** przy szukaniu najczęstszego słowa w gwiazdce. To moduł 13; tutaj wzorzec maksimum z 6.1 jest właściwy i uczy więcej.
- **`Split` w gwiazdce** to nowe narzędzie — jedno zdanie: „dzieli tekst na tablicę po podanym znaku". Nie rozwijaj.
- Jeśli uczeń pyta „a jak posortować słownik" — to znak, że myśli o nim jak o liście. Wróć do kroku 4: słownik nie ma kolejności.
