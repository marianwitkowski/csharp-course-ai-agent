# Lekcja 12.3 — JSON

## Cel
Po lekcji uczeń:
- Zamienia obiekt na tekst przez `JsonSerializer.Serialize` i z powrotem przez `Deserialize`
- Zapisuje i wczytuje **całą listę obiektów** jednym wywołaniem
- Wie, że serializowane są **właściwości, nie pola** — i czemu to domyka lekcję 8.3
- Ustawia czytelne formatowanie i poprawne polskie znaki
- Wie, że w pliku jednoplikowym trzeba dopisać jedną dyrektywę — i po co

> **Uwaga techniczna, bez której lekcja nie ruszy:** w aplikacji jednoplikowej (`dotnet run plik.cs`) serializacja JSON jest domyślnie **wyłączona**. Plik musi zaczynać się od dwóch linii:
> ```csharp
> #:property JsonSerializerIsReflectionEnabledByDefault=true
> #:property PublishAot=false
> ```
> Pierwsza włącza serializację — bez niej program przewraca się z komunikatem o wyłączonej serializacji. Druga wycisza kilkanaście ostrzeżeń `IL2026`/`IL3050`, które inaczej zasypią wynik przy pierwszym uruchomieniu. Szczegóły w kroku 2. **Nie pomijaj żadnej.**

## Krok 2 — Mostek (12 min)

**Mostek:**
> „Istnieje gotowy format zapisu obiektów jako tekstu: **JSON**. Czyta go praktycznie każdy język programowania, a C# zamienia na niego obiekty jedną komendą."

**Jedna nowość składniowa, zanim zaczniemy.** Te dwa zapisy robią dokładnie to samo:

```csharp
Kot a = new Kot();
a.Imie = "Mruczek";
a.Wiek = 3;

Kot b = new Kot { Imie = "Mruczek", Wiek = 3 };
```

To **inicjalizator obiektu**: tworzy obiekt i od razu ustawia właściwości. Działa tylko na tym, co ma `set` — czyli na właściwościach z lekcji 8.3. Żadnej nowej możliwości, sam skrót zapisu; w tej lekcji obiektów powstaje dużo, więc krótszy zapis się przyda.

Uczeń tworzy `kurs/zadania/36-json.cs`. **Dwie pierwsze linie są obowiązkowe:**

```csharp
#:property JsonSerializerIsReflectionEnabledByDefault=true
#:property PublishAot=false

using System.Text.Json;

Kot mruczek = new Kot { Imie = "Mruczek", Wiek = 3 };

string json = JsonSerializer.Serialize(mruczek);
Console.WriteLine(json);

class Kot
{
    public string Imie { get; set; } = "";
    public int Wiek { get; set; }
}
```
→ `{"Imie":"Mruczek","Wiek":3}`

**Wyjaśnij dyrektywy, gdy uczeń zapyta — a zapyta:**
> „Programy jednoplikowe są przygotowane pod maksymalnie oszczędne budowanie i domyślnie mają wyłączony mechanizm, którego JSON potrzebuje do rozpoznania twoich klas. Pierwsza linia go włącza. Druga wyłącza sprawdzanie pod kątem tego oszczędnego budowania — inaczej kompilator wypisze kilkanaście ostrzeżeń o tym samym. W zwykłym projekcie z modułu 14 żadna nie będzie potrzebna."

**Jeśli uczeń pominie drugą linię**, zobaczy ścianę ostrzeżeń `warning IL2026` i `warning IL3050` — program mimo to zadziała, a ostrzeżenia znikną przy kolejnym uruchomieniu (kompilator nie buduje pliku od nowa). To myląca kombinacja; lepiej jej uniknąć.

**Pytania:**
- „Co widzisz w wyniku? Rozpoznajesz nazwy?" → to nazwy **właściwości** klasy
- „Czym jest `json`?" → **zwykłym tekstem**. Takim samym, jaki zapisywałeś w 12.1.
- „Co to za nawiasy i dwukropki?" → format JSON: klucz, dwukropek, wartość, przecinki między parami

Nazwij: **serializacja** (obiekt → tekst), **deserializacja** (tekst → obiekt), **JSON**.

> **JSON wygląda znajomo** — to niemal ten sam zapis, co inicjalizacja słownika z lekcji 6.3. Klucz i wartość.

## Krok 3 — Eksperyment (25 min)

### A. Z powrotem na obiekt

```csharp
string json = "{\"Imie\":\"Filemon\",\"Wiek\":5}";

Kot? odczytany = JsonSerializer.Deserialize<Kot>(json);
Console.WriteLine($"{odczytany?.Imie} ma {odczytany?.Wiek} lat");
```
→ `Filemon ma 5 lat`

> „Skąd `Deserialize` wie, jaki obiekt zbudować?"
→ z `<Kot>` w nawiasach ostrych — to ten sam zapis co `List<Kot>` z lekcji 6.2.

> „Czemu `Kot?` ze znakiem zapytania i `odczytany?.Imie`?"
→ bo deserializacja **może się nie udać** i wtedy zwraca `null`. Jedno zdanie, nie rozwijaj.

### B. Czytelne formatowanie

```csharp
var opcje = new JsonSerializerOptions { WriteIndented = true };
Console.WriteLine(JsonSerializer.Serialize(mruczek, opcje));
```
→
```json
{
  "Imie": "Mruczek",
  "Wiek": 3
}
```

> „Do czego przyda się wersja z wcięciami, a do czego ta jednolinijkowa?"
→ z wcięciami — gdy plik ma czytać człowiek. Bez — gdy leci przez sieć i liczy się rozmiar.

### C. Polskie znaki

```csharp
Console.WriteLine(JsonSerializer.Serialize(new Kot { Imie = "Żółw", Wiek = 1 }, opcje));
```
→
```json
{
  "Imie": "\u017B\u00F3\u0142w",
  "Wiek": 1
}
```

> „Co się stało z »Żółw«?"
→ zostało zapisane kodami znaków. **JSON jest poprawny** i każdy program odczyta z niego z powrotem »Żółw« — ale człowiek tego nie przeczyta.

Naprawa — dopisz `Encoder` do istniejących `opcje` (nie twórz drugich):
```csharp
using System.Text.Encodings.Web;

var opcje = new JsonSerializerOptions
{
    WriteIndented = true,
    Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping
};
```
→ `"Imie": "Żółw"`

> „Nazwa `Unsafe...` brzmi groźnie. Chodzi o to, że taki tekst nie jest bezpieczny do wklejenia **wprost do strony internetowej** — bo mogłyby przejść przez niego znaczniki. Do pliku na dysku jest w porządku."

### D. Pola się **nie** zapisują — i to domyka lekcję 8.3

```csharp
class ZPolem
{
    public string Imie = "Mruczek";
}

Console.WriteLine(JsonSerializer.Serialize(new ZPolem()));
```
→ `{}`

> „Pusty obiekt. Gdzie się podziało imię?"
→ `System.Text.Json` zapisuje **właściwości**, nie pola.

Zamień pole na właściwość:
```csharp
public string Imie { get; set; } = "Mruczek";
```
→ `{"Imie":"Mruczek"}`

**To jest najkonkretniejszy argument za właściwościami w całym kursie.** W lekcji 8.3 uczeń usłyszał cztery powody; to jest piąty i najbardziej namacalny: **z polami twój obiekt po prostu się nie zapisze.**

Zatrzymaj się i powiedz to wprost.

### E. Cała lista naraz

```csharp
List<Kot> koty = new List<Kot>
{
    new Kot { Imie = "Mruczek", Wiek = 3 },
    new Kot { Imie = "Filemon", Wiek = 5 }
};

string json = JsonSerializer.Serialize(koty, opcje);
File.WriteAllText("koty.json", json);

List<Kot>? wczytane = JsonSerializer.Deserialize<List<Kot>>(File.ReadAllText("koty.json"));
Console.WriteLine($"Wczytano {wczytane?.Count} kotów, pierwszy to {wczytane?[0].Imie}");
```
→ `Wczytano 2 kotów, pierwszy to Mruczek`

**Niech uczeń otworzy `koty.json` w edytorze.** Zobaczy tablicę obiektów — czytelną, uporządkowaną, gotową do przesłania komukolwiek.

> „Porównaj to z lekcją 12.1, gdzie zapisywałeś same teksty. Ile kodu potrzeba, żeby zapisać listę obiektów z trzema polami każdy?"
→ dwie linie, niezależnie od liczby właściwości.

### F. Zły JSON

```csharp
try
{
    JsonSerializer.Deserialize<Kot>("{to nie jest json}");
}
catch (JsonException e)
{
    Console.WriteLine($"Nieprawidłowy JSON: {e.Message}");
}
```

> „Znasz ten schemat z modułu 11. Kiedy to się przyda?"
→ gdy wczytujesz plik, który ktoś mógł ręcznie zepsuć.

### G. Wielkość liter ma znaczenie

```csharp
Kot? k = JsonSerializer.Deserialize<Kot>("{\"imie\":\"Bo\"}");
Console.WriteLine($"[{k?.Imie}]");
```
→ `[]` — puste!

> „JSON miał `imie` małą literą, właściwość nazywa się `Imie`. Co się stało?"
→ nie dopasowało i pole zostało puste. **Bez błędu, bez ostrzeżenia.**

Naprawa:
```csharp
var luzne = new JsonSerializerOptions { PropertyNameCaseInsensitive = true };
Kot? ok = JsonSerializer.Deserialize<Kot>("{\"imie\":\"Bo\"}", luzne);
```
→ `Bo`

> „To jedna z tych pułapek, które nie dają żadnego sygnału. Gdy dane wczytują się jako puste — sprawdź wielkość liter."

## Krok 4 — Pogłębienie (10 min)

**Co JSON zapisuje bez problemu**

| Typ | Działa? |
| --- | --- |
| `int`, `double`, `bool`, `string` | tak |
| `List<T>`, tablica | tak |
| własna klasa z właściwościami | tak |
| zagnieżdżone obiekty (klasa w klasie) | tak |
| `Dictionary<string, T>` | tak |
| pole (bez `{ get; set; }`) | **nie** |

**Klasa w klasie**

```csharp
class Osoba
{
    public string Imie { get; set; } = "";
    public Adres Adres { get; set; } = new Adres();
}
```
→ JSON zagnieżdża się sam:
```json
{ "Imie": "Ala", "Adres": { "Ulica": "Kwiatowa", "Miasto": "Kraków" } }
```

> „Ile kodu napisałeś, żeby to zadziałało?"
→ zero. Kompozycja z lekcji 10.3 przekłada się na strukturę pliku wprost.

**Klasa do deserializacji potrzebuje konstruktora bezargumentowego**

> „Jeśli twoja klasa ma tylko konstruktor z parametrami — jak w lekcji 8.2 — a nazwy parametrów nie zgadzają się z nazwami właściwości, deserializacja przewróci się z `InvalidOperationException`. Najprościej: właściwości z `{ get; set; }` i konstruktor bezargumentowy albo żadnego."

To praktyczna pułapka i warto o niej powiedzieć zawczasu.

**Wzorzec trwałości — teraz z obiektami**

To rozwinięcie wzorca z lekcji 12.1:

```csharp
List<Kot> koty = new List<Kot>();

if (File.Exists("koty.json"))
{
    koty = JsonSerializer.Deserialize<List<Kot>>(File.ReadAllText("koty.json")) ?? new List<Kot>();
}

// ...praca na liście...

File.WriteAllText("koty.json", JsonSerializer.Serialize(koty, opcje));
```

> „To jest **kompletny mechanizm zapisu stanu** dla małego programu. Użyjesz go w projekcie z modułu 14."

**Czego nie ma w tym kursie**

> „JSON potrafi znacznie więcej: mapowanie nazw, pomijanie właściwości, własne konwertery dat. Wszystko to jest atrybutami nad właściwościami. Nie potrzebujesz tego dziś."

## Pułapki

- **Brak `#:property JsonSerializerIsReflectionEnabledByDefault=true`** → `InvalidOperationException` o wyłączonej serializacji. **Pierwsza linia pliku.**
- **Brak `#:property PublishAot=false`** → kilkanaście ostrzeżeń `IL2026`/`IL3050` przed wynikiem programu. Nieszkodliwe, ale przy pierwszym uruchomieniu wyglądają jak awaria.
- **Pola zamiast właściwości** → pusty obiekt `{}` bez żadnego ostrzeżenia.
- **Wielkość liter w kluczach** → właściwości zostają puste, cicho.
- **Polskie znaki jako `\u017B`** → poprawne, ale nieczytelne. `UnsafeRelaxedJsonEscaping`.
- **Brak konstruktora bezargumentowego** → deserializacja może zawieść.
- **`Deserialize` zwraca `null`** dla tekstu `"null"` — sprawdź wynik. Dla **pustego pliku** nie zwraca `null`, tylko rzuca `JsonException`.
- **Zapomniane `using System.Text.Json`** → `CS0103` na `JsonSerializer`.
- **Ręczne sklejanie JSON-a z tekstu** — nigdy tego nie rób. Od tego jest `Serialize`.

## Notatki tutora

- **Obie dyrektywy `#:property` są obowiązkowe i trzeba o nich pamiętać w KAŻDYM pliku z JSON-em**, także w ćwiczeniach. Bez pierwszej uczeń dostanie wyjątek, którego nie umie zinterpretować; bez drugiej — ścianę ostrzeżeń.
- **Krok 3.D to najważniejsze pięć minut lekcji.** Pusty `{}` przy polach jest najkonkretniejszym argumentem za właściwościami, jaki kurs ma — mocniejszym niż wszystkie cztery powody z lekcji 8.3.
- **Każ otworzyć plik `.json` w edytorze.** Uczeń musi zobaczyć, że to zwykły, czytelny tekst — nie magia.
- **Inicjalizator obiektu z kroku 2 to jedyna nowa składnia w tej lekcji.** Pokaż równoważność z przypisaniami i idź dalej — nie rozwijaj (nie działa na polach tylko do odczytu, nie zastępuje konstruktora).
- **Nie tłumacz atrybutów** (`[JsonPropertyName]`, `[JsonIgnore]`). Jedno zdanie w kroku 4.
- **Nie tłumacz `?` przy `Kot?` ani `??`.** Jedno zdanie, jak w module 3 przy `CS8600`.
- **Nie wprowadzaj XML-a.** Starsze materiały go zawierały; dziś w nowym kodzie praktycznie nie występuje.
- **Nie wprowadzaj `async`** ani metod `...Async`. Poza kursem.
- Jeśli uczeń zapyta, czy JSON nadaje się do wszystkiego — nie. Do dużych ilości danych są bazy (moduł 14.7), a do plików binarnych inne formaty. Jedno zdanie.
