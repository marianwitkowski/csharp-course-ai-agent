# Lekcja 7.1 — Metody

## Cel
Po lekcji uczeń:
- Pisze własną metodę i wywołuje ją
- Przekazuje dane przez **parametry** i odbiera wynik przez `return`
- Rozróżnia metodę `void` od metody zwracającej wartość
- Rozumie, że metoda to **nazwany kawałek kodu**, nie magia
- Rozpoznaje `CS0161` (nie wszystkie ścieżki zwracają wartość)

> **To pierwsza lekcja, w której kod przestaje być jednym ciągiem od góry do dołu.** Do tej pory program czytało się jak listę poleceń. Od dziś da się go pogrupować i ponazywać.

## Krok 1 — Zakotwiczenie (5-8 min)

**Pytanie wejściowe:**
> „Ktoś mówi ci: »zrób herbatę«. Skąd wiesz, co masz robić? Przecież nie wymienił kroków."

**Co chcesz usłyszeć:** bo „zrobić herbatę" to **nazwa** dla ciągu czynności, które obaj znacie.

**Drugie pytanie:**
> „A gdyby powiedział »zrób herbatę dla pięciu osób«? Co się zmienia?"

**Co chcesz usłyszeć:** te same czynności, tylko z inną liczbą. **Liczba osób to parametr** — nie nazywaj tego jeszcze.

**Trzecie pytanie:**
> „A »policz, ile mamy kubków« — czym to się różni od »zrób herbatę«?"

**Co chcesz usłyszeć:** tamto coś **robi**, to coś **odpowiada**. Zapamiętaj — to różnica między `void` a metodą z `return`.

## Krok 2 — Mostek (10 min)

**Mostek:**
> „Nazwany ciąg czynności, który można wywołać jednym słowem — to w C# **metoda**. Piszesz ją raz, wywołujesz ile chcesz."

Uczeń tworzy `kurs/zadania/18-metody.cs`:

```csharp
Powitaj("Ala");
Powitaj("Bo");
Powitaj("Cyd");

void Powitaj(string imie)
{
    Console.WriteLine($"Cześć, {imie}! Miło cię widzieć.");
}
```
→ trzy powitania.

**Pytania:**
- „Ile razy napisałeś treść powitania? Ile razy się wypisała?"
- „Co jest w nawiasach przy wywołaniu, a co przy definicji?"
- „Zauważ coś dziwnego: metoda jest **na dole**, a wywołania na górze. Zadziałało?"
  → tak. **Kolejność nie ma znaczenia** — kompilator widzi całą metodę, zanim wykona pierwszą linię.

Nazwij: **metoda**, **parametr** (`string imie` przy definicji), **argument** (`"Ala"` przy wywołaniu), **wywołanie**.

> **`void` znaczy „nic nie oddaje".** Ta metoda coś robi — wypisuje — ale nie zwraca żadnej wartości. To jest „zrób herbatę" z kroku 1.

Niech uczeń zmieni treść powitania w jednym miejscu i uruchomi.
> „Ile miejsc musiałeś poprawić, żeby zmienić wszystkie trzy powitania?"
→ jedno. **To jest cały powód, dla którego metody istnieją.**

## Krok 3 — Eksperyment (25 min)

### A. Metoda, która odpowiada

```csharp
int Dodaj(int a, int b)
{
    return a + b;
}

Console.WriteLine(Dodaj(2, 3));
int wynik = Dodaj(10, 5);
Console.WriteLine(wynik);
```
→ `5` i `15`

> „Czym różni się nagłówek tej metody od `void Powitaj`?"
→ zamiast `void` stoi `int` — **typ tego, co metoda odda**.

> „Co robi `return`?"
→ oddaje wartość i **kończy metodę** w tym miejscu.

To jest „policz kubki" z kroku 1.

### B. `return` kończy metodę natychmiast

```csharp
int Bezpieczne(int a, int b)
{
    if (b == 0)
    {
        return 0;
    }

    return a / b;
}

Console.WriteLine(Bezpieczne(10, 2));
Console.WriteLine(Bezpieczne(10, 0));
```
→ `5` i `0`

> „Dla `b == 0` program nie doszedł do drugiego `return`. Czemu?"
→ pierwszy `return` zakończył metodę.

**To jest wzorzec zwany wczesnym wyjściem** i będzie wracał: sprawdź złe przypadki na początku, wyjdź, a reszta metody zajmuje się przypadkiem normalnym.

### C. Zapomniany `return`

```csharp
int Zle(int x)
{
    if (x > 0)
    {
        return 1;
    }
}
```
→ `CS0161: 'Zle(int)': not all code paths return a value`

> „Przeczytaj: »nie wszystkie ścieżki zwracają wartość«. Która ścieżka jej nie zwraca?"
→ ta, w której `x` nie jest większe od zera.

> „Czemu kompilator się na to nie zgadza, skoro w praktyce może nigdy tam nie trafić?"
→ bo **obiecałeś w nagłówku**, że oddasz `int`. Obietnica musi być spełniona na każdej drodze.

### D. Metody bez parametrów i z wieloma

```csharp
void Linia()
{
    Console.WriteLine("--------------------");
}

double Srednia(int a, int b, int c)
{
    return (a + b + c) / 3.0;
}

Linia();
Console.WriteLine(Srednia(5, 4, 3));
Linia();
```
→ kreska, `4`, kreska

> „Czemu `3.0`, a nie `3`?"
→ bo dzielenie trzech `int` przez `int` dałoby dzielenie całkowite z lekcji 2.3. Sprawdź, zamieniając na `3`.

### E. Przypisanie wyniku metody `void`

```csharp
void Nic() { }
int x = Nic();
```
→ `CS0029: Cannot implicitly convert type 'void' to 'int'`

> „`void` znaczy »nic nie oddaje«. Co próbowałeś włożyć do `x`?"

Ta sama rodzina błędów co przy `?:` z lekcji 4.2: **wyrażenie daje wartość, instrukcja nie.**

### F. Metoda wywołująca inną metodę

```csharp
bool CzyParzysta(int n)
{
    return n % 2 == 0;
}

void Opisz(int n)
{
    if (CzyParzysta(n))
    {
        Console.WriteLine($"{n} jest parzysta");
    }
    else
    {
        Console.WriteLine($"{n} jest nieparzysta");
    }
}

for (int i = 1; i <= 4; i++)
{
    Opisz(i);
}
```

> „`CzyParzysta` zwraca `bool` — i ten `bool` wylądował wprost w `if`. Czy to cię dziwi?"
→ nie powinno: `if` zawsze chciał `bool`, a metoda go oddaje. To ta sama zasada z lekcji 4.1.

> „Ile metod wywołuje się przy jednym obiegu pętli?"
→ dwie: `Opisz`, a w środku `CzyParzysta`.

## Krok 4 — Pogłębienie (10 min)

**Krótszy zapis — metoda jednowyrażeniowa**

Gdy całe ciało to jedno wyrażenie:
```csharp
bool CzyParzysta(int n) => n % 2 == 0;
double Pole(double bok) => bok * bok;
```
> „`=>` zamiast klamer i `return`. Znasz tę strzałkę z wyrażenia `switch` z lekcji 4.3 — tam też oznaczała »to daje tamto«."

**Nie zmuszaj do używania.** To skrót do rozpoznania; obie formy są poprawne.

**Jak nazywać metody**

| Rodzaj | Konwencja | Przykład |
| --- | --- | --- |
| coś robi (`void`) | czasownik | `Powitaj`, `Wypisz`, `Zapisz` |
| coś zwraca | rzeczownik albo czasownik | `Suma`, `PoliczSrednia` |
| zwraca `bool` | pytanie | `CzyParzysta`, `CzyPusty` |

> „Nazwy metod piszemy z **wielkiej litery** — `PascalCase`, jak `Console.WriteLine`. Parametry z małej, jak zmienne. To ta sama konwencja co z lekcji 1.2."

**Co metoda widzi, a czego nie**

```csharp
int poza = 10;

void Pokaz()
{
    Console.WriteLine(poza);
}

Pokaz();
```
→ `10` — działa.

> „Metoda sięgnęła po zmienną spoza siebie. Czy to dobrze?"

Zwykle **nie**. Metoda, która sięga po wszystko dookoła, jest trudna do zrozumienia i nie da się jej przenieść gdzie indziej. **Lepiej przekazać przez parametr:**

```csharp
void Pokaz(int wartosc)
{
    Console.WriteLine(wartosc);
}
Pokaz(poza);
```

> „Teraz z nagłówka widać, czego ta metoda potrzebuje. Wcześniej trzeba było przeczytać całe ciało."

To zapowiedź lekcji 7.3, gdzie zasięg zmiennych będzie tematem.

**Kiedy wydzielić metodę?**

- ten sam kod występuje **drugi raz** → wydziel
- fragment da się nazwać jednym sensownym zdaniem → wydziel
- metoda nie mieści się na ekranie → podziel

> „Nie wydzielaj na zapas. Metoda użyta raz, o nazwie `ZrobToICoJeszcze`, nie pomaga nikomu."

## Krok 5 — Ćwiczenie

→ Skill `cwiczenie`. Temat: „metody". Propozycje:

- 🔥 **Rozgrzewka** (`18-metody-a.cs`): napisz metodę `void Ramka(string tekst)`, która wypisuje tekst otoczony linią z gwiazdek nad i pod. Wywołaj ją trzy razy z różnymi tekstami.
- ⭐ **Główne** (`18-metody-b.cs`): kalkulator na metodach. Napisz cztery metody: `Dodaj`, `Odejmij`, `Pomnoz`, `Podziel` (ta ostatnia ma zwrócić zero przy dzielniku równym zeru — wczesne wyjście z kroku 3.B). Wczytaj dwie liczby i znak działania, wybierz metodę przez `switch` z lekcji 4.3 i wypisz wynik.
- ⚡ **Gwiazdka** (`18-metody-c.cs`): statystyki tablicy. Napisz trzy metody przyjmujące `int[]` i zwracające: sumę, średnią (`double`) i największy element. Każda ma być **jednym** krótkim ciałem, bez powtarzania kodu między nimi. Potem wczytaj pięć liczb do tablicy i wypisz wszystkie trzy statystyki. Zastanów się: czy średnia może wywołać sumę?

Gwiazdka ma podpowiedź w ostatnim pytaniu: `Srednia` powinna wywołać `Suma`, zamiast liczyć od nowa. To pierwszy raz, gdy uczeń buduje metodę z metody.

## Pułapki

- **Brak `return` na którejś ścieżce** → `CS0161`. Prześledź wszystkie gałęzie `if`.
- **`return` w metodzie `void`** — samo `return;` jest dozwolone (kończy metodę), ale `return coś;` da błąd.
- **Przypisanie wyniku `void`** → `CS0029`.
- **Zła kolejność argumentów** — `Dodaj(b, a)` skompiluje się i da zły wynik, gdy typy się zgadzają. Kompilator nie zna twoich intencji.
- **Metoda sięgająca po zmienne z zewnątrz** — działa, ale utrudnia zrozumienie. Przekazuj przez parametry.
- **Nazwa metody z małej litery** — działa, ale łamie konwencję. `PascalCase`.
- **Dzielenie całkowite w metodzie zwracającej `double`** — `return (a + b) / 2;` przy `int`-ach obetnie wynik **przed** zamianą na `double`. To pułapka z lekcji 2.3 w nowym przebraniu.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Ta lekcja nie ma znaczących zmian — metody wyglądają w C# tak samo od początku.

Jedna różnica dotyczy **miejsca**, w którym metodę się pisze. W starszych materiałach każda metoda musiała być w klasie i oznaczona `static`:
```csharp
class Program
{
    static void Powitaj(string imie) { ... }
    static void Main(string[] args) { Powitaj("Ala"); }
}
```
Dziś, w pliku z instrukcjami najwyższego poziomu, piszesz samo `void Powitaj(...)`. To ta sama metoda bez obudowy — obudowę poznasz w module 8.

## Notatki tutora

- **Krok 2 kończy się pytaniem „ile miejsc musiałeś poprawić".** To jest cały powód istnienia metod i uczeń ma go **zobaczyć**, nie usłyszeć.
- **Nie tłumacz `static`.** W pliku bez klasy nie występuje. Jeśli uczeń znajdzie je w internecie — „to z czasów, gdy wszystko musiało być w klasie; moduł 8".
- **Nie wprowadzaj przeciążania.** Uczeń może zapytać, czy da się mieć dwie metody o tej samej nazwie — lekcja 7.2 i tam czeka niespodzianka.
- **Nie wprowadzaj `ref` ani `out`.** To 7.3. `out` widział przy `TryParse`, ale bez wyjaśnienia i tak ma zostać.
- **Nie wprowadzaj rekurencji.** Metoda wywołująca samą siebie to temat, który dla początkującego kosztuje więcej, niż daje; kurs go nie ma.
- **Kolejność metody i wywołania warto podkreślić.** Uczniowie przyzwyczajeni do czytania kodu od góry dziwią się, że metoda na dole działa. Jedno zdanie rozwiewa to na zawsze.
- Jeśli uczeń pisze wszystko w jednej metodzie o nazwie `Program` — to normalne na początku. Reguła z kroku 4 („ten sam kod drugi raz") wystarczy; nie narzucaj podziału na siłę.
