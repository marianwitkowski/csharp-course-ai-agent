# Lekcja 9.4 — Składowe statyczne

## Cel
Po lekcji uczeń:
- Odróżnia składową **obiektu** od składowej **klasy** (`static`)
- Pisze licznik wspólny dla wszystkich obiektów danej klasy
- Tworzy klasę statyczną jako zbiór narzędzi
- Rozumie wreszcie, czemu `Console.WriteLine` i `Math.Round` woła się **bez `new`**
- Rozpoznaje `CS0723` i `CS0120`

> **Ta lekcja wyjaśnia coś, czego uczeń używa od pierwszej lekcji kursu.** `Console.WriteLine("Cześć")` — nigdy nie tworzył obiektu `Console`. Dziś dowie się dlaczego.

## Krok 1 — Zakotwiczenie (5 min)

**Pytanie wejściowe:**
> „Każda książka w bibliotece ma swój tytuł i swojego autora. A »liczba książek w bibliotece« — czyja to cecha?"

**Co chcesz usłyszeć:** nie konkretnej książki, tylko **całej biblioteki**. Jednej książki nie da się zapytać, ile jest wszystkich.

**Drugie pytanie:**
> „Gdzie zapiszesz tę liczbę? W każdej książce po kopii?"

**Co chcesz usłyszeć:** nie — raz, w jednym miejscu, wspólnym dla wszystkich.

**Trzecie pytanie:**
> „A kalkulator na ścianie w bibliotece — czy potrzebujesz »własnego egzemplarza kalkulatora«, żeby dodać dwie liczby?"

**Co chcesz usłyszeć:** nie, korzystasz ze wspólnego. **To jest klasa statyczna** — nie nazywaj jeszcze.

## Krok 2 — Mostek (12 min)

**Mostek:**
> „Do tej pory każde pole należało do **obiektu**: każdy kot ma swoje imię. Ale niektóre rzeczy należą do **całej klasy**, nie do pojedynczego obiektu. Oznacza się je słowem `static`."

Uczeń tworzy `kurs/zadania/28-static.cs`:

```csharp
Console.WriteLine(Kot.Ile);

Kot a = new Kot("Mruczek");
Kot b = new Kot("Filemon");
Kot c = new Kot("Puszek");

Console.WriteLine(Kot.Ile);
Console.WriteLine(a.Imie);

class Kot
{
    public static int Ile { get; private set; }

    public string Imie { get; }

    public Kot(string imie)
    {
        Imie = imie;
        Ile = Ile + 1;
    }
}
```
→ `0`, `3`, `Mruczek`

**Pytania:**
- „Przez co wołasz `Ile` — przez obiekt czy przez nazwę klasy?" → **przez nazwę klasy**: `Kot.Ile`
- „A `Imie`?" → przez obiekt: `a.Imie`
- „Ile jest w programie zmiennych `Ile`? A ile zmiennych `Imie`?" → jedna kontra trzy

Nazwij: **składowa statyczna** (należy do klasy), **składowa instancyjna** (należy do obiektu).

> **Reguła jednym zdaniem: `static` znaczy »jedna sztuka na całą klasę, niezależnie od tego, ile jest obiektów«.**

Niech uczeń spróbuje:
```csharp
Console.WriteLine(a.Ile);
```
→ `CS0176: Member 'Kot.Ile' cannot be accessed with an instance reference; qualify it with a type name instead`

> „C# nie pozwala udawać, że to cecha kota. To cecha **klasy** i tak trzeba ją wołać."

## Krok 3 — Eksperyment (22 min)

### A. Metoda statyczna

```csharp
class Matma
{
    public static int Kwadrat(int x) => x * x;
}
```

```csharp
Console.WriteLine(Matma.Kwadrat(5));
```
→ `25`

> „Ile obiektów `Matma` utworzyłeś?"
→ zero. **Metoda statyczna nie potrzebuje obiektu**, bo nie korzysta z żadnych jego danych.

### B. Czemu `Console.WriteLine` działa bez `new`

Zapytaj, zanim wyjaśnisz:
> „Od pierwszej lekcji piszesz `Console.WriteLine`. Ile razy utworzyłeś obiekt `Console`?"

→ ani razu.

> „A `Math.Round` z lekcji 2.3? A `int.TryParse` z 2.3?"

Wszystkie to **metody statyczne**. `Console`, `Math` — to klasy, których nikt nigdy nie tworzy; służą jako zbiór narzędzi.

> „Czemu `Console` jest statyczne, a `List` nie?"
→ konsola jest **jedna** — nie ma sensu mieć dwóch. List jest wiele, każda ze swoją zawartością.

**To jest domknięcie wątku ciągnącego się przez cały kurs.** Uczeń używał tego mechanizmu przez osiem modułów.

### C. Klasa statyczna

```csharp
static class Matma
{
    public static int Kwadrat(int x) => x * x;
    public static int Szescian(int x) => x * x * x;
}
```

```csharp
Matma m = new Matma();
```
→ `CS0723: Cannot declare a variable of static type 'Matma'`

> „Klasa oznaczona `static` mówi wprost: **nie da się mnie utworzyć, nie próbuj**. Wszystko w niej musi być statyczne."

> „Kiedy warto?"
→ gdy klasa jest **zbiorem narzędzi**, a nie opisem rzeczy. `Math` jest taki. `Kot` nie.

### D. Statyczna metoda nie widzi pól obiektu

```csharp
class Kot
{
    public string Imie { get; }
    public Kot(string imie) => Imie = imie;

    public static void Opisz()
    {
        Console.WriteLine(Imie);
    }
}
```
→ `CS0120: An object reference is required for the non-static field, method, or property 'Kot.Imie'`

> „Metoda statyczna należy do klasy. Czyje imię miałaby wypisać, skoro nie wie, o którego kota chodzi?"

**To jest najlepsze wyjaśnienie `static` w całej lekcji.** Statyczna metoda nie ma `this` — nie istnieje „ten obiekt".

Odwrotnie **działa**:
```csharp
public void Pokaz()
{
    Console.WriteLine($"{Imie}, a wszystkich kotów jest {Ile}");
}
```
> „Metoda obiektu widzi i swoje pola, i statyczne. Czemu?"
→ bo statyczne są wspólne — dostępne zawsze.

### E. Stała statyczna

```csharp
static class Fizyka
{
    public const double G = 9.81;
    public static double Predkosc(double czas) => G * czas;
}
```

> „`const` z lekcji 2.2 jest automatycznie statyczna — nie ma sensu, żeby każdy obiekt miał własną wartość liczby, która się nie zmienia."

Warto pokazać, że `Math.PI` z lekcji 9.3 to dokładnie to samo.

### F. Licznik z pułapką

```csharp
class Kot
{
    public static int Ile { get; private set; }
    public string Imie { get; }

    public Kot(string imie)
    {
        Imie = imie;
        Ile = Ile + 1;
    }
}
```

> „Co się stanie z licznikiem, gdy program się zakończy i uruchomisz go ponownie?"
→ wróci do zera. **Statyczne nie znaczy trwałe** — znaczy „wspólne w ramach jednego uruchomienia".

To ważne rozróżnienie; trwałość to moduł 12 (pliki).

## Krok 4 — Pogłębienie (10 min)

**Kiedy `static`, a kiedy nie**

| Sytuacja | Wybór |
| --- | --- |
| cecha konkretnego obiektu (`Imie`) | zwykła |
| cecha całej klasy (`Ile`, `MaksymalnaWaga`) | `static` |
| metoda używająca pól obiektu | zwykła |
| metoda licząca coś z samych argumentów | `static` |
| zbiór narzędzi bez własnych danych | `static class` |

> „Pytanie rozstrzygające: **czy ta rzecz ma sens bez konkretnego obiektu?**"

**Czego `static` nie robi**

- nie przyspiesza programu w sposób, który uczeń zauważy
- nie chroni danych — statyczne pole publiczne jest **globalnie** dostępne, co jest gorsze niż zwykłe
- nie jest zamiennikiem dla klasy z jednym obiektem

> „Statyczne pole `public` to zmienna globalna. Działa, i dokładnie dlatego bywa kuszące — a potem nikt nie wie, kto ją zmienił."

**Statyczne i dziedziczenie**

```csharp
class Zwierze { public static int Ile; }
class Kot : Zwierze { }
```
```csharp
Kot.Ile = 5;
Console.WriteLine(Zwierze.Ile);
```
→ `5`

> „To **jedna** zmienna, nie dwie. Klasa pochodna nie dostaje własnej kopii."

To zaskakuje i warto sprawdzić samemu.

**`static` a instrukcje najwyższego poziomu**

> „Pamiętasz z lekcji 7.1, że w starszych materiałach każda metoda była `static void`? Teraz wiesz, czemu: leżały w klasie `Program`, której nikt nie tworzył. `static` znaczyło »da się to zawołać bez obiektu«."

To domyka wątek z modułu 7.

## Pułapki

- **Wywołanie składowej statycznej przez obiekt** → `CS0176`. Wołaj przez nazwę klasy.
- **Sięganie po pole obiektu z metody statycznej** → `CS0120`. Metoda statyczna nie ma `this`.
- **`new` na klasie statycznej** → `CS0723`.
- **Niestatyczna składowa w klasie statycznej** → błąd. W `static class` wszystko musi być `static`.
- **Statyczne pole publiczne** — zmienna globalna z wszystkimi tego konsekwencjami. Trzymaj `private` plus `static` właściwość tylko do odczytu.
- **Oczekiwanie, że `static` przetrwa uruchomienie** — nie przetrwa. Do tego są pliki (moduł 12).
- **Statyczne pole w klasie bazowej** — wspólne dla wszystkich pochodnych, nie po jednym na klasę.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)

Sekcja `[moduł 9]`. Jedna zmiana dotyczy **miejsca, w którym uczeń widuje `static`**: w materiałach sprzed 2021 roku każdy program zaczynał się od `static void Main(string[] args)` wewnątrz klasy `Program`. Dziś piszesz instrukcje najwyższego poziomu i `static` pojawia się dopiero wtedy, gdy sam go potrzebujesz.

To dobra wiadomość dydaktyczna: dawniej uczeń musiał zobaczyć `static` w pierwszej minucie nauki, nie mając szans go zrozumieć.

- **Krok 3.D (`CS0120`) jest najlepszym wyjaśnieniem `static`.** „Czyje imię miałaby wypisać?" tłumaczy mechanizm lepiej niż definicja.
- **Nie tłumacz `this` w kontekście statycznym głębiej.** „Nie ma tego obiektu" wystarcza.
- **Ostrzeż przed nadużywaniem.** `static` jest wygodne i uczniowie zaczynają oznaczać nim wszystko, żeby uniknąć tworzenia obiektów. To prowadzi do programu, który jest jedną wielką zmienną globalną.
- **Nie wprowadzaj konstruktora statycznego** ani `Singleton`. Poza kursem.
